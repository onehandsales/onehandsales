# Bonsai 플로우 분석 재검토와 FE 준비도

검토일: 2026-11-20 KST · 차수: R3 · 대상: `bonsai_analysis` 전체.

후속 기록: 2026-11-22 [R4 원본 → 분석 감사](SOURCE_ANALYSIS_REVIEW.md). 아래 R3의 MCP·웹·선택 이미지 검토는 당시 수행 이력이며 R4의 직접 검토 범위와 구분한다.

**확보한 Gummble 자료의 파일·단계 누락은 발견하지 않았다. 다만 이 자료만으로 현재 Bonsai 전체 UX를 동일하게 구현할 수 있을 정도로 분석이 완결된 것은 아니다.** 기존 문서에는 입력값·상태 변화·미확인 사항이 상당 부분 기록되어 있다. 이번에는 실제 내용 오류, 근거 링크 단절, 미수록 성공 경로, 화면 간 상태 연결, 현행 제품과의 차이를 나누어 검토했다.

현재 작업 방향은 **FE 화면과 상태를 목으로 구현·검증한 뒤, 검증된 UX와 공식 도움말·공개 API를 대조하여 우리 계약과 DB를 설계**하는 것이다. 이 검토는 그 준비 자료이며 FE 구현·실제 계정 재현·DB 변경 완료 보고가 아니다.

이전 공통 파일은 Git 이력상 `81ab81b1`에서 삭제되어 있다. 삭제된 파일을 복원하지 않았다. 기존 R1/R2 수행 기록을 역사 기록으로 보존한다. R3 당시 연결한 `review/2026-11-20-r3/evidence.json`도 2026-11-22 현재 체크아웃에는 없다. R3 수행 서술은 이력으로 남기며, 새 [R4 원본·검토 색인](SOURCE_ANALYSIS_INDEX.json)은 로컬 파일과 이미지 대조의 근거다. R3 MCP 응답의 복원본이나 R4 MCP 재조회 결과가 아니다.

5절에 남은 기능별 공식 규칙까지 모두 사라진 것은 아니다. 문제는 상세 출처·적용 한계로 이어지던 공통 문서가 없어졌다는 것이다. 새 검토에서 읽지 않은 URL은 R2 기록으로 표시한다.

<a id="verification"></a>
## 8. 검증 방법과 이번 시각 확인 목록

MCP의 앱 화면 목록은 최대 48개씩 마지막 페이지까지 조회했다. 기존 134개 Flow ID는 batch로 조회하되, 큰 묶음에서 일부 긴 플로우의 반환 단계가 줄어드는 현상을 발견하여 해당 22개 흐름을 작은 묶음으로 재조회했다. 최종 응답의 모든 단계 순서가 문서와 일치함을 확인한 후에만 누락 0으로 판정했다.

## 9. 다음 FE 작업의 준비 순서

1. 해당 기능의 ANALYSIS와 보완표를 읽고, 구형 캡처 재현 부분과 현행 기능 보완 부분을 명시한다. Clients/Companies·구형/신형 문서 편집기처럼 버전이 다른 것은 섞지 않는다.
2. 화면 경로·진입 역할·시작 seed·목표 종료·폼 저장 경계·정상/실패/취소 상태를 정의한다. 모르는 정책은 임시 가정으로 기록한다.
3. 공통 저장소와 가상 인증 문맥을 통해 FE 목을 구현한다. 목록·상세·검색·연결 화면의 상태를 함께 검증한다.
4. 구현 중 드러난 추가 데이터 요구를 기록하고, 미수록 업무는 공식 자료나 추가 계정 관찰로 보완한다. 전체 화면 작업을 마칠 때까지 질문을 숨겨 두지 않는다.
5. UX 수용 기준 통과 후 우리 API·DB 계약으로 옮긴다. 이 문서의 검토 완료는 FE 구현 시작 자료가 정리됐다는 뜻이며 제품 전체 분석·계정 검증 완료를 의미하지 않는다.
