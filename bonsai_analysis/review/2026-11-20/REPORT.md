## 무엇을 완료로 판단했는가

목표는 각 플로우를 재현하고 데이터 요구를 검토할 수 있도록 출처·화면 상태·연결·규칙·미확인 사항을 추적 가능하게 만드는 것이다.

- 모든 로컬 플로우가 Gummble 분류와 연결되고 단계의 ID·순서·원본 URL이 일치한다.
- 모든 고유 이미지를 실제로 보고, 단계별 레이아웃·입력·컨트롤·상태·전환 설명과 대조한다.
- 관찰·현재 공식 자료·설계 가정이 분리되고 성공 안내를 실제 서버 결과로 확대하지 않는다.
- 시작 화면과 마지막 확인 화면, 서로 다른 캡처의 비연속 변화, 원본에 없는 분기를 명시한다.
- 문서 구조·링크·단계 수·이미지 무결성을 별도의 기계 검사로 검증한다.

위 기준의 **정적 자료 재검토를 완료**했다. 정상·취소·실패·재진입을 실제 계정에서 재현하거나 필수값·권한·트랜잭션·API 계약을 확정하는 작업은 남아 있다. 화면 수가 일치한다는 사실만으로 기능 전체의 의미적 완전성을 판단하지 않는다.

## 이미지 재검토 방법

원본 PNG 642개를 고유 Screen ID 순으로 묶어 번호를 붙인 2×2 비교 시트 161장을 만들고 모두 시각 확인했다. 시트 안의 각 화면은 1280×800으로 축소했다. 각 분석의 단계에 시트 번호와 고유 이미지 번호를 기록했다. 같은 이미지를 사용하는 여러 플로우는 관찰을 재사용하면서 각 플로우의 앞뒤 단계·목적과 대조했다.

비교 시트는 작업 중 임시 자료로 사용했다. 저장소에는 기존 단계별 원본 PNG와 [manifest.json](manifest.json)의 Screen ID·시트 번호·해시 대응을 남긴다. 파일 다운로드·해시 비교·문서 구조 검사는 시각 검토 횟수에 더하지 않았다. 기존 R1·R2 이력은 삭제하지 않고 이번 전수 검토 날짜를 추가했다.

## 검증 방법

저장소 루트에서 실행한다.

```powershell
python -X utf8 bonsai_analysis/tools/validate_flow_analysis.py
git -c core.safecrlf=false diff --check -- bonsai_analysis
```

[검증 결과](validation.json)는 134문서·754단계의 구조·순서·원본 연결·상대 링크·이미지 해시 점검 결과다. 검증 스크립트는 로컬 자료를 검사하며 Gummble 재조회나 시각 판단을 대신하지 않는다. [검토 기준 manifest](manifest.json)는 이번 MCP 응답과 이미지 대조에서 확정한 목록을 저장한다.
