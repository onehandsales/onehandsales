# Bonsai 학습 계획과 사용자 역할

Updated: 2026-11-18

**Bonsai 전체 기능·UX를 먼저 재현하고 이후 차별화한다.** 조사에는 공식 도움말·공식 API·Gummble·실제 계정 관찰을 사용한다. 현재 구현 기준은 [PM 036](../AGENT/PM_AGENT/DECISIONS/036_bonsai_benchmark_transition.md)에 반영한다.

## 대표나 영업사원이 사용해도 되는가

그렇다. 직업명보다 어떤 업무를 담당하고 어떤 정보에 접근해야 하는지로 이해한다. 대표는 전체 업무와 재무, 영업은 고객·거래·견적·후속 연락, 운영·프로젝트 담당자는 수행·일정·예산, 실무자는 작업·시간, 고객은 공유 문서·청구를 확인하는 시나리오다.

이 역할 구분은 우리 학습용 시나리오이며 Bonsai의 기본 권한 프로필 이름과 동일하지 않다. 실제 접근 범위는 [공식 권한 안내](https://help.hellobonsai.com/en/articles/1894805-all-about-user-permissions-in-bonsai)와 계정 관찰로 대조한다.

Bonsai는 [공식 소개](https://www.hellobonsai.com/)에서 서비스 사업의 고객·프로젝트·재무 관리를 설명한다. 이를 OneHand CRM의 프리랜서 전용·개발사 전용·특정 인원수 제한으로 옮기지 않는다. 최종 판매 타깃·가격은 아직 별도 결정 사항이다.

## 한 건의 가상 업무로 배우기

외주 개발팀 대표와 영업 담당자가 고객 A사의 예약 사이트 제작을 맡는 예시다. 금액과 사건은 가상이며 국내 결제 지원이나 실제 테스트를 뜻하지 않는다.

| 순서 | 업무 | 배울 개념 |
| --- | --- | --- |
| 1 | 고객사·연락 담당자 등록 | 고객 회사와 Contact, 계정 조직의 차이 |
| 2 | 영업 담당자가 상담·후속 연락 | Deal, 단계·금액·담당자·작업 |
| 3 | 로그인 200만·예약 500만·관리자 300만 원 산정 | Estimate 항목·수량·단가·원가·할인 |
| 4 | 범위와 금액을 고객에게 보내 합의 | Document·수신자·발송·서명·버전 |
| 5 | 수주 후 실제 개발 업무 준비 | Project·Task·배정·예산 |
| 6 | 작업·시간·비용과 추가 요청 기록 | 완료·투입 시간·청구 가능 여부 |
| 7 | 계약금·잔금 청구와 일부 입금 확인 | Invoice·Payment·미수 잔액 |
| 8 | 고객이 자기 문서·청구·자료 확인 | Client Portal과 내부/외부 권한 |
| 9 | 다음 프로젝트·반복 업무·보고서 | 템플릿·단가표·반복·자동화·집계 |

각 단계가 자동으로 연결되는지, 사람이 선택·수정해야 하는지, 같은 고객의 여러 거래·프로젝트가 어떻게 구분되는지 확인한다. 실제 UI의 순서나 DB 일대일 관계로 확정하지 않는다.

## 학습과 구현을 함께 진행하기

1. 공식 자료로 해당 기능의 입력·상태·제한을 이해한다.
2. Gummble에서 원본 화면·flow·캡처 조건을 확보한다.
3. 실제 계정에서 같은 사례의 정상·실패·권한 경로를 관찰한다.
4. 화면 mock과 API·DB·상태 계약 초안을 함께 만든다.
5. 작은 업무 단위로 구현하고 저장·재조회·권한·오류를 검증한다.
6. [전체 기능 대응표](../AGENT/PM_AGENT/PLANNING/BONSAI_FEATURE_PARITY_MATRIX.md)를 확장하며 누락을 채운다.

서비스 전체를 모두 외워야 시작하는 것은 아니다. 다만 구현하는 기능의 업무 의미·연결·상태는 이해해야 한다. Gummble 연결 대기 중에도 문서 분석·범위 정리·계약 초안은 진행한다. 화면만 보고 업무 규칙을 추정하지 않는다.

## 타깃과 차별화

개발·디자인·청소 서비스 사례는 비교할 업무 예시다. 특정 업종 인터뷰나 구매자 확정을 복제 작업의 선행 조건으로 두지 않는다. 대표·영업사원의 실제 업무도 함께 관찰한다.

추가 요구는 별도 후보로 기록하고 Bonsai에 이미 있는 기능처럼 취급하지 않는다. 재현 기준과 확인되지 않은 차이를 먼저 관리하고, 전체 대응 검수 이후 차별화 계획을 구체화한다.

## 현재 확인 수준

공식 주요 문서와 API 개요를 확인했다. Gummble의 Bonsai Web 분석 134개와 고유 화면 642개를 확보했고, 2026-11-18 전체 754단계의 원본 배치·문서 연결을 검증했다. [플로우 색인](README.md)을 먼저 확인하고, 검토 상태와 이력은 각 분석의 1절·9절에서 확인한다. 실계정 테스트는 미수행이다. [기능 지도](CRM_Bonsai_기능지도와_확인사항.md), [공식 근거와 미확인](../AGENT/UXUI_AGENT/PLANNING/BONSAI_BENCHMARK_RESEARCH.md)을 함께 읽는다.
