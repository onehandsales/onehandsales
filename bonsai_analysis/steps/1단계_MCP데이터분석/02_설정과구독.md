# 1단계 학습 — 설정·연동·구독

검토일: 2026-11-18 KST. 로컬 캡처와 기존 분석 문서의 대조 결과다. 가격·플랜·정책은 캡처 당시 표시이며 현재 서비스 정책을 새로 확인한 결과가 아니다.

<a id="f116"></a>

## F116 — 설정 전체 탐색

원본: [Settings](../../flows/Settings/ANALYSIS.md) · 화면 **12/12** 확인.

- 01→02: 프로필 메뉴 → Settings/Account/Profile Settings. 가입의 Full Name과 달리 First name·Last name이 분리되고 Email·Title·개인 사진·Update Password·계정 삭제 진입이 있다.
- 03: Company Settings에는 운영 회사명·담당자·공개 프로필 Enabled/Disabled·URL·국가·주소가 있다. 회사명을 비우면 사용자 이름을 쓴다는 안내가 보인다. 고객 CRM 회사와 동일 객체로 확정하지 않는다.
- 04→05: 기본 고객 발송 메시지(청구서·제안서 본문) → 개인 알림 선호 5개, 브라우저 알림 진입, 장시간 타이머 이메일 기준. 문구에 이름이 들어 있다고 동적 변수 기능을 추정하지 않는다.
- 06→07: Contractor/Client Mode → 2FA. Email Verification 선택·SMS 대안·무작위 6자리 안내가 있다. **30일 장치 기억은 로그인에만 적용된다고 화면에 명시**된다. 기존 분석의 추가 질문을 이 문구로 보완한다. Enabled/Disabled의 흐린 표현만으로 해제 가능 여부를 판단하지 않는다.
- 08: Branding은 회사 로고·표시 크기·헤더·폰트·색과 Sample Invoice 미리보기. 변경은 새 문서에만 적용된다는 안내가 핵심이다.
- 09→10: Team의 초대/가입 공존 목록 → 연동 카드. Gmail·Google Calendar·Zapier·Slack·QuickBooks·Calendly·ClickUp·Trello·Google Drive가 보인다. 카드를 실제 연결한 증거는 없다.
- 11→12: 이미 기간 말 해지 예약된 Starter와 종료일 → 플랜 기능 비교·별도 Tax 상품. 화면 간 Upgrade Now 유무가 달라 전체를 동일 시점의 연속 저장 작업으로 취급하지 않는다.
- Account 내부 Client Portal 메뉴는 보이지만 그 패널을 연 화면은 이 루트에 없다. 탭을 테이블과 일대일로 대응시키지 않는다.

## F117 — 계정 삭제 진입

원본: [Deleting account](../../flows/Settings/Deleting%20account/ANALYSIS.md) · 화면 **5/5** 확인.

- 01→02: 프로필에서 아래로 스크롤해 별도 Delete Account 카드에 접근한다.
- 03→04: Confirm Account Deletion 모달에서 Current Password를 입력한다. 프로젝트·제안·계약·청구서 삭제 안내와 고객의 서명 계약·지급 완료 청구서 접근 보존 안내가 함께 있다.
- 05: 빈 로그인 화면으로 돌아간다. 삭제 성공 토스트나 실제 데이터 재조회는 없다.
- 로그인 이동만으로 완전 삭제·구독 취소·팀 전체 삭제를 확정하지 않는다. 기존 분석에는 과거 UI와 후속 공식 문서의 비활성화/영구 삭제 구분 차이가 기록되어 있어 2단계 재확인 대상으로 남긴다.

## F119 — 브랜드 기본값 편집

원본: [Editing branding settings](../../flows/Settings/Editing%20branding%20settings/ANALYSIS.md) · 화면 **6/6** 확인.

- 01→02: 로고 파일과 Small Square 84×84, 헤더 No image, 폰트·색 설정에서 아래 화이트라벨 3개 선택지까지 스크롤한다. Show Bonsai branding만 선택되어 있고 나머지 두 선택지에 왕관이 있다.
- 03→04→05: 헤더 목록(No image·Abstract·Plant·Desk·Custom Header)을 연 뒤 Abstract, Plant 순서로 미리본다. 이미지가 생기면서 로고가 헤더 경계에 겹쳐 배치된다.
- 06: 상단으로 돌아와 Plant 상태와 브랜딩 저장 성공 토스트를 확인한다. 미리보기 변화와 저장 완료를 구분한다.
- 새 문서 적용 안내는 명확하지만 기존 문서 수정·실제 새 문서 생성 결과는 없다. 왕관 옵션 구매 조건·커스텀 헤더 파일 제한은 미확인이다.

## F120 — 알림 선호 편집

원본: [Editing notification settings](../../flows/Settings/Editing%20notification%20settings/ANALYSIS.md) · 화면 **4/4** 확인.

- 01→02: 체크된 5개 알림과 브라우저 알림 진입, 타이머 기준 360분까지 확인한다.

- 브라우저 권한과 앱의 수신 선호는 별도다. 360분을 모든 계정의 고정 기본값으로 확정하지 않는다.

## F122 — CSV 가져오기와 실패

원본: [Importing a CSV](../../flows/Settings/Importing%20a%20CSV/ANALYSIS.md) · 화면 **11/11** 확인.

- 01→03: 연동 카드 → 하단 Import/Download → 가져오기 유형 선택. Import는 Clients·Paid Invoices·Time Entries·Expenses, Download는 Invoices·Projects·Expenses·Clients·Time Tracked여서 범위가 다르다.
- 02–03의 하단에는 Google Sheets·Xero·Hubspot 카드와 Request an integration 링크도 있다. F116의 상단 9개 카드와 합쳐 이 설정 화면에서 확인한 연동 카드는 12개다. Google Sheets 연결을 통한 자동화, Bonsai 청구서 결제 시 Xero 판매 청구서 생성, Hubspot의 CRM·마케팅 작업 자동화는 카드의 설명이며, 실제 연결·실행 결과는 이 흐름에 없다.
- 04→06: Expenses 안내 → 파일 첨부 전 → balances.csv 첨부 및 Import CSV 활성. Name·Amount·Date가 required, Date는 YYYY-MM-DD, Currency는 ISO 코드, 가져온 비용은 uncategorized라는 안내가 보인다.
- 07→08: 열 매핑 빈 상태 → Name에 Balance를 연결하자 샘플 2행의 이름이 -10.00으로 나타난다. 원본 열 선택과 데이터 의미 검증은 별개다.
- 09: Name=Account, Amount=Balance, Date=Date, Billable=Account, Currency=Date. 마지막 두 매핑은 자료형에 맞지 않는데도 Import Data는 진한 녹색이다.
- 10→11: 처리 중 → Line 2부터 18까지 17개 Billable 오류. 허용 값 blank/true/false와 CSV 수정 후 재시도 링크를 보여준다. 성공으로 끝나는 흐름이 아니다.
- Currency 오류가 없다고 날짜를 통화로 허용하는 것은 아니다. 부분 저장·전체 취소·재시도 중복 방지·파일 제한과 다른 유형의 매핑은 미확인이다. CSV의 required를 다른 생성 경로의 DB 제약으로 곧바로 옮기지 않는다.

## F126 — 서비스 구독

원본: [Subscribing to Starter plan](../../flows/Subscribing%20to%20Starter%20plan/ANALYSIS.md) · 화면 **12/12** 확인.

- 01→03: 체험 종료 화면 → Professional 추천 선택 → Starter 선택. 추천 배지와 실제 선택은 독립이며 CTA 이름이 바뀐다.
- 04→05: 연 결제의 월 환산 $21·총액 $252 → 월 결제 $25·총액 $25. 자동갱신 설명도 연/월에 맞춰 바뀐다. 이는 캡처 당시 가격이다.
- 06→09: 카드 입력 후 처리 중 → hCaptcha 미체크/체크 → 카드 브랜드와 끝자리 요약. 봇 확인 성공·결제수단 표시·결제 승인·구독 반영을 한 상태로 합치지 않는다. 카드 상세값은 학습 문서에 옮기지 않는다.
- 10: 구독 업데이트 토스트, Starter 월 구독, 다음 청구일과 결제수단 요약. 결제수단 관리·업그레이드·해지·연간 전환 경로가 나타난다.
- 11→12: 기본 플랜 비교·Tax → 별도 Team Seat·Subscription Receipts의 이용기간/금액 행. 고객에게 발행하는 업무 인보이스와 Bonsai 사용료 영수증을 구분한다.
- 실패·추가 카드 인증·할인코드·세금·일할 계산·좌석 청구·영수증 상세는 미수록이다. 화면 성공은 결제사 승인 로그를 검증한 결과가 아니다.

## F127 — 구독 해지 예약

원본: [Canceling subscription](../../flows/Subscribing%20to%20Starter%20plan/Canceling%20subscription/ANALYSIS.md) · 화면 **10/10** 확인.

- 01→02: 활성 Starter에서 해지 영향 확인. 프로젝트/미서명 계약/미결제 청구서·장부/대시보드·프로모션 제한 안내와 유지/계속/일시정지 대안이 있다.
- 03→05: 다음 3개월 50% 할인 제안 → 1~3개월 일시정지 제안과 6개 해지 사유 → 사업 중단 선택 후 최종 해지 버튼이 진해진다. 할인·정지 분기는 실제 실행되지 않았다.
- 06→09: 후속 설문 로딩 → 이미 취소되었다는 안내와 개선점 질문 → No 입력 → 피드백 완료. 설문 필수 표시를 해지 처리의 선행조건으로 해석하지 않는다.
- 10: 청구기간 말 취소 예정 토스트, 현재 Starter/월 금액과 종료일, 해지 철회 링크가 남는다. 계정 삭제나 즉시 접근 차단으로 끝나지 않는다.
- 기간 말 실제 권한·철회·설문 닫기·환불은 미확인이다. 기존 분석에 기록된 공식 자료와 캡처의 권한/환불 차이는 2단계에서 다시 검증한다.

## 연결해서 이해한 내용

- 운영 회사 설정·개인 프로필·고객에게 보낼 문서 기본값·계정의 서비스 구독은 서로 다른 범위다. 비슷한 Save Changes도 저장 대상과 후속 이동이 다르다.
- 공개 프로필 비활성화, 초대 제거, 구독 해지 예약, 계정 삭제 진입은 각각 별도의 상태 변화다.
- 미리보기·필수 입력 충족·처리 중·검증 실패·저장 성공을 구분해야 한다. CSV의 녹색 버튼과 구독의 CAPTCHA 체크는 최종 성공의 증거가 아니다.
