# 청구서·결제 연결·수입·지출

Gummble에 저장된 캡처를 순서대로 직접 확인한 1단계 기록이다. 금액·날짜·세율은 캡처의 사례 값이며 제품 정책으로 확정하지 않는다. 기존 ANALYSIS의 공식 문서 대조는 이전 조사이고, 이 단계에서 새로 조회한 결과가 아니다.

## F077 — 청구서 목록과 두 종류의 설정

원본: [Invoices](../../flows/Invoices/ANALYSIS.md) · 화면 **4/4** 확인.

- 01–04: Dashboard → #1001 목록 → Default Values → Invoice Settings. 목록은 발행일·만기일·번호·프로젝트·고객·총액·입금액을 따로 보여준다. 결제수단 안내의 Cards/Bank Transfer/PayPal은 꺼져 있어도 초안은 존재한다.
- Default Values는 미래 문서 초기값, Invoice Settings는 기존·신규 문서 적용 안내다. 두 설정의 적용 범위를 혼동하지 않는다. 회색 상태 점만으로 상태 코드 전체를 정하지 않는다.

## F010 — 반복 비용 등록과 검증 오류

원본: [Adding a recurring expense](../../flows/Bookkeeping/Adding%20a%20recurring%20expense/ANALYSIS.md) · 화면 **11/11** 확인.

- 01 비용 빈 상태 →02 Business 비용 폼 →03 Travel expenses 입력 →04 분류 펼침 →05 Advertising 선택 →06 125 USD 입력 →07 Billable·Recurring 체크 →08 반복 간격 오류 →09 30 Days로 수정 →10 이미지·Travel notes 추가 →11 생성 성공이다.
- 필드는 Business/Personal, 이름, 카테고리, 금액·통화·날짜, Billable, 선택적 Project, 반복 여부·간격 숫자·단위, 이미지/영수증, 메모다. 예시의 프로젝트는 비어 있다.
- 07의 회색 10은 예시이고, 08은 반복 간격이 0보다 커야 한다는 오류다. 입력은 유지되고 30 Days 지정 후 오류가 사라진다. 30일 반복을 월별 반복으로 바꾸어 해석하지 않는다.
- 종료는 새 미청구 비용 생성 성공이며 125, Advertising, 첨부·반복 아이콘이 목록에 보인다. 입력 날짜 Feb 6과 목록 Feb 5가 다르며 시간대·캡처 간 변경 원인은 미확인이다. 다음 반복 발생이나 청구 전환은 나오지 않는다.

<a id="f017"></a>

## F017 — 비용 필터와 빈 결과 복원

원본: [Filtering expenses](../../flows/Bookkeeping/Filtering%20expenses/ANALYSIS.md) · 화면 **10/10** 확인.

- 01 목록 →02 필터 →03 두 달 달력 →04 Last 30 Days(Jan 7–Feb 6) →05 상태 목록 →06 Non-billable로 두 건 →07 Advertising 추가로 0건 →08 Has Receipt Yes →09 패널을 닫아 조건 칩 확인 →10 분류·영수증 조건 제거 후 두 건 복원이다.
- 기간·Status·Category·Client·Currency·Project·최소/최대 금액·영수증 유무를 제공한다. 날짜는 시작/종료 두 칩, 각 조건에는 제거 X가 있다. 별도 Apply 버튼은 보이지 않지만 정확한 적용 이벤트는 알 수 없다.
- Status 선택지에 Uncategorized, Billable reimbursed/not-reimbursed, Non-billable, Recurring, Questionable Deduction이 함께 있다. 반복 여부와 청구 상태가 동시에 존재할 수 있으므로 배타적 상태 하나로 해석하지 않는다.
- No expenses yet는 필터 결과 0건에도 사용된다. 원장 전체가 비어 있는 시작 안내와 다르다. AND/OR의 전체 규칙·날짜 경계·다중 분류·검색 및 CSV 범위는 미확인이다.
