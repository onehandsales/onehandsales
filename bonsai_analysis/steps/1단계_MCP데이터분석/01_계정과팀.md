# 1단계 학습 — 계정·초대·팀

검토일: 2026-11-18 KST. 아래 확인 범위는 이번 작업에서 실제 열람한 로컬 캡처와 기존 분석 문서 기준이다. 실계정 조작·공식 사이트 재조회는 수행하지 않았다. F번호는 이번 학습의 플로우 식별 번호다.

<a id="f086"></a>

## F086 — 가입

원본: [Onboarding](../../flows/Onboarding/ANALYSIS.md) · 화면 **10/10** 확인.

- 01→02: 공개 랜딩의 이메일 입력과 Start free 진입. 우측 수입·비용 알림 그림은 제품 설명용 이미지다.
- 03→04: 가입 카드에 이메일이 유지되고 Full Name 한 칸에 이름을 입력한다. Google 가입, 기존 사용자 로그인, 비밀번호 표시 아이콘이 보인다.
- 05→06: 비밀번호 입력의 `Too Weak`와 최소 10자 안내를 확인했다. 다음 캡처는 길이 오류 말풍선을 보이며 이메일·이름·마스킹 입력이 남아 있다.
- 07→08: 비밀번호 수정 후 오류 말풍선이 사라지고, 다음 화면에는 `Strong`과 CAPTCHA 체크가 보인다. 강도 판정과 CAPTCHA는 별도 표시다.
- 09→10: 가입 카드 위 대기 오버레이 후 `Welcome, Joe.` 사업 설문으로 이동한다. 가입 폼과 사업 설정은 별도 화면 단계다.
- 약관은 계정 생성 시 수락한다는 안내와 링크다. 별도 동의 체크박스·이메일 인증 완료 화면은 이 캡처에 없다.
- 후속 질문: 중복 이메일, 소셜 계정 연결, 이메일 인증, 비밀번호 강도 산정, 실패·중단 후 복구. 캡처의 최소 길이를 현재 정책으로 확정하지 않는다.

## F087 — 사업 설정과 첫 대시보드

원본: [Completing account setup](../../flows/Onboarding/Completing%20account%20setup/ANALYSIS.md) · 화면 **16/16** 확인.

- 01→03: 업종 선택 목록을 열고 내부 스크롤로 Design에 접근한다. 강조된 항목과 선택 확정 값은 구별된다.
- 04→05: Design 선택 후 회사명·국가 입력이 나타난다. Malaysia가 표시되고 Joe Studio 입력 뒤 Next가 진한 녹색이 된다. 국가에는 법적으로 사업을 운영하는 곳이라는 설명이 있다.
- 06→08: 사업 형태·청구 통화·예상 연 매출을 묻는다. MYR이 표시되며 Registered/Incorporated에서 Unregistered로 선택이 바뀌고 마지막에는 RM0–RM50,000 구간이 보인다. 이 값은 실제 매출 집계가 아니라 설문 응답이다.
- 09→10: 진행 표시가 네 번째 칸인 팀 초대 화면에 이메일 입력 3칸이 있다. 첫 칸만 입력한다. 세 번째 진행 칸의 질문은 수록되지 않았다. 세 칸을 최대 팀원 수로 해석하지 않는다.
- 11→12: 사용 목적 7개 중 Client billing, Time tracking and reporting, Bookkeeping and banking, Project and task management의 네 항목이 선택된다. 복수 선택 안내가 있으며 메뉴 활성화 정책은 화면에 없다.
- 13→14: 대시보드 로딩 후 회사 정보·팀 초대·예약 페이지·문의 폼·장부 자동화 체크리스트가 나타난다. 팀 초대 완료 표시가 초대자의 수락 완료를 증명하지는 않는다.
- 15→16: 타임라인·활동·작업은 빈 상태, 손익·시간 집계는 0이다. 배경의 흐린 예시 행을 실제 저장된 레코드로 세지 않는다.
- 추가 확인: 설문은 MYR인데 대시보드는 USD다. 기본 청구 통화와 보고서 표시 통화의 관계는 미확정이다. 화면 날짜를 캡처일로 사용하지 않는다.

## F083 — 로그인

원본: [Logging in](../../flows/Logging%20in/ANALYSIS.md) · 화면 **5/5** 확인.

- 01→02: 공개 랜딩에서 로그인 페이지로 이동한다. 좌측은 Changelog, 우측은 인증 카드다.
- 03→04: 이메일·마스킹 비밀번호 입력 뒤 CAPTCHA 체크 상태로 바뀐다. Google·Apple 로그인, Reset Password, Resend Verification Email 경로가 함께 보인다.
- 05: Joe의 대시보드와 기존 프로젝트 타임라인이 나타난다. 새 가입 후 빈 대시보드와 구분한다.
- CAPTCHA 체크 전에도 로그인 버튼이 녹색이다. 버튼 색을 서버 검증 완료나 제출 허용의 증거로 쓰지 않는다.
- 후속 질문: 2FA·장치 기억·소셜 연결·역할별 진입 화면은 이 흐름에 수록되지 않았다. 로그인 화면의 변경 공지를 실제 기능 실행으로 취급하지 않는다.

## F084 — 비밀번호 재설정

원본: [Resetting password](../../flows/Logging%20in/Resetting%20password/ANALYSIS.md) · 화면 **10/10** 확인.

- 01→04: 로그인 → 재설정 이메일 폼 → 이메일 입력 → CAPTCHA 체크.
- 05→06: 이메일 발송 안내 후 New Password 폼으로 이동한다. 메일함·실제 수신·링크 클릭·토큰 값은 중간에 없다.
- 07→08: 새 비밀번호 제출 뒤 `Whoops! / Password is too weak` 오류가 나타나고 입력이 빈 placeholder로 돌아간다. 가입의 길이 오류 때 값이 유지되는 동작과 다르다.
- 09: 다시 입력해도 이전 오류가 화면에 남아 있다. 정확한 재검증 트리거는 미확인이다.
- 10: 빈 로그인 폼과 새 비밀번호 설정 성공 토스트. 인증된 대시보드로 바로 진입하는 캡처는 아니다.
- 새 비밀번호는 한 칸이며 확인 입력은 없다. `Resend Verification Email`은 이름 그대로 기록하며 비밀번호 재설정 메일 재발송과 동일한 동작으로 확정하지 않는다.
- 후속 질문: 토큰 만료·재사용, 존재하지 않는 이메일, 재발송 제한, 기존 로그인 세션의 처리.

## F068 — 팀원 초대

원본: [Inviting a member](../../flows/Inviting%20a%20member/ANALYSIS.md) · 화면 **5/5** 확인.

- 01→02: 대시보드 Invite Team에서 Settings/Team 위 Invite Member 모달로 이동한다. 이메일·Role·Projects가 각각 독립 입력이다.
- 03→04: 이메일만 입력한 상태에서 Collaborator와 프로젝트 한 개를 선택한 상태로 바뀐다. 프로젝트는 제거 가능한 칩이며 CTA도 Invite Collaborator로 바뀐다. 선택 목록 자체는 캡처되지 않았다.
- 05: Invite sent 토스트와 새 Collaborator 행. 이름 자리에는 이메일, Projects에는 1 Project, Joined에는 Invite Pending이 나온다. 기존 Owner·Partner는 All Projects로 표시된다.
- 발송 완료는 수락 완료가 아니다. 역할별 프로젝트 필수 여부·복수 선택 상한·초대 중복·좌석 과금 시점은 미확인이다.

## F002 — 초대 수락과 협업자 화면

원본: [Accepting an invitation](../../flows/Accepting%20an%20invitation/ANALYSIS.md) · 화면 **13/13** 확인.

- 01→03: 인증이 필요하다는 토스트가 있는 로그인 → 자격정보 입력 → Invalid email or password 오류. 02와 03의 이메일은 다르므로 동일 요청의 실패 결과로 단정하지 않는다.
- 04→07: 일반 가입 폼 → `jon` 입력의 이메일 형식 오류 → 이메일·Jon Smith·비밀번호 입력 → Strong/CAPTCHA 체크. 초대 회사 표시가 없는 일반 가입 구간이다.
- 08→09: Joe Studio의 초대 전용 폼으로 바뀌고 초대 이메일이 고정 표시된다. 앞선 이메일과 또 다르다. Full Name·Password 입력과 Accept Invitation이 있으며 별도 Work Email 입력은 없다.
- 10: 비밀번호 설정 및 로그인 성공 토스트와 배정 프로젝트 상세로 진입한다. 사이드바는 Projects·Tasks, 프로젝트 탭은 Overview·Tasks·Time Tracking·Team이다. 작업 집계와 청구 전/후 시간이 보인다.
- 11→13: Tasks 보드의 완료 작업 → Projects 한 행 → 축소된 프로필 메뉴(Help Center·Settings·Logout). Owner 화면의 금액·문서 메뉴와 차이가 있지만 API 권한 차단까지 검증한 것은 아니다.
- 초대 이메일 실제 수신, 링크/토큰, 기존 회원의 수락, 만료·재사용·타 워크스페이스 전환은 수록되지 않았다. 여러 이메일 구간을 하나의 확정된 계정 생명주기로 합치지 않는다.

## F123 — 팀에서 사용자 제거

원본: [Removing a user](../../flows/Settings/Removing%20a%20user/ANALYSIS.md) · 화면 **4/4** 확인.

- 01→02: Owner 포함 5행 목록에서 마지막 Invite Pending 행의 메뉴를 연다. Resend Invite·Remove가 나타난다. 같은 표시 이름의 다른 이메일 행이 공존한다.
- 03: 대상 이메일을 명시한 Confirm Removal. 모든 프로젝트·문서 접근을 철회한다는 안내와 빨간 Remove Member 버튼이 있다.
- 04: 해당 행이 없어져 4행이 되고 Team member removed 토스트가 나타난다. 이 캡처의 대상은 초대 대기자다.
- 실제 가입된 사용자의 제거, 담당 작업/댓글의 보존, 기존 세션 무효화, 계정 자체 삭제는 이 흐름으로 확인할 수 없다.

## 연결해서 이해한 내용

- 계정 생성 → 사업 설문 → 대시보드 체크리스트가 서로 다른 단계다. 팀 이메일 입력과 초대 수락도 구분해야 한다.
- 가입 오류는 필드 주변 말풍선, 재설정 오류는 폼 본문의 오류 영역, 완료 알림은 토스트로 나타난다. 같은 인증 영역에도 오류 표현·값 유지 방식이 다르다.
- 로그인 페이지가 여러 흐름의 종료 화면으로 재사용된다. 성공 토스트와 앞선 맥락 없이 화면만 보고 로그아웃·계정 삭제·비밀번호 변경을 판정하면 안 된다.
- 초대 이메일·계정 프로필·팀 멤버십·프로젝트 배정은 화면에서도 따로 표현된다. 표시 이름을 식별자로 삼거나 Invite Pending을 가입 완료로 취급하면 흐름이 맞지 않는다.
