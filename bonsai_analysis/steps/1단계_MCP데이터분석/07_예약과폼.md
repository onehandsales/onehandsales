# 1단계 — 예약과 폼

예약 유형 설정과 실제 예약, 폼 정의와 제출 응답을 구분하여 캡처 순서대로 검토했다. 아래는 저장된 Gummble 이미지 관찰이며 최신 공식 정책의 확인은 2단계 대상이다.


<a id="f043"></a>

## F043 — Google 캘린더 연결

원본: [Connecting to Google Calendar](../../flows/Dashboard/Connecting%20to%20Google%20Calendar/ANALYSIS.md) · 화면 **8/8** 확인.

- 01 Dashboard의 Create your booking page →02 Scheduling 소개 →03 제공자 선택 →04 Google →05 Cronofy 동의 전 →06 동의 체크 →07 Bonsai 복귀 →08 연결 성공 알림과 New Event Type이다.
- Google/Apple/Office 365/Exchange/Outlook.com이 보인다. Cronofy를 통한 일정 조회·추가 안내가 있지만 Google 계정 선택·권한 동의 화면은 생략되었다.
- 연결 후에도 유형·예약은 비어 있다. 연결 성공은 08의 알림과 선택된 캘린더로 확인하며, OAuth scope·토큰·재연결·팀 공유 범위는 알 수 없다.

## F042 — 예약 유형의 기본 정보

원본: [Adding event details](../../flows/Dashboard/Connecting%20to%20Google%20Calendar/Adding%20event%20details/ANALYSIS.md) · 화면 **5/5** 확인.

- 01 기본 폼 →02 Consultation call과 consultation-call slug 입력 →03 설명 입력 →04 Availability 로딩 →05 주간 시간표 표시다. 유형 생성 마법사는 Details / Availability / Advanced Settings / Branding & Design 네 단계다.
- 회의 방식 Video Conferencing, Google Meet, 30 Minutes, 기록할 캘린더, URL 접두사와 slug, 설명, 고객 확인 이메일 체크가 있다. Google Meet 링크는 예약 후 생성된다는 안내이며 실제 링크 생성은 아직 없다.
- 가용성 화면은 충돌 검사 대상 Included calendars All, 평일 09–17시, 주말 불가, Kuala Lumpur 시간대를 표시한다. 회색 로딩 상태를 불가 시간으로 해석하지 않는다. slug 자동생성·중복 검증은 미확인이다.

## F047 — 주간 가용 시간과 충돌 검사 캘린더

원본: [Setting up availability](../../flows/Dashboard/Connecting%20to%20Google%20Calendar/Setting%20up%20availability/ANALYSIS.md) · 화면 **8/8** 확인.

- 01 기본 시간표 →02 캘린더 목록 →03 기본 캘린더 한 개 선택 →04 수요일 09:00–09:30 hover →05 수요일 12:30–13:00 hover →06 수요일 제외·월요일 hover →07 월·수·금 점심 제외 →08 고급 설정으로 이동한다.
- 한 외부 계정에 여러 캘린더가 있으며 All 표시를 개별 선택 칩으로 바꿀 수 있다. 예약을 기록할 캘린더와 충돌 검사 대상 집합은 서로 다른 입력이다.

- 요일 반복 시간표와 특정 날짜의 확정 예약은 다르다. 날짜 예외·공휴일·시간대 변경·DST·동시 예약·연결 해제 영향은 추가 확인한다.

## F063 — 폼 공유

## F060 — 공개 폼 입력과 제출 오류 복구

원본: [Giving a response](../../flows/Forms/Form%20responses/Giving%20a%20response/ANALYSIS.md) · 화면 **9/9** 확인.

- 01 공개 폼 →02 Amanda Soh와 이메일 입력 →03 매체/파일 형식 미선택 →04 Logo·E-newsletter·Poster 복수 선택 →05 PDF·.png 복수 선택 →06 하단 Credit card 선택 →07 예산 숫자 오류 →08 200 입력 →09 Thank you 제출 성공이다.
- 이름·성·이메일·파일 형식·예산·결제 방식에는 필수 별표가 있다. 웹사이트·사업명·첨부·시작일은 이 캡처에서 비어 있어도 제출되었다. 중간 브랜드 관련 질문 선택 과정은 생략되었다.
- 회색 0은 빈 숫자 입력의 예시다. Please enter a number value를 0 금지 규칙으로 해석하지 않는다. 200 입력 직후에도 이전 오류가 남고 다음 제출에서 성공한다.
- 질문 재정렬 흐름 F062의 추가 문의 질문은 이 공개 폼 하단에 없다. 삭제·버전·발행 시점 차이 중 원인은 미확인이다. 공개 화면/편집 화면/응답 상세를 무조건 같은 시점으로 합치지 않는다.
- 제출 뒤 이메일이 채워진 Continue는 Bonsai 가입 유도다. 폼 제출 성공은 그 전에 완료된다. 자동 고객 생성·이메일 매칭·재제출 방지·자동화 실행은 보이지 않는다.

## F061 — 응답 상세와 고객 연결 진입점

원본: [Response detail](../../flows/Forms/Form%20responses/Response%20detail/ANALYSIS.md) · 화면 **4/4** 확인.

- 01 응답 목록 →02 View Response/View Client/Delete Response 메뉴 →03 Jane Studio 응답 상단 →04 하단과 Print다.
- Submission Date와 Email, 비어 있는 답변의 '-', 복수 선택 목록, 예산 200, Credit card, 비어 있는 시작일을 확인한다. F060과 이메일·일부 답변이 일치하지만 제출 이름 Amanda Soh와 표시명 Jane Studio가 다르다.
