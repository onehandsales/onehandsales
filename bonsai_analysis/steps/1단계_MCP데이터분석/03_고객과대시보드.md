## F003 — 고객 생성

원본: [Adding a new client](../../flows/Adding%20a%20new%20client/ANALYSIS.md) · 화면 **7/7** 확인.

- 01→02: 빈 타임라인의 대시보드에서 전역 +New 메뉴를 연다. Client·Project·Invoice·Proposal·Contract·Form·Expense 생성 진입이 모여 있다.
- 03→05: New Client 빈 폼 → 회사명·담당자명·이메일 입력 → Client 태그 칩. Contact Name·Email에는 별표, Company Name에는 없다. 추가만으로 고객에게 알리지 않는다는 안내가 명시된다. 태그 선택 과정은 생략됐다.
- 06: 고객 추가 성공 토스트와 Doe Company 상세. Active·Client 태그·Default Contact가 별도로 표시되고 Add New Contact 진입이 있다. 연락처명과 고객명도 다르다.
- 07: 노트·인보이스·완료 폼이 비어 있고 청구 집계는 USD/Outstanding·Overdue·Paid/Pending 각각 0이다. Company Title에는 문서에 미리 채운다는 안내, 연락처 외 Phone·Website·Address와 Edit Fields가 보인다.
- 회사명 공백·이메일 중복·추가 연락처·기본 연락처 변경·알림 예외는 미확인. 화면의 회사/연락처 동시 입력을 동일 테이블이나 고정 1:1 관계의 근거로 삼지 않는다. 기존 문서의 현재 회사/연락처 분리 모델은 다음 공식 문서 검증과 대조할 대상이다.

## F041 — 업무 대시보드 탐색

원본: [Dashboard](../../flows/Dashboard/ANALYSIS.md) · 화면 **8/8** 확인.

- 01–02: 프로젝트 3개 타임라인, 문서 빠른 생성 4종, 손익 통화/기간 필터 → 문서 아이콘 툴팁에 Contract Sent와 Invoice Drafted. 문서 생성일·발행일·금액을 함께 표시한다.

- 06–08: 청구 전 시간 08:01:16/$160.42, 청구된 시간 01:00:07/$20.04 → 일별 툴팁 → 오래된 활동. 활동에는 제안서 수락·보관·복원, 계약 작성·자신의 서명·발송, 폼 발송/응답, 작업 완료가 별개로 나온다. 청구된 시간과 결제 완료 금액은 같은 개념이 아니다.
- 같은 문구의 작업 완료 활동이 두 번 보이지만 중복 원인은 미확인. 복원 활동은 존재하지만 복원 조작 화면은 없다. 이 흐름은 스크롤·툴팁 탐색이며 표시된 사건을 이 8장 동안 실행한 것으로 보지 않는다.

## 영역 간 연결과 남은 질문

- 자신의 회사 정보 → 문서 기본 정보/브랜딩, 고객 → 연락처/프로젝트/포털, 프로젝트 → 문서/작업/시간/비용으로 연결된다. 이름·이미지가 같다는 이유로 서로 같은 객체로 보지 않는다.
- 대시보드는 각 영역의 집계와 활동을 모아 보여준다. Drafted·Sent·accepted·Incomplete·완료·청구 전/후·결제 상태를 하나의 공통 상태 목록으로 합칠 근거는 없다.
- 검색·사이드바·추천 링크는 공통 진입/편의 기능이다. 화면 선호 저장 방식이나 검색 색인을 지금 DB 테이블로 확정하지 않는다.
- 대시보드에서 시작하는 수입 기록은 재무 영역, 폼/예약 설정은 폼·일정 영역에서 이어서 검토한다. 기존 공식 문서 인용은 과거 조사 근거이며 이번 이미지 재검토와 구분한다.
