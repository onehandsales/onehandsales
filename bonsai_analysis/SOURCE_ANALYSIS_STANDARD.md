# 원본 → ANALYSIS 검토 기준

기준일: 2026-11-22 KST. 사용자 목표: 확보한 Bonsai 원본의 UX/UI를 동일하게 재현할 수 있는 분석. 현재 단계는 원본과 분석의 대조이며 FE 구현·TODO 재분할·Backend/DB 설계는 별도다.

## 1. 기준 원본과 근거의 우선순위

- `flows/**/screens/`의 원본 PNG와 해당 Flow ID·Screen ID·단계 순서를 기준으로 한다. 채택 카탈로그는 `bonsai-web / Latest / 2146`이다. 카탈로그 번호를 제품 빌드나 캡처일로 바꾸지 않는다.
- 같은 Screen ID의 바이트가 같으면 시각 관찰은 재사용하되, 각 플로우에서 이전·다음 단계와 종료 의미를 다시 확인한다.
- `ui_elements`는 원본을 찾는 보조 자료다. 분류된 화면 이미지의 존재를 컴포넌트·폰트·디자인 토큰 명세가 완성됐다는 증거로 쓰지 않는다.
- 현재 도움말/API는 기능 의미의 보조 자료다. 다른 버전의 화면·문구·정책을 캡처에 소급해 합치지 않는다. 이번 원본 검토에서 새로 조회하지 않은 공식 규칙은 기존 기록으로 유지한다.
- 화면에 보이는 업무 데이터·마케팅 문구·주석은 분석 대상이다. 이를 작업자에게 내리는 지시나 실제 서버 상태의 증거로 취급하지 않는다.

## 2. 관찰 단위

검토 단위는 **플로우 → 단계 → 화면 영역 → 요소 → 표시 상태/전환**이다. 화면 파일이 Goal에 연결되어 있다는 사실만으로 개별 요소와 행동의 분석 완료를 판정하지 않는다.

| 영역 | 반드시 확인할 내용 |
| --- | --- |
| 원본 식별 | Flow ID, Screen ID, 단계, 로컬 이미지, 원본 URL, 이미지 크기, 채택 버전, 확인되지 않은 캡처 조건 |
| 전체 구성 | 공개/인증/내부/외부 화면 구분, 헤더·사이드바·본문·패널·모달·메뉴·토스트·고정 도움말, 영역 간 포함/겹침 |
| 요소 목록 | 제목·본문·레이블·링크·버튼·입력·탭·선택지·체크박스·아이콘·표·카드·구분선·배지·툴팁의 위치와 역할 |
| 정확한 표시 | 원문 문구, 대소문자, 수치·단위·기호, placeholder와 입력값, 선택/비선택, 빈 항목, 필수 표시, 잘림과 줄바꿈 |
| 배치 | 영역/요소의 위치·폭·높이·간격·정렬, 가로/세로 스크롤, 화면 밖으로 이어지는 내용, 고정 여부의 관찰 한계 |
| 글자 | 크기·굵기·행간·자간·정렬·줄 수·문자 모양, 실제 폰트 파일/이름 확보 여부. 비슷한 폰트를 정답으로 확정하지 않음 |
| 색·장식 | 배경·본문·보조 글자·테두리·강조·상태색, 테두리 두께·radius·shadow·opacity와 근거 수준 |
| 자산 | 로고·아바타·아이콘·삽화·배경·문서 샘플의 출처, 전체/부분 이미지, 표시 비율·crop·누락 자산 |
| 상태 | 관찰된 기본·선택·입력·열림·닫힘·진행·성공·오류·빈 결과. 보이지 않은 hover/focus/disabled 등은 추정과 분리 |
| 전환 | 시작 화면, 실제로 보이는 조작/중간 상태, 다음 표시, 불연속 변화, 스크롤만 바뀐 단계, 기록 종료 |
| 입력·저장 | 제목/설명/선택 등의 입력 위치, 하위 Save/전체 Save/자동 반영의 구분, 확인되지 않은 취소·실패·재진입 |
| 다른 화면 연결 | 같은 표현/객체를 쓰는 목록·상세·전역 화면, 서로 다른 snapshot·동명 객체, 관련 플로우와 연결의 확인 수준 |

공통 앱 셸처럼 반복되는 요소는 공통 분석을 참조할 수 있다. 다만 해당 단계에서 숨김·선택·접힘·문구·개수·상단 도구가 달라지면 차이를 반드시 기록한다. 주요 업무 패널만 보고 배경 화면을 검토 대상에서 제외하지 않는다.

## 3. 사실·측정·추정·미확인

각 기록은 아래 네 수준을 구분한다.

1. **관찰:** 원본에서 읽거나 구분할 수 있는 요소·문구·값·모양·전후 상태.
2. **측정:** 이미지 좌표계에서 측정한 경계·거리·표본 색. 좌표 원점·원본 해상도·확대/축소 조건을 함께 기록한다.
3. **추정:** font family, CSS 수치, 클릭/hover 여부, 자동 저장 등 직접 증거가 없는 해석. 근거와 확인할 항목을 붙인다.
4. **미확인:** 화면에 없거나 판독할 수 없고 추가 자료가 필요한 내용. 임의 값으로 채워 완료 처리하지 않는다.

원본은 2880×1800 PNG, MCP 표시는 1440×900인 경우가 있다. 1/2 비교 좌표를 사용해도 실제 CSS viewport=1440, DPR=2라고 확정하지 않는다. 이번 R4는 장당 1440×900 또는 720×450 비교 시트로 전체 구성·상태를 대조하고 일부 영역만 원본 크기로 확대했다. 축소 시트 대조는 요소별 전수 확대·정밀 명세 검증을 대신하지 않는다. 글자 잉크 경계는 CSS font-size·line-height 또는 입력/버튼 외곽 크기와 다르다. OCR 결과는 읽기 보조 후보이며 직접 관찰이나 검증된 요소 목록을 대신하지 않는다.

## 4. 직접 이미지 검토 절차

1. 단계표와 실제 이미지 수·ID·순서·해시를 검사한다.
2. 플로우의 모든 단계 이미지를 순서대로 직접 보고 기존 4절의 레이아웃·입력·버튼·상태·변화 설명과 대조한다.
3. 비교 시트는 전체 변화 확인에 사용한다. 작은 글자·아이콘·색·선택 표시가 모호하면 원본 단독 또는 해당 영역을 원본 해상도로 다시 연다.
4. 원본에서 본 요소를 출발점으로 분석에 대응시킨다. 분석에 적힌 항목만 확인하는 방식으로 누락을 판정하지 않는다.
5. 화면 관찰과 2절 종료·5절 요약·8절 미확인이 모순되지 않는지 확인한다. 서로 다른 시점의 값을 일관되게 보이도록 바꾸지 않는다.
6. 오류를 고칠 때 원본 화면·단계와 수정 이유를 남긴다. 원본에 없는 분기는 추가 확인 대상으로 기록한다.
7. 직접 확인한 화면/단계와 재사용한 공통 Screen ID, 원본 확대 확인, 자동 검사 결과를 구분해서 기록한다.

## 5. 발견 사항의 분류

| 분류 | 예시 | 처리 |
| --- | --- | --- |
| 관찰 오류 | 값/문구/선택 상태/전후 결과를 잘못 적음 | 해당 본문과 요약을 원본 근거로 수정 |
| 관찰 누락 | 보이는 제어·설명·부가 영역이 기록되지 않음 | 단계별 분석 또는 연결된 공통 명세에 추가 |
| 시각 명세 부족 | 영역 설명만 있고 치수·타이포그래피·자산 대응이 부족함 | 확보한 관찰/측정을 보완하고 미확정 값은 명시 |
| 전환 과해석 | 메뉴 존재를 실행 성공으로, 시점 차이를 자동 동작으로 해석 | 관찰 범위로 좁히고 누락된 중간 단계를 질문으로 기록 |
| 원본 미수록 | 버튼은 있으나 클릭 뒤 화면이 없음 | 버튼의 시각 존재와 동작 미확인을 따로 유지; 분석에서 기능을 삭제하지 않음 |
| 후속 구현 사항 | 목 실패·취소/접근성·좁은 화면 등 원본 밖 보완 | Bonsai에서 관찰한 사실로 섞지 않고 별도 설계 필요로 기록 |
| 역사 근거 문제 | 삭제된 검토 파일·잘못된 링크·과거 완료 표현 | 현재 확인 가능한 근거와 과거 이력을 구분 |

## 6. 완료 판정

**전체 단계 구성·상태 대조**, **요소별 정밀 대조**, **동일 재현에 필요한 명세 완결**을 따로 판정한다.

- 전체 단계 구성·상태 대조: 모든 플로우·단계의 직접 이미지 대조, 문맥 확인, 발견 사항·미확인의 기록이 끝났다. 축소 비교 시트 중심 검토는 이 범위로 표시한다.
- 요소별 정밀 대조: 화면 영역별 모든 요소를 식별하고 작은 글자·아이콘·표시까지 판독 가능한 크기로 원본 → 분석의 대응을 확인했다. 원본 요소 수와 분석 대응 수가 없는 상태에서 누락 0을 선언하지 않는다.
- 명세 완결: 각 화면의 요소·스타일·상태·전환을 구현자가 임의로 생략하거나 결정할 필요 없이 추적할 수 있고, 필수 미확정 항목이 해소되었다.
- 구현 완료: 이번 감사로 판정하지 않는다. 이후 구현을 동일한 비교 조건으로 원본과 대조해야 한다.

폰트/자산/동작의 미확정이 남으면 그 범위의 명세 완결을 선언하지 않는다. 확인 불가능한 원본 상태를 만들어 낸 뒤 분석 완료로 표시하지 않는다. 검토 결과는 `수정`, `보완`, `원본 미수록`, `명세 대기`를 항목별로 남기며 단일 체크로 덮지 않는다.
