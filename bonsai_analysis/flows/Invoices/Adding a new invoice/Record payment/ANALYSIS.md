# Record payment 플로우 분석

최신 검토: **R4 전체 단계 구성·상태 대조 3/3 · 동일 재현 세부 명세 미완** (2026-11-22 KST). 장당 720×450 비교 시트로 직접 대조했다. 요소별 전수 확대·픽셀 일치 판정은 아니다. [기준](<../../../../SOURCE_ANALYSIS_STANDARD.md>) · [결과](<../../../../SOURCE_ANALYSIS_REVIEW.md>) · [원본 색인](<../../../../SOURCE_ANALYSIS_INDEX.json>).

기존 검토 기록: **R2 누락·내용 재검토 완료(정적 캡처 범위)**. 실제 이미지 재확인 **3/3단계**. 계정 재현은 수행하지 않았다.

추가 검토: **R3 문서·MCP 목록 대조 완료 / FE 보완 항목 있음**. 이번 이미지 확인은 고유 이미지 기준 선택 검토이며 이 흐름에 해당하는 화면은 **1/3단계**다. 기존 R2 전수 시각 검토 이력과 구분한다. [플로우별 FE 보완표](<../../../../FLOW_REVIEW_MATRIX.md#flow-085fa1f3-f846-4dac-9bbd-0b65f000a427>).

관찰은 Gummble 캡처에서 직접 본 내용, 문서 확인은 현재 공식 도움말·공개 API, 설계 가정은 우리 구현 후보를 뜻한다. 버튼의 존재·성공 안내·실제 서버 결과를 구분한다.

## 2. 플로우 목적과 연결

청구 담당자가 외부 입금을 기록하려 시도하지만 구독 인보이스의 결제 설정 조건에 막히는 경로다.

- 금액70.04의 Drafted 구독형 인보이스에서 시작한다.
- 이 흐름은 입금 기록 성공이 아니다. 결제 입력 필드도 나타나지 않는다.

- 상위 흐름: [Adding a new invoice](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Invoices/Adding a new invoice/Record payment`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **시간 포함된 구독 인보이스 초안**이다. 초안이며 결제수단 활성화 버튼이 남아 있다. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **입금 기록 차단 모달**이다. 검증 차단 상태. 성공 알림·Paid 표시 없음. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Adding a new invoice](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

### R2 재검토에서 보완한 해석

Record Payment 메뉴는 있지만 청구서 완성과 카드 결제 활성화를 요구하는 오류가 나타난다. 금액·일자 입력이나 Paid 결과는 없다. 구독 청구서의 차단 사례를 모든 수동 입금 기록의 필수 카드 조건으로 일반화하지 않는다.

### 업무 규칙과 연결 시 주의점

- [관찰] 인보이스 완성 후 지급 표시하라는 문구와 credit card payments 활성화 요구가 함께 나온다.
- [미확인] 이 제한은 구독형/현재 설정/당시 버전 중 무엇 때문인지 확정하지 않는다. 모든 수동 입금에 카드가 필요하다고 일반화하지 않는다.
- [문서] 현행 외부 입금은 완납·부분납, 방법·금액·날짜·선택적 고객 통지를 지원한다. 캡처의 차단 화면에서는 검증할 수 없다.

## 6. 공식 도움말과 API 대조

아래 URL과 5절의 문서 규칙은 **R2의 2026-11-20 대조 기록**이다. 공통 상세 대조 문서는 현재 체크아웃에 없다. R3에서 모든 URL을 다시 읽은 것은 아니며, 새로 확인한 자료와 적용 범위는 [이번 공식 자료 검토](<../../../../FE_REVIEW.md#official-sources>)에 구분했다. 과거 캡처에 현재 규칙을 소급 적용하지 않는다. 실제 계정이나 내부 API는 실행하지 않았다.

- [Invoices API](https://docs.hellobonsai.com/api/tag/invoices): R2 본문 대조 기록(S054). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [수동 입금 도움말](https://help.hellobonsai.com/en/articles/2899880-how-to-manually-mark-invoices-as-paid): R2 본문 대조 기록(S061). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.
