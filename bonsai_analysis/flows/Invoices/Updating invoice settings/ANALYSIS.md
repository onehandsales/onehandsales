# Updating invoice settings 플로우 분석

최신 검토: **R4 전체 단계 구성·상태 대조 5/5 · 동일 재현 세부 명세 미완** (2026-11-22 KST). 장당 720×450 비교 시트로 직접 대조했다. 요소별 전수 확대·픽셀 일치 판정은 아니다. [기준](<../../../SOURCE_ANALYSIS_STANDARD.md>) · [결과](<../../../SOURCE_ANALYSIS_REVIEW.md>) · [원본 색인](<../../../SOURCE_ANALYSIS_INDEX.json>).

기존 검토 기록: **R2 누락·내용 재검토 완료(정적 캡처 범위)**. 실제 이미지 재확인 **5/5단계**. 계정 재현은 수행하지 않았다.

추가 검토: **R3 문서·MCP 목록 대조 완료 / FE 보완 항목 있음**. 이번 이미지 확인은 고유 이미지 기준 선택 검토이며 이 흐름에 해당하는 화면은 **2/5단계**다. 기존 R2 전수 시각 검토 이력과 구분한다. [플로우별 FE 보완표](<../../../FLOW_REVIEW_MATRIX.md#flow-4a05877b-fd77-4532-a407-7c93a2168895>).

관찰은 Gummble 캡처에서 직접 본 내용, 문서 확인은 현재 공식 도움말·공개 API, 설계 가정은 우리 구현 후보를 뜻한다. 버튼의 존재·성공 안내·실제 서버 결과를 구분한다.

## 2. 플로우 목적과 연결

인보이스 테마를 Foundation으로 바꾸고 지급 후 팁 허용을 켠다.

- 전체 화면 Invoice Settings에서 시작한다.
- 설정 저장 후 인보이스 목록으로 복귀하며 성공 토스트가 나타난다.

- 상위 흐름: [Invoices](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Invoices/Updating invoice settings`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **인보이스 표현 설정 Studio**이다. 문서 테마와 결제 페이지 레이아웃을 별도 선택. 미리보기는 실제 청구서가 아니다. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **인보이스 설정 저장 후 목록**이다. 설정 저장 성공. 기존 캡처와 목록 데이터가 달라 촬영 시점 차이 가능. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Invoices](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

아래 URL과 5절의 문서 규칙은 **R2의 2026-11-20 대조 기록**이다. 공통 상세 대조 문서는 현재 체크아웃에 없다. R3에서 모든 URL을 다시 읽은 것은 아니며, 새로 확인한 자료와 적용 범위는 [이번 공식 자료 검토](<../../../FE_REVIEW.md#official-sources>)에 구분했다. 과거 캡처에 현재 규칙을 소급 적용하지 않는다. 실제 계정이나 내부 API는 실행하지 않았다.

- [Invoices API](https://docs.hellobonsai.com/api/tag/invoices): R2 본문 대조 기록(S054). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [인보이스 생성 도움말](https://help.hellobonsai.com/en/articles/2899904-how-to-create-an-invoice): R2 본문 대조 기록(S056). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [결제 페이지 레이아웃](https://help.hellobonsai.com/en/articles/6537018-payment-page-layouts-on-client-invoices): R2 본문 대조 기록(S060). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

## 7. 데이터 모델링 시사점

다음은 관찰에 기반한 OneHandSales 구현 후보다. 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- 계정 문서 테마·결제 페이지 배치·시간표 표시·팁·부분결제·첨부 잠금의 독립 설정 후보.
- 단가3자리 옵션은 표시/입력 정밀도 정책이며 전체 금액 통화 소수 자릿수와 혼동하지 않는다.

### 단계별 모델링 근거

- 단계 01: 계정 문서 스타일·결제 페이지 표시·첨부 접근·금액표현 정책 후보.
- 단계 02: 테마 식별자와 렌더링 구성 후보.
- 단계 03: 표시·결제 정책의 조건별 적용 후보.
- 단계 04: 팁 허용 설정과 실제 팁 거래를 분리하는 후보.
- 단계 05: 설정 저장과 업무 데이터 변경을 분리해 추적할 후보.

## 8. 미확인 사항과 검토 질문

**원본에 없는 분기·남은 범위:** 결제 완료 문서와 이미 내려받은 PDF에 스타일 변경이 어떻게 적용되는가? 보존 정책 확인이 필요하다. 팁 지원 결제수단·국가·요금제와 지급 후 반환·회계 집계를 별도 확인한다.

- 결제 완료 문서와 이미 내려받은 PDF에 스타일 변경이 어떻게 적용되는가? 보존 정책 확인이 필요하다.
- 팁 지원 결제수단·국가·요금제와 지급 후 반환·회계 집계를 별도 확인한다.
- 저장하지 않고 Close할 때 취소 확인 및 복원 여부를 확인한다.

### 단계별 미확인 사항

- 단계 01: Close 시 수정 폐기 여부, 요금제 제한, 기존 PDF 재생성 미확인.
- 단계 02: 미리보기 즉시 변경과 서버 저장의 시점은 다를 수 있음.
- 단계 03: 체크별 기본값·요금제별 차이 미확인.
- 단계 04: 고객 팁 화면·비율·금액 한도·거래처리 미수록.
- 단계 05: 변경된 옵션의 실제 고객 화면 적용·목록 데이터 생성 경위 미확인.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **결과**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: Foundation 유지·팁 on·명시적 Save를 재현한다. 미리보기 변경·저장·재진입을 나누고 팁을 청구 금액에 즉시 더하지 않는다.
- [이 흐름의 보완표](<../../../FLOW_REVIEW_MATRIX.md#flow-4a05877b-fd77-4532-a407-7c93a2168895>)와 [공통 웹 상태·연결 기준](<../../../FE_REVIEW.md#fe-acceptance>)을 함께 적용한다. 캡처에 없는 동작은 Bonsai 관찰 사실로 쓰지 않고 목 가정 또는 추가 조사로 표시한다.


### 동일 재현을 위한 남은 분석 (R4)

- Classic과 Single-Column 적용 화면·미저장 닫기·각 체크 옵션의 문서 반영 결과는 미확인이다. 설정 패널 스크롤 범위와 데모 크기를 별도 명세해야 한다.
- 공통 미완: 요소별 누락 검사, 정확한 배치·타이포그래피·색/장식·자산 대응·미노출 상태는 [12개 검토 항목](<../../../SOURCE_ANALYSIS_STANDARD.md>)으로 추가 명세한다. 원본에 없는 동작은 관찰 사실과 분리한다. 이 문서의 R4 표시를 동일 재현 명세나 FE 구현 완료로 읽지 않는다.
