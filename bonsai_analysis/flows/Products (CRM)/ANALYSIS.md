## 2. 플로우 목적과 연결

공개 방문자가 Product 메뉴에서 CRM 소개를 읽고 기능·템플릿·FAQ를 탐색한다.

- 실제 Clients/Projects CRUD가 아니라 공개 마케팅 흐름이다.
- 폼 템플릿·시간 기록·작업 관리·가입으로 연결되는 링크가 있다.


- 폴더 위치: `bonsai_analysis/flows/Products (CRM)`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 상위 흐름: 없음. Gummble 최상위 분류.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **Product 전체 메뉴**이다. Product 초록색 활성; 신기능은 Branded scheduling portal. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **CRM FAQ 첫 답변 열림**이다. 첫 답변만 열려 있다. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Clients](<../Clients/ANALYSIS.md>) · [Adding a new client](<../Adding a new client/ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../SOURCES.md#api>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

## 7. 데이터 모델링 시사점

다음은 관찰에 기반한 OneHandSales 구현 후보다. 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- 공개 제품 페이지·FAQ·추천 템플릿은 콘텐츠 후보.
- 업무 모델은 회사·담당자·프로젝트·폼 응답의 실제 연결을 Clients/Forms/API에서 대조해야 한다.

### 단계별 모델링 근거

- 단계 01: 공개 내비게이션 그룹·링크·프로모션 카드 후보.
- 단계 02: 콘텐츠 랜딩 변형 및 가입 유입 후보.
- 단계 03: 고객·프로젝트·팀원·문서 관계 후보를 앱/API와 대조.
- 단계 04: 회사·담당자 분리, 고객 프로필 속성, 프로젝트 문서 연결 후보.
- 단계 05: 제품 소개와 추천 템플릿의 연결 후보.
- 단계 06: 공개 템플릿 메타데이터·추천 순서 후보.
- 단계 07: 접근 정책은 공개/로그인/요금제 조건을 분리해 확인.
- 단계 08: 연관 기능 추천과 업무 모델 연결 후보.
- 단계 09: FAQ 콘텐츠와 펼침 상태 분리.
- 단계 10: FAQ 펼침 상태는 화면 상태, 폼→리드 연결은 별도 검증할 업무 후보.

## 8. 미확인 사항과 검토 질문

**원본에 없는 분기·남은 범위:** FAQ 나머지 두 답변과 메가 메뉴 키보드 동작은 미수록이다. Bonsai Forms 리드 자동 생성·중복 판정은 실제 앱에서 확인해야 한다.

- FAQ 나머지 두 답변과 메가 메뉴 키보드 동작은 미수록이다.
- Bonsai Forms 리드 자동 생성·중복 판정은 실제 앱에서 확인해야 한다.
- 목업 UI와 구현 기준 화면의 차이를 구분해 FE 컴포넌트 범위를 정한다.

### 단계별 미확인 사항

- 단계 01: 메뉴가 hover인지 click인지, 닫힘·키보드 포커스 미확인.
- 단계 02: 이메일 전달·검증·가입 경로는 본 흐름 미수록.
- 단계 03: 실제 관계 카디널리티·권한은 이 카드로 알 수 없다.
- 단계 04: 목업과 현재 실제 Clients의 필수 필드 차이 미확인.
- 단계 05: 클릭 후 가입 필요 여부와 템플릿 사용 결과 미확인.
- 단계 06: 각 제목과 실제 템플릿 스키마의 일치·공개 API 제공 여부 미확인.
- 단계 07: 유료 여부·템플릿 개별 접근 조건 미확인.
- 단계 08: 이 링크의 실제 이동 화면은 수록되지 않았다.
- 단계 09: 독립 다중 열림·키보드 접근·기본 열림 여부 미확인.
- 단계 10: 다른 답변·동시 열림·자동화의 정확한 범위 미확인.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.
