## 2. 플로우 목적과 연결

찾을 수 없는 페이지에 진입한 방문자에게 복구 경로를 제공하는 두 가지 오류 화면을 관찰한다.

- 두 장은 색·문구·배치가 다른 오류 화면이며 순차 클릭 결과라고 단정할 수 없다.
- 정확한 원래 URL·공개 사이트/앱 구분·HTTP 상태 코드는 이미지에 없다.


- 폴더 위치: `bonsai_analysis/flows/404`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.

## 5. 업무 규칙과 데이터 변화

- 화면에 404가 있어도 실제 HTTP 응답 코드·라우터 처리 방식은 미확인이다.
- 존재하지 않는 경로·삭제 자원·권한 은폐가 같은 화면을 사용하는지 확인되지 않았다.

## 6. 공식 도움말과 API 대조

- [Bonsai 공식 홈페이지](https://www.hellobonsai.com/): 현재 페이지의 고객·프로젝트·재무 영역 소개를 확인했다. 캡처와 카피·메뉴·기능 구성이 달라 동일 버전으로 취급하지 않는다.
- [공식 지원](https://www.hellobonsai.com/support): 현재 도움말·이메일·앱 채팅 경로를 확인했다. 404의 Report a problem이 이 경로인지 확인하지 못했다.
- [공개 API](https://docs.hellobonsai.com/api): 조회한 문서는 업무 리소스 중심이며 이 공개 페이지의 콘텐츠·검색·추천·제휴 관리 endpoint와 필드 계약은 확인하지 못했다. 화면 카드를 곧바로 업무 DB 테이블로 확정하지 않는다.

## 7. 데이터 모델링 시사점

- 페이지 찾기 실패·홈 복귀·문제 신고 UI 상태 후보. 별도 업무 엔티티가 필요한 근거는 없다.

## 8. 미확인 사항과 검토 질문

- 두 화면의 원래 도메인·URL·버전·실제 HTTP 상태를 확인한다.
- 홈·문제 신고 버튼 목적지와 인증 상태별 복구 경로를 확인한다.
