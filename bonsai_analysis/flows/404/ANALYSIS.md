기존 검토 기록: **R2 누락·내용 재검토 완료(정적 캡처 범위)**. 실제 이미지 재확인 **2/2단계**. 계정 재현은 수행하지 않았다.

추가 검토: **R3 문서·MCP 목록 대조 완료 / FE 보완 항목 있음**. 이번 이미지 확인은 고유 이미지 기준 선택 검토이며 이 흐름에 해당하는 화면은 **0/2단계**다. 기존 R2 전수 시각 검토 이력과 구분한다. [플로우별 FE 보완표](<../../FLOW_REVIEW_MATRIX.md#flow-b340c3e3-ad5f-401c-839d-60e02a8c7ce2>).

관찰은 Gummble 캡처에서 직접 본 내용, 문서 확인은 현재 공식 도움말·공개 API, 설계 가정은 우리 구현 후보를 뜻한다. 버튼의 존재·성공 안내·실제 서버 결과를 구분한다.

## 2. 플로우 목적과 연결

찾을 수 없는 페이지에 진입한 방문자에게 복구 경로를 제공하는 두 가지 오류 화면을 관찰한다.

- 두 장은 색·문구·배치가 다른 오류 화면이며 순차 클릭 결과라고 단정할 수 없다.
- 정확한 원래 URL·공개 사이트/앱 구분·HTTP 상태 코드는 이미지에 없다.


- 폴더 위치: `bonsai_analysis/flows/404`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 상위 흐름: 없음. Gummble 최상위 분류.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **짙은 녹색 404**이다. 페이지가 존재하지 않는다는 설명과 복구 제안. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **흰 배경 Page Not Found**이다. 페이지가 없거나 이동했다는 안내. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Landing page](<../Landing page/ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

## 6. 공식 도움말과 API 대조

아래 URL과 5절의 문서 규칙은 **R2의 2026-11-20 대조 기록**이다. 공통 상세 대조 문서는 현재 체크아웃에 없다. R3에서 모든 URL을 다시 읽은 것은 아니며, 새로 확인한 자료와 적용 범위는 [이번 공식 자료 검토](<../../FE_REVIEW.md#official-sources>)에 구분했다. 과거 캡처에 현재 규칙을 소급 적용하지 않는다. 실제 계정이나 내부 API는 실행하지 않았다.

- [Bonsai 공식 홈페이지](https://www.hellobonsai.com/): R2 본문 대조 기록(S001). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [공식 지원](https://www.hellobonsai.com/support): R2 본문 대조 기록(S002). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [공개 API](https://docs.hellobonsai.com/api): R2 본문 대조 기록(S003). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

- 단계 01: 공통 오류 레이아웃·복구 링크 후보.
- 단계 02: 오류 페이지 변형과 라우팅 복구 후보.

## 8. 미확인 사항과 검토 질문

**원본에 없는 분기·남은 범위:** 두 화면의 원래 도메인·URL·버전·실제 HTTP 상태를 확인한다. 홈·문제 신고 버튼 목적지와 인증 상태별 복구 경로를 확인한다.

- 두 화면의 원래 도메인·URL·버전·실제 HTTP 상태를 확인한다.
- 홈·문제 신고 버튼 목적지와 인증 상태별 복구 경로를 확인한다.

### 단계별 미확인 사항

- 단계 01: 발생 URL·실제 상태 코드·신고 방식 미확인.
- 단계 02: 같은 사이트의 버전 차이인지 앱/사이트 구분인지 미확인.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **조회**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: 홈 복귀와 신고 버튼의 목적지를 구분하고, 미인증·삭제 자원·잘못된 URL 시나리오의 복구 경로를 정한다.
- [이 흐름의 보완표](<../../FLOW_REVIEW_MATRIX.md#flow-b340c3e3-ad5f-401c-839d-60e02a8c7ce2>)와 [공통 웹 상태·연결 기준](<../../FE_REVIEW.md#fe-acceptance>)을 함께 적용한다. 캡처에 없는 동작은 Bonsai 관찰 사실로 쓰지 않고 목 가정 또는 추가 조사로 표시한다.
