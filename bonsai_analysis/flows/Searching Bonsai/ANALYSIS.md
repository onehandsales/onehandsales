## 2. 플로우 목적과 연결

전역 검색 모달에서 최근 조회 항목을 확인하고 rebranding 검색 결과에서 프로젝트 상세로 이동한다.

- 고객·프로젝트·문서·작업을 함께 찾는 전역 검색.
- 검색 중간 화면의 여러 항목과 최종2개 결과를 구분한다.


- 폴더 위치: `bonsai_analysis/flows/Searching Bonsai`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 상위 흐름: 없음. Gummble 최상위 분류.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **대시보드 — 프로젝트 타임라인과 손익 요약**이다. Dashboard가 선택되어 있으며 모달·오류·성공 토스트는 없다. 여러 플로우가 공유하는 동일한 시작 이미지다. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **검색 뒤 열린 Rebranding Project 상세**이다. 검색 모달이 닫히고 프로젝트 상세가 표시된다. 이 화면에서 작업 목록은 비어 있지만 문서와 활동은 존재한다. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Project detail](<../Project detail/ANALYSIS.md>) · [Invoices](<../Invoices/ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

### R2 재검토에서 보완한 해석

최근 항목과 검색 중 결과, 완료 후 Rebranding Project·Drafted 청구서 5,517.75의 두 결과를 구분했다. 청구서 강조 뒤 프로젝트 화면으로 전환되어 선택 방법은 미확인이다. 프로젝트 Outstanding 0과 검색 결과의 Drafted 금액은 서로 다른 집계 범위일 수 있다. 활동의 제안서 복원 기록은 복원 조작 자체를 보여주지 않는다.

### 업무 규칙과 연결 시 주의점

- [관찰] 빈 검색어에서는 Recently Viewed가 표시된다. 검색어 입력 후 로딩 표시가 있는 중간 상태와 결과 2개가 남은 상태를 구분한다.
- [관찰] 최종 화면의 청구서 제목은 Doe Company Invoice이며, 하위 정보에 검색어와 일치하는 Rebranding Project가 있다. 관련 객체 이름도 검색한다는 해석은 아직 가정이다.
- [관찰] 청구서 행이 강조되어 있지만 후속 화면은 프로젝트 상세다. 행 강조만으로 최종 선택 대상을 확정하지 않는다.
- [관찰] 결과 종류마다 금액·상태·날짜·연결 프로젝트 표시가 다르다.
- [교차 관찰] 마지막 프로젝트 상세에 제안서 수락·보관·복원 활동이 나타난다. 복원 조작 UI는 해당 이미지에도 없다.

## 6. 공식 도움말과 API 대조

아래 URL과 5절의 문서 규칙은 **R2의 2026-11-20 대조 기록**이다. 공통 상세 대조 문서는 현재 체크아웃에 없다. R3에서 모든 URL을 다시 읽은 것은 아니며, 새로 확인한 자료와 적용 범위는 [이번 공식 자료 검토](<../../FE_REVIEW.md#official-sources>)에 구분했다. 과거 캡처에 현재 규칙을 소급 적용하지 않는다. 실제 계정이나 내부 API는 실행하지 않았다.

- [공개 API](https://docs.hellobonsai.com/api): R2 본문 대조 기록(S003). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [탐색·전역 검색](https://help.hellobonsai.com/en/articles/13764408-how-to-navigate-bonsai-and-customize-the-sidebar): R2 본문 대조 기록(S082). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

## 7. 데이터 모델링 시사점

다음은 관찰에 기반한 OneHandSales 구현 후보다. 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- 서로 다른 객체 종류·ID, 표시 제목, 상위 관계와 상태·금액을 갖는 검색 결과 후보.
- 사용자별 최근 조회 이력과 검색 결과의 권한 필터 후보. 검색 색인과 업무 원본 데이터를 구분한다.

### 단계별 모델링 근거

- 단계 01: 프로젝트·문서 참조, 기간·통화별 재무 집계, 빠른 생성 진입점 및 공통 내비게이션 후보. 메뉴 노출은 서버 권한의 증거와 구분한다.
- 단계 02: 객체 종류·ID·표시 제목·연결 객체와 종류별 요약 정보, 사용자별 최근 조회 이력 후보.
- 단계 03: 입력값·로딩·확정 결과 상태의 구분, 기능 이동 항목과 업무 객체 결과의 구분 후보.
- 단계 04: 연결 객체의 요약 정보를 갖는 검색 결과와 객체 종류별 상세 화면 이동 후보.
- 단계 05: 검색 결과의 상세 화면 연결, 프로젝트별 문서 참조, 제안서 업무 상태와 보관 상태 및 개별 활동 이력 후보.

## 8. 미확인 사항과 검토 질문

**원본에 없는 분기·남은 범위:** 관계명·본문·번호의 검색 범위, 정렬, 입력 지연 처리, 페이지네이션, 무결과 상태를 실제 계정에서 확인한다. 삭제·보관·권한 제거된 객체가 최근 조회와 검색 결과에서 어떻게 처리되는지 검증한다.

- 관계명·본문·번호의 검색 범위, 정렬, 입력 지연 처리, 페이지네이션, 무결과 상태를 실제 계정에서 확인한다.
- 삭제·보관·권한 제거된 객체가 최근 조회와 검색 결과에서 어떻게 처리되는지 검증한다.

### 단계별 미확인 사항

- 단계 01: 날짜와 집계의 기준 시간대, 그래프 산식, 타임라인 아이콘의 정확한 날짜 의미, 역할별 접근 권한, 홍보 노출 조건은 이 이미지로 확인할 수 없다.
- 단계 02: 최근 조회의 저장 범위와 최대 수, 행 강조가 마우스 hover인지 키보드 선택인지, 입력 후 검색 실행 시점은 미확인이다.
- 단계 03: 빈 작업 제목이 실제 데이터인지 일시적인 렌더링인지, 중간 결과의 정렬과 검색 일치 조건은 미확인이다.
- 단계 04: 검색 대상 필드·정렬 규칙·권한 필터, 키보드/마우스 선택 방식은 미확인이다. 강조된 청구서가 다음 화면의 이동 대상이라고 단정하지 않는다.
- 단계 05: 검색 결과 선택 방식, 제안서 복원 조작 UI와 권한, 복원 전후 고객 접근·연결 문서 영향은 미확인이다.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **결과**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: 최근 조회·검색 중·완료·무결과와 객체별 링크를 나눈다. 삭제·권한 변경 이후 최근 목록 정리와 키보드 탐색을 정한다.
- [이 흐름의 보완표](<../../FLOW_REVIEW_MATRIX.md#flow-f6466df8-7932-40c1-a10e-f84bfe1070f5>)와 [공통 웹 상태·연결 기준](<../../FE_REVIEW.md#fe-acceptance>)을 함께 적용한다. 캡처에 없는 동작은 Bonsai 관찰 사실로 쓰지 않고 목 가정 또는 추가 조사로 표시한다.
