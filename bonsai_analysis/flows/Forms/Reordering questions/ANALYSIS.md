기존 검토 기록: **R2 누락·내용 재검토 완료(정적 캡처 범위)**. 실제 이미지 재확인 **3/3단계**. 계정 재현은 수행하지 않았다.

추가 검토: **R3 문서·MCP 목록 대조 완료 / FE 보완 항목 있음**. 이번 이미지 확인은 고유 이미지 기준 선택 검토이며 이 흐름에 해당하는 화면은 **0/3단계**다. 기존 R2 전수 시각 검토 이력과 구분한다. [플로우별 FE 보완표](<../../../FLOW_REVIEW_MATRIX.md#flow-68ec72c2-b771-428b-98b7-256018628743>).

관찰은 Gummble 캡처에서 직접 본 내용, 문서 확인은 현재 공식 도움말·공개 API, 설계 가정은 우리 구현 후보를 뜻한다. 버튼의 존재·성공 안내·실제 서버 결과를 구분한다.

## 2. 플로우 목적과 연결

폼의 날짜 질문과 추가 문의 질문 순서를 바꾼다.

- 추가 질문이 이미 있는 편집기 하단에서 시작한다.

- 상위 흐름: [Forms](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Forms/Reordering questions`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **날짜 질문 추가**이다. 짧은 텍스트 다음 날짜 순서가 확인된다. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **질문 순서 변경 결과**이다. 기존 마지막 두 요소가 서로 자리를 바꿨다. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Forms](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

## 5. 업무 규칙과 데이터 변화

| 단계 | 관찰된 상태·값 | 근거의 한계 |
| --- | --- | --- |
| 01 | 짧은 텍스트 다음 날짜 순서가 확인된다. — When are you planning to kickstart the project?; 날짜 placeholder YYYY-MM-DD와 달력 아이콘. 위 질문 유지. | 날짜 제한·시간대·기본 날짜·필수값 및 저장은 미확인. |
| 02 | 질문 내용은 유지되고 이동 도구가 보인다. — 추가 문의 → 프로젝트 시작 날짜 순서. 답변란은 비어 있다. | hover인지 선택인지 정확한 트리거는 미확인. |
| 03 | 기존 마지막 두 요소가 서로 자리를 바꿨다. — 날짜 placeholder YYYY-MM-DD; 텍스트 답변 placeholder 유지. | 저장 완료·공개 폼 반영 시점은 미확인. |

위 표는 화면에서 보이는 상태·값이다. 성공 토스트가 있어도 수신자 접근·영수증·서버 저장을 독립 검증한 것은 아니다.

### R2 재검토에서 보완한 해석

추가 문의 질문과 시작 날짜 질문의 순서가 뒤바뀌며 내용·입력 예시는 유지된다. 이동 도구의 위·아래 화살표가 보이지만 정확한 클릭 이벤트, 저장 완료와 공개 폼 반영은 기록되지 않았다.

### 업무 규칙과 연결 시 주의점

- [관찰] 질문별 위/아래 화살표와 삭제/설정 도구가 있다.
- [관찰] 마지막 두 질문의 순서만 바뀌고 질문 내용/타입은 유지된다.
- [미확인] 드래그 정렬·키보드 조작은 화면에 없다.

## 6. 공식 도움말과 API 대조

아래 URL과 5절의 문서 규칙은 **R2의 2026-11-20 대조 기록**이다. 공통 상세 대조 문서는 현재 체크아웃에 없다. R3에서 모든 URL을 다시 읽은 것은 아니며, 새로 확인한 자료와 적용 범위는 [이번 공식 자료 검토](<../../../FE_REVIEW.md#official-sources>)에 구분했다. 과거 캡처에 현재 규칙을 소급 적용하지 않는다. 실제 계정이나 내부 API는 실행하지 않았다.

- [공개 API](https://docs.hellobonsai.com/api): R2 본문 대조 기록(S003). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [폼·질문·공유·응답 도움말](https://help.hellobonsai.com/en/articles/3831621-create-custom-forms-and-questionnaires): R2 본문 대조 기록(S045). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

## 7. 데이터 모델링 시사점

다음은 관찰에 기반한 OneHandSales 구현 후보다. 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- 질문 식별자와 순서를 분리하고 순서 변경으로 기존 응답 참조가 바뀌지 않게 할 후보.

### 단계별 모델링 근거

- 단계 01: 날짜 전용 답변 타입과 질문 순서 후보.
- 단계 02: 선택/hover UI와 영속 순서값 구분.
- 단계 03: 안정적인 질문 ID+정렬 값 후보.

## 8. 미확인 사항과 검토 질문

**원본에 없는 분기·남은 범위:** 첫/마지막 요소의 이동 제한, 기본 연락처 필드 위치 변경 가능 여부, 동시 편집 충돌을 확인한다. 순서 변경이 공개 폼에 반영되는 시점과 응답 조회 순서 정책을 확인한다.

- 첫/마지막 요소의 이동 제한, 기본 연락처 필드 위치 변경 가능 여부, 동시 편집 충돌을 확인한다.
- 순서 변경이 공개 폼에 반영되는 시점과 응답 조회 순서 정책을 확인한다.

### 단계별 미확인 사항

- 단계 01: 날짜 제한·시간대·기본 날짜·필수값 및 저장은 미확인.
- 단계 02: hover인지 선택인지 정확한 트리거는 미확인.
- 단계 03: 저장 완료·공개 폼 반영 시점은 미확인.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **결과**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: 순서 변경 시 질문 ID와 기존 답변 연결을 유지한다. 첫·마지막 이동 제한·공개 폼 반영·저장 실패를 별도 정의한다.
- [이 흐름의 보완표](<../../../FLOW_REVIEW_MATRIX.md#flow-68ec72c2-b771-428b-98b7-256018628743>)와 [공통 웹 상태·연결 기준](<../../../FE_REVIEW.md#fe-acceptance>)을 함께 적용한다. 캡처에 없는 동작은 Bonsai 관찰 사실로 쓰지 않고 목 가정 또는 추가 조사로 표시한다.
