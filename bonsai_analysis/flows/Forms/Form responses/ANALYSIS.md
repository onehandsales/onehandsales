## 2. 플로우 목적과 연결

폼 응답의 빈 상태와 제출 후 목록을 확인한다.

- 폼 목록→설정 화면→Responses 탭으로 이어진다. 중간 설정 오류 발생 원인과 2건의 응답 생성은 이 상위 흐름에 없다.

- 상위 흐름: [Forms](../ANALYSIS.md)
- 하위 흐름: [Response detail](Response%20detail/ANALYSIS.md), [Giving a response](Giving%20a%20response/ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Forms/Form responses`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **폼 목록**이다. 기존 폼 하나와 응답 0건이 표시된다. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **응답 2건 목록**이다. 최신 시각 행이 위에 있다. 기존 0건에서 생성 과정 없이 2건으로 바뀌었다. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Forms](<../ANALYSIS.md>), [Giving a response](<Giving a response/ANALYSIS.md>), [Response detail](<Response detail/ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.
