- [미확인] 중복 제출 방지·고객 자동 생성/매칭·알림·자동화 실행은 이 흐름에서 확인되지 않는다.

## 6. 공식 도움말과 API 대조

아래 URL과 5절의 문서 규칙은 **R2의 2026-11-20 대조 기록**이다. 공통 상세 대조 문서는 현재 체크아웃에 없다. R3에서 모든 URL을 다시 읽은 것은 아니며, 새로 확인한 자료와 적용 범위는 [이번 공식 자료 검토](<../../../../FE_REVIEW.md#official-sources>)에 구분했다. 과거 캡처에 현재 규칙을 소급 적용하지 않는다. 실제 계정이나 내부 API는 실행하지 않았다.

- [공개 API](https://docs.hellobonsai.com/api): R2 본문 대조 기록(S003). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [폼·질문·공유·응답 도움말](https://help.hellobonsai.com/en/articles/3831621-create-custom-forms-and-questionnaires): R2 본문 대조 기록(S045). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

## 7. 데이터 모델링 시사점

다음은 관찰에 기반한 OneHandSales 구현 후보다. 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- 제출자 정보와 고객 참조, 응답 묶음/제출시각, 질문별 타입·필수 검증 및 다중 선택 답변 후보.
- 숫자 0·빈 값·검증 실패를 구분하고 응답 제출 성공과 마케팅 가입을 분리할 후보.

### 단계별 모델링 근거

- 단계 01: 질문 정의의 필수 여부와 공개 렌더링 후보.
- 단계 02: 제출된 이름/이메일과 기존 고객 정보 구분 후보.
- 단계 03: 선택지 ID/라벨/순서와 다중 답변 후보.
- 단계 04: 다대다 또는 배열 등 표현은 설계 후보이며 아직 확정하지 않는다.
- 단계 05: 질문 필수 여부와 답변 cardinality를 별도 표현할 후보.
- 단계 06: 첨부 답변·숫자 답변·날짜 답변의 선택/필수 구분 후보.
- 단계 07: 빈 값/실제0/숫자 형식을 구분하는 검증 후보.
- 단계 08: 검증 메시지 갱신 상태 후보.
- 단계 09: 응답 완료 상태와 별도 가입 전환을 분리한다.

## 8. 미확인 사항과 검토 질문

**원본에 없는 분기·남은 범위:** 기존 고객 이메일 일치 시 이름 갱신/매칭·새 고객 생성 여부를 확인한다. 이메일·이름·숫자 범위/소수·날짜 검증, 필수 선택 최소 개수와 파일 제한을 확인한다.

- 기존 고객 이메일 일치 시 이름 갱신/매칭·새 고객 생성 여부를 확인한다.
- 이메일·이름·숫자 범위/소수·날짜 검증, 필수 선택 최소 개수와 파일 제한을 확인한다.
- 공개 링크의 반복 제출·봇 방지·만료·권한·성공 메시지 커스터마이징을 확인한다.

### 단계별 미확인 사항

- 단계 01: 필수 옵션 변경 경로·로그인 요구·URL 유효성은 미확인.
- 단계 02: 이메일 검증·동일 이메일 고객 매칭은 미확인.
- 단계 03: 선택 개수 상한·Other 입력 확장 여부는 미확인.
- 단계 04: 미선택 해제 시 저장·다른 선택 영향은 미확인.
- 단계 05: 최소/최대 선택 제약 전체는 미확인.
- 단계 06: 중간 브랜드 재작업 질문 선택 단계는 미수록.
- 단계 07: 0 자체를 금지하는 규칙이라는 증거는 아니다. 서버/클라이언트 검증 위치 미확인.
- 단계 08: blur 또는 재제출 시 해제되는지 미확인.
- 단계 09: 자동 고객 생성/알림/중복/뒤로 가기·재제출은 미확인.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **결과**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: 필수 입력·복수 및 단일 선택·숫자 오류·제출 성공을 재현한다. 응답 목록 연결은 가상 ID로 하고 결제 선택을 실제 결제로 처리하지 않는다.
- [이 흐름의 보완표](<../../../../FLOW_REVIEW_MATRIX.md#flow-b3f0ee03-c692-4960-8ed0-a8e15c1b4def>)와 [공통 웹 상태·연결 기준](<../../../../FE_REVIEW.md#fe-acceptance>)을 함께 적용한다. 캡처에 없는 동작은 Bonsai 관찰 사실로 쓰지 않고 목 가정 또는 추가 조사로 표시한다.


### 동일 재현을 위한 남은 분석 (R4)

- 공개 폼과 편집기 필수 표시·색상·검증 시점을 별도로 명세해야 한다. Amanda Soh 입력과 다른 플로우의 Jane Studio 응답을 동일 고객 변경 과정으로 단정할 수 없다. 캡처 사이에 생략된 검증·전송 동작은 미확인이다.
- 공통 미완: 요소별 누락 검사, 정확한 배치·타이포그래피·색/장식·자산 대응·미노출 상태는 [12개 검토 항목](<../../../../SOURCE_ANALYSIS_STANDARD.md>)으로 추가 명세한다. 원본에 없는 동작은 관찰 사실과 분리한다. 이 문서의 R4 표시를 동일 재현 명세나 FE 구현 완료로 읽지 않는다.
