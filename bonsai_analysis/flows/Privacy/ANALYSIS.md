## 2. 플로우 목적과 연결

- 동의 체크·요청 제출 없이 정적 문서를 읽는 공개 흐름이다.
- 두 이미지 사이 본문이 생략되어 정책 전문을 이미지로 전수 확인한 것은 아니다.


- 폴더 위치: `bonsai_analysis/flows/Privacy`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.

## 5. 업무 규칙과 데이터 변화

- 당시 수집·계정 삭제·정보 요청 설명을 관찰했지만 실제 삭제·내보내기 API를 확인한 것은 아니다.
- 정책에 쓰인 연락처·보관·동의 설명을 새 제품의 정책으로 자동 채택하지 않는다.

## 6. 공식 도움말과 API 대조

- [현재 공식 Privacy Policy](https://www.hellobonsai.com/legal/privacy): 2025-08-05 업데이트 표시, 방문자·계정·채용·통신 데이터 범주와 고객을 대신 처리하는 데이터의 적용 구분을 확인했다. 캡처의 짧은 구형 문서와 동일 버전이 아니다.
- [공개 API](https://docs.hellobonsai.com/api): 조회한 문서는 업무 리소스 중심이며 이 공개 페이지의 콘텐츠·검색·추천·제휴 관리 endpoint와 필드 계약은 확인하지 못했다. 화면 카드를 곧바로 업무 DB 테이블로 확정하지 않는다.

## 7. 데이터 모델링 시사점

- 정책 종류·버전·적용 시점·본문·링크 콘텐츠 후보.
- 정책 동의 이력·개인정보 요청 처리는 구현 후보일 뿐 이 읽기 화면에 저장 증거는 없다.

## 8. 미확인 사항과 검토 질문

- 구형 문서 전체·효력일·언어별 버전은 미확인이다.
- 동의 기록과 데이터 삭제/보관 정책은 제품 요구사항·실제 계약을 별도로 정해야 한다.
