## 2. 플로우 목적과 연결

방문자가 Start a business 분류를 고른 상태에서 marketing 검색으로 글을 좁힌다.

- 상위 Blog의 공개 기사 검색이며 앱 통합 검색과 다르다.
- 결과 클릭·검색어 지우기·결과 없음 상태는 미수록이다.

- 상위 흐름: [Blog](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Blog/Searching blog`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **분류 변경 중 희미한 목록**이다. 임원 코칭·사진 시작·좋은 컨설턴트 글 텍스트가 있으나 로딩/전환처럼 보인다. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **marketing 검색 결과**이다. 결과 카드1개, 페이지1/1. 요약의2018과 현재 캡처시점은 별개. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Blog](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

### R2 재검토에서 보완한 해석

Start a business 선택을 유지한 채 marketing을 입력하면 글 한 건과 1/1 페이지 표시가 보인다. 입력만으로 검색되는지 제출이 필요한지, 전체 본문까지 검색하는지는 확인되지 않는다.

### 업무 규칙과 연결 시 주의점

- 검색 중에도 Start a business 선택이 유지된다.
- 한 결과 관찰은 이 검색어의 당시 결과이며 검색 알고리즘·AND 필터 구현을 확정하지 않는다.
- 첫 화면은 로딩/전환으로 보이지만 명시적 spinner는 없다.

다음은 관찰에 기반한 OneHandSales 구현 후보다. 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- 단계 03: 검색어+분류+페이지 상태·결과 카드 재사용 후보.

## 8. 미확인 사항과 검토 질문

**원본에 없는 분기·남은 범위:** 입력 즉시 검색인지 Enter 제출인지 debounce·URL query·뒤로가기 복원을 확인한다. 분류+검색 결합 범위·부분일치·대소문자·검색어 초기화를 확인한다.

- 입력 즉시 검색인지 Enter 제출인지 debounce·URL query·뒤로가기 복원을 확인한다.
- 분류+검색 결합 범위·부분일치·대소문자·검색어 초기화를 확인한다.

### 단계별 미확인 사항

- 단계 01: 실제 로딩 상태인지 애니메이션인지 미확인.
- 단계 02: 결과 전체 개수·페이징 미확인.
- 단계 03: 제목/본문 검색범위·정렬·네트워크 방식 미확인.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.
