# Converting contract type 플로우 분석

최신 검토: **R4 전체 단계 구성·상태 대조 3/3 · 동일 재현 세부 명세 미완** (2026-11-22 KST). 장당 720×450 비교 시트로 직접 대조했다. 요소별 전수 확대·픽셀 일치 판정은 아니다. [기준](<../../../SOURCE_ANALYSIS_STANDARD.md>) · [결과](<../../../SOURCE_ANALYSIS_REVIEW.md>) · [원본 색인](<../../../SOURCE_ANALYSIS_INDEX.json>).

기존 검토 기록: **R2 누락·내용 재검토 완료(정적 캡처 범위)**. 실제 이미지 재확인 **3/3단계**. 계정 재현은 수행하지 않았다.

추가 검토: **R3 문서·MCP 목록 대조 완료 / FE 보완 항목 있음**. 이번 이미지 확인은 고유 이미지 기준 선택 검토이며 이 흐름에 해당하는 화면은 **0/3단계**다. 기존 R2 전수 시각 검토 이력과 구분한다. [플로우별 FE 보완표](<../../../FLOW_REVIEW_MATRIX.md#flow-3903d09f-3610-46dd-808a-2e1017a411d5>).

관찰은 Gummble 캡처에서 직접 본 내용, 문서 확인은 현재 공식 도움말·공개 API, 설계 가정은 우리 구현 후보를 뜻한다. 버튼의 존재·성공 안내·실제 서버 결과를 구분한다.

## 2. 플로우 목적과 연결

표준 계약을 전체 편집 가능한 문서로 전환한다.

- Drafted/Standardized 계약에서 시작해 Drafted/Fully Editable로 끝난다. 서명은 다음 하위 흐름에서 확인한다.

- 상위 흐름: [Creating a new contract](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Creating a new contract/Converting contract type`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **계약 초안·첫 안내**이다. 입력 부분은 노란 강조. 본문에는 비용 사전 승인 불필요·지원 미제공 등 마법사에서 직접 보지 못한 조항도 있다. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **Fully Editable 전환 완료**이다. Contract has been successfully updated 토스트. 본문 계약 조건은 남아 있다. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Creating a new contract](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

- 버튼·메뉴·안내 문구: Sign Contract, Preview, Automation, …; 기존 Add Custom Clause/Convert 도구는 없어졌다.
- 확인된 상태: Contract has been successfully updated 토스트. 본문 계약 조건은 남아 있다.
- 단계 간 변화: Confirm Change 후 전환 결과를 확인한다. 캡처 사이의 정확한 클릭·요청·저장 순서는 별도 관찰하지 않았다.

#### 동작과 데이터

- 화면 관찰: 편집 타입 변경 성공을 확인했다. 금액 표시 제거가 데이터 삭제 증거는 아니다. 정적 캡처의 UI 상태이며 실제 요청 성공·서버 영속성은 독립 검증하지 않았다.
- 공식 문서 확인: 6절에서 기능별 출처·현재 규칙·과거 화면과의 차이를 대조한다. 이 화면의 내부 API 호출은 관찰하지 않았다.
- 설계 가정: 표시된 업무 개념은 구현 후보이며 저장 방식·권한·트랜잭션을 확정하지 않는다.
- 미확인: 전환 이후 실제 본문 수정과 저장은 미수록.

#### 모델링 영향

- 후보와 근거: 자유 본문·타입·계약 상태의 분리 후보. 위 표시 데이터와 상태를 근거로 검토할 후보이며 확정 스키마가 아니다.
- 확정 전 확인: 전환 이후 실제 본문 수정과 저장은 미수록. 소유 범위·필수값·연결 수·삭제 영향은 화면과 공식 계약을 추가 대조한다.

### R2 재검토에서 보완한 해석

확인 모달은 전체 편집 허용, 구조화 편집 불가, 되돌릴 수 없음을 명시한다. 확인 뒤 Fully Editable과 갱신 토스트가 나타나며 Drafted는 유지된다. 본문 조건은 남지만 Overview의 Amount 행과 구조화 설정이 줄어든다.

### 업무 규칙과 연결 시 주의점

- [관찰] 확인 모달은 전체 문서 편집이 가능해지는 대신 구조화된 편집이 없어지고 되돌릴 수 없다고 안내한다.
- [관찰] 전환 후 노란 강조·Addendum·Contract Type 전환 도구가 사라지고 Type Fully Editable가 된다.
- [미확인] 기존 구조화 값의 내부 삭제 여부는 UI로 알 수 없다.

## 6. 공식 도움말과 API 대조

아래 URL과 5절의 문서 규칙은 **R2의 2026-11-20 대조 기록**이다. 공통 상세 대조 문서는 현재 체크아웃에 없다. R3에서 모든 URL을 다시 읽은 것은 아니며, 새로 확인한 자료와 적용 범위는 [이번 공식 자료 검토](<../../../FE_REVIEW.md#official-sources>)에 구분했다. 과거 캡처에 현재 규칙을 소급 적용하지 않는다. 실제 계정이나 내부 API는 실행하지 않았다.

- [표준·사용자 정의 계약](https://help.hellobonsai.com/en/articles/918802-creating-completely-custom-contracts): R2 본문 대조 기록(S027). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [Documents API](https://docs.hellobonsai.com/api/tag/documents): R2 본문 대조 기록(S029). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

## 8. 미확인 사항과 검토 질문

**원본에 없는 분기·남은 범위:** 전환 후 청구 일정/시급 메타데이터가 유지되는지 확인한다. 일반 텍스트 편집 툴바·변수·서명 블록 제한과 저장 방식, 복제 후 표준형 복구 가능 여부를 확인한다.

- 전환 후 청구 일정/시급 메타데이터가 유지되는지 확인한다.
- 일반 텍스트 편집 툴바·변수·서명 블록 제한과 저장 방식, 복제 후 표준형 복구 가능 여부를 확인한다.

### 단계별 미확인 사항

- 단계 01: 기본 조항 출처, 전체 문서 하단, 실제 저장 요청 및 지급 설정 하단은 미확인.
- 단계 02: 취소 후 상태 및 권한 제약은 미수록.
- 단계 03: 전환 이후 실제 본문 수정과 저장은 미수록.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **결과**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: 전환 확인의 취소·확정을 구분하고 확정 뒤 Fully Editable를 표시한다. 구조화 값 보존·복원은 실제 동작으로 단정하지 않는다.
- [이 흐름의 보완표](<../../../FLOW_REVIEW_MATRIX.md#flow-3903d09f-3610-46dd-808a-2e1017a411d5>)와 [공통 웹 상태·연결 기준](<../../../FE_REVIEW.md#fe-acceptance>)을 함께 적용한다. 캡처에 없는 동작은 Bonsai 관찰 사실로 쓰지 않고 목 가정 또는 추가 조사로 표시한다.


### 동일 재현을 위한 남은 분석 (R4)

- 전환 전후 문서 텍스트와 간격을 각각 대조해야 한다. 상태는 Drafted로 유지되며 편집/서명 완료로 승격하지 않는다. 되돌리기/취소/실패 분기는 미수록이다.
- 공통 미완: 요소별 누락 검사, 정확한 배치·타이포그래피·색/장식·자산 대응·미노출 상태는 [12개 검토 항목](<../../../SOURCE_ANALYSIS_STANDARD.md>)으로 추가 명세한다. 원본에 없는 동작은 관찰 사실과 분리한다. 이 문서의 R4 표시를 동일 재현 명세나 FE 구현 완료로 읽지 않는다.
