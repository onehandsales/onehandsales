## 2. 플로우 목적과 연결

날짜·업무 상태·분류·영수증 조건을 조합하여 비용 목록을 좁히고, 조건을 일부 제거해 결과를 복원한다.

- 시작: 비용 세 건 목록. 종료: 날짜·Non-billable 조건으로 두 건을 표시하는 목록.
- 행위자: 목록 조회 사용자. 조회 범위에 따른 권한은 미확인.
- 프론트 구현: 중첩 달력과 드롭다운, 조건 칩, 개별 해제, 결과 없음, 조건 유지.

- 상위 흐름: [Bookkeeping](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Bookkeeping/Filtering expenses`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **Expenses 등록 목록**이다. 실데이터가 있는 목록. 이전 시작 안내와 달리 세 비용을 표시한다. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **조건 일부 해제 후 결과 복원**이다. 두 행이 다시 표시된다. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Bookkeeping](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

- 관찰: No expenses yet. 문구가 필터 결과 0건에도 쓰인다. 신규 계정 빈 화면과 맥락을 구분한다.
- 설계 가정: Status의 Recurring·Questionable Deduction·청구 상태를 하나의 DB enum으로 단순 복제하지 않는다.
- 미확인: 조건 AND/OR·금액 경계 포함·통화 변환·복수 Category·검색과 필터의 결합.
