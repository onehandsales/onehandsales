## 2. 플로우 목적과 연결

날짜·업무 상태·분류·영수증 조건을 조합하여 비용 목록을 좁히고, 조건을 일부 제거해 결과를 복원한다.

- 시작: 비용 세 건 목록. 종료: 날짜·Non-billable 조건으로 두 건을 표시하는 목록.
- 행위자: 목록 조회 사용자. 조회 범위에 따른 권한은 미확인.
- 프론트 구현: 중첩 달력과 드롭다운, 조건 칩, 개별 해제, 결과 없음, 조건 유지.

- 상위 흐름: [Bookkeeping](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Bookkeeping/Filtering expenses`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **Expenses 등록 목록**이다. 비용 세 행이 표시된 목록. 소개용 그림과 구분되지만 실제 거래·서버 데이터의 진위는 검증하지 않았다. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **조건 일부 해제 후 결과 복원**이다. 두 행이 다시 표시된다. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Bookkeeping](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

### R2 재검토에서 보완한 해석

Jan 7–Feb 6, Non-billable, Advertising, Has Receipt Yes 조건에서 No expenses yet가 표시된다. 분류·영수증 조건 해제 후 Lunch 10·Prints 30이 복원되므로 이 빈 화면을 계정 전체 비용 없음으로 해석하지 않는다. 조건 변경은 패널 뒤 목록에도 반영되지만 요청 타이밍·논리식은 미확인이다.

### 업무 규칙과 연결 시 주의점

- 관찰: 조건 변경 중 배경 목록이 바뀌며 별도 Apply 버튼은 보이지 않는다. 정확한 이벤트·debounce는 미확인.
- 관찰: 기간은 시작·종료 칩으로 나뉜다. 선택 조건은 개별 제거가 가능하다.
- 관찰: No expenses yet. 문구가 필터 결과 0건에도 쓰인다. 신규 계정 빈 화면과 맥락을 구분한다.
- 설계 가정: Status의 Recurring·Questionable Deduction·청구 상태를 하나의 DB enum으로 단순 복제하지 않는다.
- 미확인: 조건 AND/OR·금액 경계 포함·통화 변환·복수 Category·검색과 필터의 결합.

## 6. 공식 도움말과 API 대조

아래 URL과 5절의 문서 규칙은 **R2의 2026-11-20 대조 기록**이다. 공통 상세 대조 문서는 현재 체크아웃에 없다. R3에서 모든 URL을 다시 읽은 것은 아니며, 새로 확인한 자료와 적용 범위는 [이번 공식 자료 검토](<../../../FE_REVIEW.md#official-sources>)에 구분했다. 과거 캡처에 현재 규칙을 소급 적용하지 않는다. 실제 계정이나 내부 API는 실행하지 않았다.

- [공개 API](https://docs.hellobonsai.com/api): R2 본문 대조 기록(S003). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [비용 일괄 편집](https://help.hellobonsai.com/en/articles/1865151-how-to-bulk-edit-your-expenses): R2 본문 대조 기록(S017). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **결과**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: 필터별 칩 제거와 결과 복원을 연결한다. 데이터 0건과 필터 결과 0건을 구분하고 내보내기·일괄 선택 범위를 정한다.

### 동일 재현을 위한 남은 분석 (R4)

- 필터/드롭다운/달력의 겹침 순서·칩 높이·Clear/Close 차이를 명세한다. 미선택 Client/Project/Currency/금액 필드도 구현 대상 요소에서 빠뜨리면 안 된다.
- 공통 미완: 요소별 누락 검사, 정확한 배치·타이포그래피·색/장식·자산 대응·미노출 상태는 [12개 검토 항목](<../../../SOURCE_ANALYSIS_STANDARD.md>)으로 추가 명세한다. 원본에 없는 동작은 관찰 사실과 분리한다. 이 문서의 R4 표시를 동일 재현 명세나 FE 구현 완료로 읽지 않는다.
