최신 검토: **R4 전체 단계 구성·상태 대조 6/6 · 동일 재현 세부 명세 미완** (2026-11-22 KST). 장당 720×450 비교 시트로 직접 대조했다. 요소별 전수 확대·픽셀 일치 판정은 아니다. [기준](<../../../SOURCE_ANALYSIS_STANDARD.md>) · [결과](<../../../SOURCE_ANALYSIS_REVIEW.md>) · [원본 색인](<../../../SOURCE_ANALYSIS_INDEX.json>).

기존 검토 기록: **R2 누락·내용 재검토 완료(정적 캡처 범위)**. 실제 이미지 재확인 **6/6단계**. 계정 재현은 수행하지 않았다.

추가 검토: **R3 문서·MCP 목록 대조 완료 / FE 보완 항목 있음**. 이번 이미지 확인은 고유 이미지 기준 선택 검토이며 이 흐름에 해당하는 화면은 **0/6단계**다. 기존 R2 전수 시각 검토 이력과 구분한다. [플로우별 FE 보완표](<../../../FLOW_REVIEW_MATRIX.md#flow-3a74090f-e360-4fb9-9b79-c1ca197708ba>).

관찰은 Gummble 캡처에서 직접 본 내용, 문서 확인은 현재 공식 도움말·공개 API, 설계 가정은 우리 구현 후보를 뜻한다. 버튼의 존재·성공 안내·실제 서버 결과를 구분한다.

## 2. 플로우 목적과 연결

사용자 비용 분류를 이름과 색상으로 생성하고, 목록의 새 행과 편집·삭제 진입점을 확인한다.

- 시작: Manage Categories 화면. 종료: 생성 성공 토스트와 Other Expenses 그룹의 새 행.
- 행위자: 로그인한 내부 사용자. 계정 역할별 생성 권한은 미확인.
- 비용 자체의 생성·분류 적용은 이 흐름에 없다. 생성한 분류를 선택하는 별도 비용 편집과 연결된다.
- 프론트 구현: 모달 폼, 포커스, 색상 선택 체크, 저장 후 토스트와 스크롤 하단 새 행.

- 상위 흐름: [Bookkeeping](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Bookkeeping/Adding a bookkeeping category`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **비용 카테고리 관리**이다. 기존 분류가 있는 목록. 잠금은 보이지만 수정 제한의 정확한 조건은 미확인. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **생성된 사용자 분류 행**이다. 사용자 분류에 편집·삭제 작업이 보이며 생성 토스트가 남아 있다. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Bookkeeping](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

| 01 | 기존 분류가 있는 목록. 잠금은 보이지만 수정 제한의 정확한 조건은 미확인. — Personal 비용을 장부와 보고서에 포함하는 체크가 선택됨. Advertising, Cost of Labor, Materials & Supplies 등의 분류에 색과 잠금 아이콘. | 잠긴 기본 분류의 수정·삭제 범위, 사용자 분류가 사용 중일 때 삭제 정책. |
| 02 | 입력 전으로 보이는 상태. 회색 문구는 placeholder 가능성이 있어 기본값으로 확정하지 않는다. — 이름 입력의 회색 Design Resources 텍스트. 필수 별표는 보이지 않는다. | 빈 이름·중복 이름 검증, 기본 색상, 닫기·바깥 클릭의 취소 효과. |
| 03 | 이름 입력 상태. — Design Resources가 검은 입력값으로 보인다. 색상 체크는 아직 없다. | 포커스·키보드 저장과 최대 길이·공백 정규화. |
| 04 | 색상 선택 후 저장 전. — 이름 유지, 선택 색상 한 개 표시. | 색상 저장 형식과 임의 색 허용 여부. |
| 05 | Design Resources 생성 성공 문구. — 추가 폼 없음. 기존 분류는 유지된다. | 중복 제출 처리와 생성된 항목으로 자동 스크롤 여부. |
| 06 | 사용자 분류에 편집·삭제 작업이 보이며 생성 토스트가 남아 있다. — 새 분류의 왼쪽 빨간색 선. 기본 항목들은 잠금 아이콘. | 다른 그룹에 추가 가능 여부, 비용이 참조하는 분류 삭제 시 처리. |

위 표는 화면에서 보이는 상태·값이다. 성공 토스트가 있어도 수신자 접근·영수증·서버 저장을 독립 검증한 것은 아니다.

### R2 재검토에서 보완한 해석

빈 입력의 회색 예시와 실제 이름 입력을 구분했다. 생성 토스트 다음 하단 목록에서 새 분류·빨간색 표시·Edit/Delete를 확인한다. 기본 분류의 잠금과 사용자 분류의 삭제 허용 조건은 별도 검증이 필요하다.

### 업무 규칙과 연결 시 주의점

- 관찰: 이름·색상과 명시적 Save Category 버튼이 있다. 폼 변경 즉시 저장으로 해석하지 않는다.
- 관찰: 생성된 분류가 선택한 이름·색상으로 나타난다.
- 문서 확인: 기본 분류의 잠금은 수정·삭제 제한을 뜻하고 사용자 분류는 편집·삭제할 수 있다.
- 미확인: 분류 이름 중복·최대 길이·색상 생략의 기본값·사용 중인 분류 삭제 영향.

## 6. 공식 도움말과 API 대조

아래 URL과 5절의 문서 규칙은 **R2의 2026-11-20 대조 기록**이다. 공통 상세 대조 문서는 현재 체크아웃에 없다. R3에서 모든 URL을 다시 읽은 것은 아니며, 새로 확인한 자료와 적용 범위는 [이번 공식 자료 검토](<../../../FE_REVIEW.md#official-sources>)에 구분했다. 과거 캡처에 현재 규칙을 소급 적용하지 않는다. 실제 계정이나 내부 API는 실행하지 않았다.

- [공개 API](https://docs.hellobonsai.com/api): R2 본문 대조 기록(S003). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [비용 분류 관리](https://help.hellobonsai.com/en/articles/3184359-how-to-add-expense-categories): R2 본문 대조 기록(S013). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

## 7. 데이터 모델링 시사점

다음은 관찰에 기반한 OneHandSales 구현 후보다. 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- 설계 가정: ExpenseCategory의 표시 이름·색상·시스템 제공 여부와 계정 소유 후보.
- 설계 가정: 기본 분류 그룹과 사용자 분류의 소속 관계. 이번 새 행은 Other Expenses에 있지만 모든 생성 규칙으로 일반화하지 않는다.
- 카테고리 삭제 시 비용의 분류를 비우거나 대체하는 정책은 별도 확인한다.

### 단계별 모델링 근거

- 단계 01: 카테고리 그룹·분류·색상·시스템 제공 여부, 개인 비용 집계 포함 설정 후보.
- 단계 02: 분류의 표시 이름과 색상 후보.
- 단계 03: 임시 폼 값과 저장된 분류를 구분할 필요.
- 단계 04: UI 팔레트 선택값 후보. 저장 형식을 먼저 고정하지 않는다.
- 단계 05: 새 분류 생성과 목록 갱신/토스트 상태 후보.
- 단계 06: 시스템 제공 분류와 사용자 분류의 변경 가능성 구분 후보.

## 8. 미확인 사항과 검토 질문

**원본에 없는 분기·남은 범위:** 색상 없이 저장하면 어떤 값이 지정되는가? 빈 폼·기본 선택·재진입 검증. 중복 이름과 공백 입력이 허용되는가? 오류 화면 확인.

- 색상 없이 저장하면 어떤 값이 지정되는가? 빈 폼·기본 선택·재진입 검증.
- 중복 이름과 공백 입력이 허용되는가? 오류 화면 확인.
- 새 분류의 그룹을 선택·이동할 수 있는가? 추가 편집 플로우 확인.
- 참조 중인 분류 삭제는 금지·미분류 전환·대체 중 무엇인가? 계정 재현 필요.

### 단계별 미확인 사항

- 단계 01: 잠긴 기본 분류의 수정·삭제 범위, 사용자 분류가 사용 중일 때 삭제 정책.
- 단계 02: 빈 이름·중복 이름 검증, 기본 색상, 닫기·바깥 클릭의 취소 효과.
- 단계 03: 포커스·키보드 저장과 최대 길이·공백 정규화.
- 단계 04: 색상 저장 형식과 임의 색 허용 여부.
- 단계 05: 중복 제출 처리와 생성된 항목으로 자동 스크롤 여부.
- 단계 06: 다른 그룹에 추가 가능 여부, 비용이 참조하는 분류 삭제 시 처리.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **결과**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: 분류 생성 후 목록과 비용 편집 선택지에 반영한다. 기본 잠금 분류와 사용자 분류를 구분하고 사용 중 삭제 규칙은 별도 확인한다.
- [이 흐름의 보완표](<../../../FLOW_REVIEW_MATRIX.md#flow-3a74090f-e360-4fb9-9b79-c1ca197708ba>)와 [공통 웹 상태·연결 기준](<../../../FE_REVIEW.md#fe-acceptance>)을 함께 적용한다. 캡처에 없는 동작은 Bonsai 관찰 사실로 쓰지 않고 목 가정 또는 추가 조사로 표시한다.


### 동일 재현을 위한 남은 분석 (R4)

- 색상 격자의 모든 색/순서·선택 표시·닫기 노출 차이 및 행 높이를 수치화해야 한다. 새 이름/색 변경·삭제 확인 후 화면은 미수록이다.
- 공통 미완: 요소별 누락 검사, 정확한 배치·타이포그래피·색/장식·자산 대응·미노출 상태는 [12개 검토 항목](<../../../SOURCE_ANALYSIS_STANDARD.md>)으로 추가 명세한다. 원본에 없는 동작은 관찰 사실과 분리한다. 이 문서의 R4 표시를 동일 재현 명세나 FE 구현 완료로 읽지 않는다.
