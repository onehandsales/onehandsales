## 2. 플로우 목적과 연결

공개 eCommerce 견적 템플릿을 열고 설명·미리보기·FAQ를 읽은 뒤 사용 진입점을 확인한다.

- 카드 목록→간소 헤더 상세→본문·고정 이메일 CTA로 이어진다.
- 문서 편집·계정 복제·발송 완료는 없다.

- 상위 흐름: [Filtering all templates](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Filtering all templates/Template detail`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **eCommerce 견적 카드 강조**이다. hover/focus로 보이는 강조. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **FAQ·추가 템플릿**이다. 웹사이트 견적 작성·포함 사항·eCommerce 견적 정의; 하단 No items found 일부가 고정바 위에 보인다. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Filtering all templates](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

- 견적과 청구서·제안서의 실제 앱 문서 유형 대응은 미정이다.

### 단계별 미확인 사항

- 단계 01: 입력 방식·카드 전체 클릭 영역 미확인.
- 단계 02: 버튼의 가입/편집 이동·실제 read receipt 범위 미확인.
- 단계 03: 누적수 집계·본문 전체·템플릿 편집 동작 미확인.
- 단계 04: 작은 미리보기 세부값·실제 문서 타입·평점 출처 미확인.
- 단계 05: 추가 템플릿 빈 상태가 로딩/오류/실제0건인지 미확인.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **공개**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: 상세·목차·CTA를 연결한다. 이메일 Customize와 Get template의 가입 후 이동·입력 보존·앱 템플릿 대응은 추가 조사한다.
- [이 흐름의 보완표](<../../../FLOW_REVIEW_MATRIX.md#flow-4fe6aa73-a216-43cb-87ff-be898ffc869c>)와 [공통 웹 상태·연결 기준](<../../../FE_REVIEW.md#fe-acceptance>)을 함께 적용한다. 캡처에 없는 동작은 Bonsai 관찰 사실로 쓰지 않고 목 가정 또는 추가 조사로 표시한다.


### 동일 재현을 위한 남은 분석 (R4)

- 전체 기사 원문/문서 미리보기·평가 자산·목차/고정 CTA 위치를 명세한다. Get template 이후 가입/복제 결과와 미수록 중간 본문은 별도 근거가 필요하다.
- 공통 미완: 요소별 누락 검사, 정확한 배치·타이포그래피·색/장식·자산 대응·미노출 상태는 [12개 검토 항목](<../../../SOURCE_ANALYSIS_STANDARD.md>)으로 추가 명세한다. 원본에 없는 동작은 관찰 사실과 분리한다. 이 문서의 R4 표시를 동일 재현 명세나 FE 구현 완료로 읽지 않는다.
