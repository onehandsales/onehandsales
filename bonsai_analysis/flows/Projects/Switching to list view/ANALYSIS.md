## 2. 플로우 목적과 연결

프로젝트 보드를 표 형태로 전환하고 프로젝트별 요약 정보·행 메뉴를 조회한다.

- 같은 두 프로젝트의 보드→List View. 표에서는 고객·태그·시작일·금액을 한 줄에 비교한다.
- 마지막은 Consulting Project 행의 액션 메뉴를 확인하는 상태이며 실행 결과는 없다.

- 상위 흐름: [Projects](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Projects/Switching to list view`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **프로젝트 보드 목록**이다. 상태별 카드와 개수. 가로로 더 있는 열은 현재 뷰포트 밖. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **프로젝트 목록 행 메뉴**이다. 행 액션 조회 상태. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Projects](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

| 01 | 상태별 카드와 개수. 가로로 더 있는 열은 현재 뷰포트 밖. — New Lead1개 Design Project with Doe Studio/Doe Company; Proposal Sent0, Contract Signed0, In Progress1개 Consulting Project/Sample Client/Sample태그. | 전체 열 수·가로스크롤 방식·드래그·필터. |
| 02 | 프로젝트2개 표 조회. — Title, Client, Tags, Start Date, Due, Paid. Consulting Project/Sample Client/Sample/Feb7 2024/$0/$0; Design Project with Doe Studio/Doe Company/Feb6/$0/$0. | 색 점 툴팁·금액 산식·통화·페이지네이션. |
| 03 | 행 액션 조회 상태. — 표 값은 유지. | 행별 권한·태그 편집 경로·확인 모달. |

위 표는 화면에서 보이는 상태·값이다. 성공 토스트가 있어도 수신자 접근·영수증·서버 저장을 독립 검증한 것은 아니다.

### R2 재검토에서 보완한 해석

목록에는 Consulting Project와 Design Studio 프로젝트가 나타난다. Due·Paid는 금액 열이고 Start Date는 별도 날짜 열이다. 행 메뉴에는 View Project·Mark Completed·Archive·Delete가 보이며, 보드에서 보인 태그 편집이 이 메뉴에도 있다고 일반화하지 않는다.

### 업무 규칙과 연결 시 주의점

- 관찰: Due는 날짜가 아니라 $0.00 금액 열이다. 작업 기한 또는 프로젝트 종료일로 오인하지 않는다.
- 관찰: Title과 Start Date에 정렬 아이콘이 있다. 현재 정렬 기준·다중 정렬 지원은 미확인.
- 관찰: 목록 메뉴는 View Project/완료/보관/삭제이며 보드 카드의 Tags 메뉴와 구성이 다르다.

## 7. 데이터 모델링 시사점

다음은 관찰에 기반한 OneHandSales 구현 후보다. 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- 동일 프로젝트의 보드/목록 조회 모델. 보기 변경이 새 데이터 객체를 만드는 것은 아니다.
- 청구 잔액 Due와 Paid 집계는 프로젝트의 시작일·종료일과 분리한다. 구체 집계 정의는 인보이스와 대조한다.
- 사용자별 뷰·정렬·열 구성 저장 후보; 현재 화면만으로 저장 범위는 미확정.

### 단계별 모델링 근거

- 단계 01: 프로젝트 상태/보드 그룹과 고객·태그 투영 후보.
- 단계 02: 목록 요약 필드와 청구 집계 투영.
- 단계 03: 행 컨텍스트에 따른 액션 메뉴 후보.
