## 2. 플로우 목적과 연결

프로젝트 카드를 드래그하여 다른 진행 단계로 옮기는 흐름이다.

- 이름은 Reordering projects지만 실제 이미지에서는 In Progress에서 Contract Signed로 열이 변경된다.
- Sample 태그와 고객은 유지되고 단계별 개수도 이동에 맞게 바뀐다.
- 같은 열 안의 순서 변경은 이3개 캡처에서 확인할 수 없다.

- 상위 흐름: [Projects](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Projects/Reordering projects`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **프로젝트 카드의 태그 표시**이다. 카드 요약에 태그가 반영됨. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **다른 진행 단계로 이동 완료**이다. 새 열 배치와 개수 반영. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Projects](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

- 확정 전 확인: 영속 저장·실제 계약 상태와의 연결·활동 이력. 소유 범위·필수값·연결 수·삭제 영향은 화면과 공식 계약을 추가 대조한다.

## 5. 업무 규칙과 데이터 변화

| 단계 | 관찰된 상태·값 | 근거의 한계 |
| --- | --- | --- |
| 01 | 카드 요약에 태그가 반영됨. — 제목·고객·상태 유지. 태그 추가로 카드 높이 증가. | 태그 필터·색상 공유·렌더링 줄바꿈. |
| 02 | 드래그 중으로 해석되는 위치 이동 캡처. — 기존 In Progress1, Contract Signed0. Sample태그 유지. | 실제 포인터/드래그 핸들·자동 스크롤·드롭 가능 영역. |
| 03 | 새 열 배치와 개수 반영. — Contract Signed1, In Progress0. 고객·태그 유지. | 영속 저장·실제 계약 상태와의 연결·활동 이력. |

위 표는 화면에서 보이는 상태·값이다. 성공 토스트가 있어도 수신자 접근·영수증·서버 저장을 독립 검증한 것은 아니다.

### R2 재검토에서 보완한 해석

Consulting Project 카드가 In Progress에서 Contract Signed로 이동하며 두 열의 건수가 1→0, 0→1로 바뀐다. 이 기록은 같은 열 안의 순번 조정뿐 아니라 단계 변경을 보여준다. Sample 태그가 유지되며 실제 계약 서명을 완료했다는 증거는 없다.

### 업무 규칙과 연결 시 주의점

- 관찰: 이동 전 In Progress1/Contract Signed0 → 이동 후0/1.
- 관찰: 카드 제목·고객·Sample태그는 유지된다.
- 미확인: Contract Signed로 이동했다고 실제 계약 서명이 발생한 것은 아니다. 프로젝트 단계와 문서 서명을 분리한다.

## 6. 공식 도움말과 API 대조

아래 URL과 5절의 문서 규칙은 **R2의 2026-11-20 대조 기록**이다. 공통 상세 대조 문서는 현재 체크아웃에 없다. R3에서 모든 URL을 다시 읽은 것은 아니며, 새로 확인한 자료와 적용 범위는 [이번 공식 자료 검토](<../../../FE_REVIEW.md#official-sources>)에 구분했다. 과거 캡처에 현재 규칙을 소급 적용하지 않는다. 실제 계정이나 내부 API는 실행하지 않았다.

- [Project settings](https://help.hellobonsai.com/en/articles/1284945-editing-your-project-s-settings): R2 본문 대조 기록(S022). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [Board Groups API](https://docs.hellobonsai.com/api/tag/board-groups): R2 본문 대조 기록(S078). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

## 7. 데이터 모델링 시사점

다음은 관찰에 기반한 OneHandSales 구현 후보다. 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- 프로젝트의 단계 참조 변경과 열 내부 정렬을 별도 후보로 본다.
- 드래그 시작·이동·드롭·저장중·실패복원의 FE 상태 후보. 이 캡처에서는 성공으로 보이는 배치 결과만 관찰했다.

### 단계별 모델링 근거

- 단계 01: 프로젝트 요약의 태그 배열 후보.
- 단계 02: 임시 드래그 위치와 저장된 단계 분리.
- 단계 03: 프로젝트 단계 변경과 열별 개수 갱신 후보.

- 다른 열 이동은 어떤 API 필드를 바꾸는가? board_group ID와 정렬값을 확인한다.
- 드롭 저장 실패 시 원위치로 복원되는가? 네트워크 실패 상태를 재현한다.
- 같은 열의 여러 카드를 재정렬하고 새로고침해 순서 저장 범위를 확인한다.

### 단계별 미확인 사항

- 단계 01: 태그 필터·색상 공유·렌더링 줄바꿈.
- 단계 02: 실제 포인터/드래그 핸들·자동 스크롤·드롭 가능 영역.
- 단계 03: 영속 저장·실제 계약 상태와의 연결·활동 이력.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **결과**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: 열 이동 후 카드 상태와 양쪽 건수를 함께 변경한다. 실제 계약 서명과 분리하고 동일 열 정렬·실패 복구·키보드 대안을 보완한다.
- [이 흐름의 보완표](<../../../FLOW_REVIEW_MATRIX.md#flow-c5e982aa-007d-4e20-8c8b-1fe3c276acc8>)와 [공통 웹 상태·연결 기준](<../../../FE_REVIEW.md#fe-acceptance>)을 함께 적용한다. 캡처에 없는 동작은 Bonsai 관찰 사실로 쓰지 않고 목 가정 또는 추가 조사로 표시한다.
