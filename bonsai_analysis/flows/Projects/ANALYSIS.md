## 2. 플로우 목적과 연결

프로젝트를 진행 단계별 보드에서 조회하고 가로 스크롤로 전체 단계를 확인하는 흐름이다.

- Dashboard에서 Projects로 이동한다. 처음엔 New Lead에 프로젝트1개가 보인다.
- 보드는 뷰포트보다 넓으며 오른쪽으로 이동하면 In Review까지 보인다.
- 하위 흐름은 생성·태그·드래그 이동·목록 보기다.

- 하위 흐름: [Adding a tag](Adding%20a%20tag/ANALYSIS.md), [Reordering projects](Reordering%20projects/ANALYSIS.md), [Switching to list view](Switching%20to%20list%20view/ANALYSIS.md), [Creating a project (Projects)](Creating%20a%20project%20%28Projects%29/ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Projects`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 상위 흐름: 없음. Gummble 최상위 분류.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **대시보드 — 프로젝트 타임라인과 손익 요약**이다. Dashboard가 선택되어 있으며 모달·오류·성공 토스트는 없다. 여러 플로우가 공유하는 동일한 시작 이미지다. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **보드 우측 단계 조회**이다. 오른쪽 열의 빈 상태. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Adding a tag](<Adding a tag/ANALYSIS.md>), [Creating a project (Projects)](<Creating a project (Projects)/ANALYSIS.md>), [Reordering projects](<Reordering projects/ANALYSIS.md>), [Tasks](<../Tasks/ANALYSIS.md>), [Time Tracking](<../Time Tracking/ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.
