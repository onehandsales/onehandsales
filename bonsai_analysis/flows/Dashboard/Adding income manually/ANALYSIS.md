최신 검토: **R4 전체 단계 구성·상태 대조 11/11 · 동일 재현 세부 명세 미완** (2026-11-22 KST). 장당 720×450 비교 시트로 직접 대조했다. 요소별 전수 확대·픽셀 일치 판정은 아니다. [기준](<../../../SOURCE_ANALYSIS_STANDARD.md>) · [결과](<../../../SOURCE_ANALYSIS_REVIEW.md>) · [원본 색인](<../../../SOURCE_ANALYSIS_INDEX.json>).

기존 검토 기록: **R2 누락·내용 재검토 완료(정적 캡처 범위)**. 실제 이미지 재확인 **11/11단계**. 계정 재현은 수행하지 않았다.

추가 검토: **R3 문서·MCP 목록 대조 완료 / FE 보완 항목 있음**. 이번 이미지 확인은 고유 이미지 기준 선택 검토이며 이 흐름에 해당하는 화면은 **0/11단계**다. 기존 R2 전수 시각 검토 이력과 구분한다. [플로우별 FE 보완표](<../../../FLOW_REVIEW_MATRIX.md#flow-5b74c74e-20d1-4811-8d96-864144e38a65>).

관찰은 Gummble 캡처에서 직접 본 내용, 문서 확인은 현재 공식 도움말·공개 API, 설계 가정은 우리 구현 후보를 뜻한다. 버튼의 존재·성공 안내·실제 서버 결과를 구분한다.

## 2. 플로우 목적과 연결

대시보드 온보딩에서 장부로 이동해 외부 수입100USD를 수기로 기록한다.

- 화면 날짜가Feb1→Feb2→Feb6으로 바뀌므로 연속 단일 세션으로 간주하지 않는다.
- 외부 플랫폼의 지급 사실을 수기로 기록하는 흐름이며 실제 송금이나 인보이스 결제를 실행하지 않는다.

- 상위 흐름: [Dashboard](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Dashboard/Adding income manually`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **대시보드 폼 온보딩**이다. 수입 생성 시작 전에 폼 설정 안내를 보고 있다. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **대시보드 복귀**이다. 수입 목록에서 대시보드로 이동했다. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Dashboard](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

### 업무 규칙과 연결 시 주의점

- [관찰] PreTax 선택에서 저장되어100USD/Feb1/Pre-Tax 행이 생긴다.
- [관찰] 안내의1099/W9는 제품의 미국 맥락 설명이다. 우리 제품의 세법 제약으로 확정하지 않는다.
- [미확인] 마지막 그래프의 과거 변동을 이 수입 한 건으로 설명할 수 없다.

## 6. 공식 도움말과 API 대조

아래 URL과 5절의 문서 규칙은 **R2의 2026-11-20 대조 기록**이다. 공통 상세 대조 문서는 현재 체크아웃에 없다. R3에서 모든 URL을 다시 읽은 것은 아니며, 새로 확인한 자료와 적용 범위는 [이번 공식 자료 검토](<../../../FE_REVIEW.md#official-sources>)에 구분했다. 과거 캡처에 현재 규칙을 소급 적용하지 않는다. 실제 계정이나 내부 API는 실행하지 않았다.

- [공개 API](https://docs.hellobonsai.com/api): R2 본문 대조 기록(S003). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [수입·결제 범주](https://help.hellobonsai.com/en/articles/1202116-understanding-payment-categories-outstanding-overdue-pending-and-paid): R2 본문 대조 기록(S041). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

- 단계 01: 다음 단계의 완료 표시는 폼생성 생략 구간을 포함한다.

- 단계 10: 실제입금/외부플랫폼 검증은 수행하지 않는다.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **결과**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: 수기 수입을 생성해 목록에 반영하고 외부 지급 성공과 구분한다. 세전·세후 및 인보이스 입금 중복 집계는 별도 규칙이다.
- [이 흐름의 보완표](<../../../FLOW_REVIEW_MATRIX.md#flow-5b74c74e-20d1-4811-8d96-864144e38a65>)와 [공통 웹 상태·연결 기준](<../../../FE_REVIEW.md#fe-acceptance>)을 함께 적용한다. 캡처에 없는 동작은 Bonsai 관찰 사실로 쓰지 않고 목 가정 또는 추가 조사로 표시한다.


### 동일 재현을 위한 남은 분석 (R4)

- 계약 만료 달력의 월요일 시작과 수입 달력의 일요일 시작을 무조건 통일하지 않는다. 달력별 변형·empty 배경·세금 설명 원문을 명세한다.
- 공통 미완: 요소별 누락 검사, 정확한 배치·타이포그래피·색/장식·자산 대응·미노출 상태는 [12개 검토 항목](<../../../SOURCE_ANALYSIS_STANDARD.md>)으로 추가 명세한다. 원본에 없는 동작은 관찰 사실과 분리한다. 이 문서의 R4 표시를 동일 재현 명세나 FE 구현 완료로 읽지 않는다.
