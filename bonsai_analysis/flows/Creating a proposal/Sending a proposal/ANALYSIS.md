## 2. 플로우 목적과 연결

메일 내용과 제안서 유효기간을 확인해 고객에게 제안서를 발송한다.

- 스타일 편집을 마친 Drafted 제안서에서 시작한다.
- 이메일 방식으로 발송하며 URL 방식은 버튼만 보인다.
- 결과는 Sent이고 고객 수신/열람/수락은 확인하지 않았다.

- 상위 흐름: [Creating a proposal](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Creating a proposal/Sending a proposal`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **제목·텍스트색 저장 표시**이다. 스타일변경완료표시. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **Sent 제안서 상세**이다. 발송후읽기상태. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Creating a proposal](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

### 업무 규칙과 연결 시 주의점

- [관찰] 발송 시 선택한7일이 기존Feb22를Feb15로 바꾼다. Sent날짜Feb8과 일치하는 기간이다.

- [문서] 이메일과URL공유를구분하며공개API는 문서 생성 초안만 제공한다고 설명한다.
