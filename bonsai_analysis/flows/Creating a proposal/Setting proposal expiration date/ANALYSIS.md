## 2. 플로우 목적과 연결

제안서의 승인 가능 기한을 달력으로 지정한다.

- Drafted·만료 미설정 제안서에서 시작한다.
- Feb22 2024를 지정하고 업데이트 성공까지 확인한다. 실제 만료 시간 경과는 재현하지 않았다.

- 상위 흐름: [Creating a proposal](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Creating a proposal/Setting proposal expiration date`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **제안서 초안 편집기**이다. 초안 생성 및 저장 표시. Sent/Accepted 날짜 빈칸. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **만료일 업데이트 성공**이다. 설정성공. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Creating a proposal](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

- 만료일의 어느 시각/시간대를 기준으로 승인 차단하는가? 경계 시각을 재현해야 한다.
- 만료 연장·해제·재발송이 기존 링크와 알림 예약에 어떻게 반영되는지 확인한다.

### 단계별 미확인 사항

- 단계 01: 금액 산출 항목·템플릿 치환·자동저장 주기 미확인.
- 단계 02: 계정알림설정과의 우선순위·취소동작 미확인.
- 단계 03: 오늘/hover/선택 표시 의미는 정적 이미지로 완전 구분 불가. 과거날짜제한 미확인.
- 단계 04: 지우기후저장·검증오류 미수록.
- 단계 05: 만료 설정 과정은 다른 흐름,현재 이미지로 재구성하지 않음.
- 단계 06: 실제만료전이·알림배달은확인안함.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.
