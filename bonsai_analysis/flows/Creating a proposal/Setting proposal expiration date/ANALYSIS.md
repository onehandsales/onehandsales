- 폴더 위치: `bonsai_analysis/flows/Creating a proposal/Setting proposal expiration date`

- 진입: 첫 캡처는 **제안서 초안 편집기**이다. 초안 생성 및 저장 표시. Sent/Accepted 날짜 빈칸. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.

No Expiration Date에서 Feb 22, 2024를 선택·확정하고 Overview 날짜와 갱신 토스트를 확인한다. 모달은 만료 전날 고객 알림·만료 후 작성자 알림을 안내하지만 실제 발송·만료 상태 전이는 수록되지 않았다.

### 업무 규칙과 연결 시 주의점

- [관찰] 만료 하루 전 고객 알림과 만료 후 사용자 통지를 설명한다. 실제 발송은 확인하지 않았다.
- [문서] 만료 이후 고객은 Accept/Reject를 할 수 없고 재발송이 필요하다고 설명한다.
- [관찰] 날짜 지우기 X가 있으나 만료 해제 동작은 미수록.

## 6. 공식 도움말과 API 대조

아래 URL과 5절의 문서 규칙은 **R2의 2026-11-20 대조 기록**이다. 공통 상세 대조 문서는 현재 체크아웃에 없다. R3에서 모든 URL을 다시 읽은 것은 아니며, 새로 확인한 자료와 적용 범위는 [이번 공식 자료 검토](<../../../FE_REVIEW.md#official-sources>)에 구분했다. 과거 캡처에 현재 규칙을 소급 적용하지 않는다. 실제 계정이나 내부 API는 실행하지 않았다.

- [Documents API](https://docs.hellobonsai.com/api/tag/documents): R2 본문 대조 기록(S029). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [제안서 도움말](https://help.hellobonsai.com/en/articles/5616844-all-about-proposals): R2 본문 대조 기록(S031). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [제안서 만료 도움말](https://help.hellobonsai.com/en/articles/5258968-how-to-set-up-an-expiry-valid-till-date-on-proposals): R2 본문 대조 기록(S038). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

## 7. 데이터 모델링 시사점

다음은 관찰에 기반한 OneHandSales 구현 후보다. 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- 문서 만료일·상태 전이·만료 전후 알림 후보. 캘린더 날짜와 실제 만료 timestamp의 변환 규칙 필요.
- 발송 시 상대 기간 선택이 기존 절대날짜를 변경하는 별도 경로와 연결한다.

### 단계별 모델링 근거

- 단계 01: 제안서 콘텐츠·수신자·스타일·요금 구조·상태 후보.
- 단계 02: 만료설정과알림예약 후보.
- 단계 03: 날짜선택상태 후보.
- 단계 04: nullable만료 날짜와 확정 전 편집 후보.
- 단계 05: 문서 내용·만료·표현 설정 분리 후보.
- 단계 06: 만료 설정 저장과 미래 상태 전이 분리 후보.

## 8. 미확인 사항과 검토 질문

**원본에 없는 분기·남은 범위:** 만료일의 어느 시각/시간대를 기준으로 승인 차단하는가? 경계 시각을 재현해야 한다. 만료 연장·해제·재발송이 기존 링크와 알림 예약에 어떻게 반영되는지 확인한다.

- 만료일의 어느 시각/시간대를 기준으로 승인 차단하는가? 경계 시각을 재현해야 한다.
- 만료 연장·해제·재발송이 기존 링크와 알림 예약에 어떻게 반영되는지 확인한다.

### 단계별 미확인 사항

- 단계 01: 금액 산출 항목·템플릿 치환·자동저장 주기 미확인.
- 단계 02: 계정알림설정과의 우선순위·취소동작 미확인.
- 단계 03: 오늘/hover/선택 표시 의미는 정적 이미지로 완전 구분 불가. 과거날짜제한 미확인.
- 단계 04: 지우기후저장·검증오류 미수록.
- 단계 05: 만료 설정 과정은 다른 흐름,현재 이미지로 재구성하지 않음.
- 단계 06: 실제만료전이·알림배달은확인안함.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **결과**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: 만료일 편집·지우기·확정·취소를 정의한다. 문서 수락 만료와 공유 링크 만료의 규칙을 같은 값으로 처리하지 않는다.
- [이 흐름의 보완표](<../../../FLOW_REVIEW_MATRIX.md#flow-b597e800-c771-4e17-8ddb-1167f2a61deb>)와 [공통 웹 상태·연결 기준](<../../../FE_REVIEW.md#fe-acceptance>)을 함께 적용한다. 캡처에 없는 동작은 Bonsai 관찰 사실로 쓰지 않고 목 가정 또는 추가 조사로 표시한다.


### 동일 재현을 위한 남은 분석 (R4)

- 날짜 입력·달력의 월요일 시작/선택/현재일 표식·겹침을 명세한다. 만료 해제와 과거 날짜·통지 실제 실행은 미수록이다.
- 공통 미완: 요소별 누락 검사, 정확한 배치·타이포그래피·색/장식·자산 대응·미노출 상태는 [12개 검토 항목](<../../../SOURCE_ANALYSIS_STANDARD.md>)으로 추가 명세한다. 원본에 없는 동작은 관찰 사실과 분리한다. 이 문서의 R4 표시를 동일 재현 명세나 FE 구현 완료로 읽지 않는다.
