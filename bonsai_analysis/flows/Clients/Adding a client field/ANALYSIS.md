# Adding a client field 플로우 분석

최신 검토: **R4 전체 단계 구성·상태 대조 4/4 · 동일 재현 세부 명세 미완** (2026-11-22 KST). 장당 720×450 비교 시트로 직접 대조했다. 요소별 전수 확대·픽셀 일치 판정은 아니다. [기준](<../../../SOURCE_ANALYSIS_STANDARD.md>) · [결과](<../../../SOURCE_ANALYSIS_REVIEW.md>) · [원본 색인](<../../../SOURCE_ANALYSIS_INDEX.json>).

기존 검토 기록: **R2 누락·내용 재검토 완료(정적 캡처 범위)**. 실제 이미지 재확인 **4/4단계**. 계정 재현은 수행하지 않았다.

추가 검토: **R3 문서·MCP 목록 대조 완료 / FE 보완 항목 있음**. 이번 이미지 확인은 고유 이미지 기준 선택 검토이며 이 흐름에 해당하는 화면은 **0/4단계**다. 기존 R2 전수 시각 검토 이력과 구분한다. [플로우별 FE 보완표](<../../../FLOW_REVIEW_MATRIX.md#flow-87c1f8ab-d786-4b2c-9861-d75e5813e639>).

관찰은 Gummble 캡처에서 직접 본 내용, 문서 확인은 현재 공식 도움말·공개 API, 설계 가정은 우리 구현 후보를 뜻한다. 버튼의 존재·성공 안내·실제 서버 결과를 구분한다.

## 2. 플로우 목적과 연결

모든 고객 상세에서 사용할 추가 정보 필드의 이름을 관리 화면에서 정의한다.

- Clients > Settings의 Client Fields에서 시작한다.
- Email이라는 이름의 새 필드를 추가한다. 특정 고객 이메일 값을 입력하는 흐름은 아니다.

- 상위 흐름: [Clients](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Clients/Adding a client field`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **고객 태그와 필드 설정**이다. 정의 목록과 사용 개수를 조회. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **고객 필드 추가 완료**이다. 편집 종료 상태. Email 필드가 표에 남는다. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Clients](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.
