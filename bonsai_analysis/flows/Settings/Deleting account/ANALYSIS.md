## 2. 플로우 목적과 연결

개인 설정 하단에서 계정 삭제 안내와 비밀번호 확인을 거쳐 로그인 페이지로 나가는 캡처다. 서버의 완전 삭제 결과는 이미지로 검증할 수 없다.

- Profile Settings에서 시작. 삭제 실행을 실제 계정에서 수행하지 않았다.
- 현재 공식 문서는 비활성화와 지원팀을 통한 영구 삭제를 구분하므로 과거 UI 문구와 동일 정책으로 취급하지 않는다.

- 상위 흐름: [Settings](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Settings/Deleting account`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **Profile Settings**이다. Profile Settings 선택. 개인 사진은 이니셜 상태. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **로그인 — 빈 인증 폼**이다. 로그인 입력 전 화면이다. 계정 삭제 완료나 비밀번호 재설정 완료 안내는 없다. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Settings](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

- [계정 비활성화·삭제](https://help.hellobonsai.com/en/articles/1021483-how-to-deactivate-or-delete-your-bonsai-account): R2 본문 대조 기록(S084). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

## 7. 데이터 모델링 시사점

다음은 관찰에 기반한 OneHandSales 구현 후보다. 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- 계정 비활성 상태·세션 종료·삭제 요청과 문서 수신자 접근권을 분리하는 후보.
- 서명·지급 완료 문서의 보존 경계는 사용자 계정 삭제 cascade로 확정하지 않는다.

### 단계별 모델링 근거

- 단계 01: 개인 프로필과 인증정보 분리 후보.
- 단계 02: 고위험 계정 작업 별도 경로 후보.
- 단계 03: 삭제 요청과 문서 보존 예외 후보.
- 단계 04: 민감 작업 재인증 후보; 비밀번호 원문 저장 가정 없음.
- 단계 05: 인증 제공자, 자격 증명 입력과 검증 오류, 비밀번호 재설정·메일 확인 경로 후보. 화면 이동과 계정의 삭제 상태는 별도로 판단한다.

## 8. 미확인 사항과 검토 질문

**원본에 없는 분기·남은 범위:** 현재 정책을 기준으로 복제할지 캡처 UI를 기준으로 할지 구현 전에 결정할 것. 삭제 후 수신자 문서 링크, 다른 멤버, 결제 이력 보존 여부는 지원 문서와 테스트 계정으로 확인할 것.

- 현재 정책을 기준으로 복제할지 캡처 UI를 기준으로 할지 구현 전에 결정할 것.
- 삭제 후 수신자 문서 링크, 다른 멤버, 결제 이력 보존 여부는 지원 문서와 테스트 계정으로 확인할 것.

### 단계별 미확인 사항

- 단계 01: 필수 필드 검증·이메일 변경 재인증·사진 저장 시점 미확인.
- 단계 02: 삭제 권한·유료 구독 경고 미확인.
- 단계 03: 실제 보관 객체·삭제 지연·복구 여부 미확인.
- 단계 04: 비밀번호 재인증 성공 여부·2FA 필요 여부 미확인.
- 단계 05: 이 화면으로 이동하기 전의 서버 처리, 인증 세션 종료 사유, 계정 존재·삭제 상태는 이미지로 확인할 수 없다.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **부분**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: 비밀번호 확인과 로그인 복귀를 구분한다. 삭제 완료·비활성화·수신자 문서 보존은 현재 도움말과 별도 대조할 정책이다.
- [이 흐름의 보완표](<../../../FLOW_REVIEW_MATRIX.md#flow-3d51760e-2893-42a1-ada6-a2c44849a54d>)와 [공통 웹 상태·연결 기준](<../../../FE_REVIEW.md#fe-acceptance>)을 함께 적용한다. 캡처에 없는 동작은 Bonsai 관찰 사실로 쓰지 않고 목 가정 또는 추가 조사로 표시한다.


### 동일 재현을 위한 남은 분석 (R4)

- 최종 화면만으로 서버 데이터 삭제 범위·완료 여부까지 검증된 것은 아니다. 비밀번호 오류·취소·장기 보존 규칙과 모달 치수는 미확인이다.
- 공통 미완: 요소별 누락 검사, 정확한 배치·타이포그래피·색/장식·자산 대응·미노출 상태는 [12개 검토 항목](<../../../SOURCE_ANALYSIS_STANDARD.md>)으로 추가 명세한다. 원본에 없는 동작은 관찰 사실과 분리한다. 이 문서의 R4 표시를 동일 재현 명세나 FE 구현 완료로 읽지 않는다.
