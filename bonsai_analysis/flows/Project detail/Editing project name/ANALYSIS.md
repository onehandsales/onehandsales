## 2. 플로우 목적과 연결

프로젝트 상세 헤더에서 이름을 직접 편집하고 저장하는 흐름이다.

- 연필 아이콘으로 제목을 입력 모드로 바꾸는 맥락이다. Settings의 Project Title과 같은 업무 정보로 추정하되 내부 저장 호출은 미확인.
- 시작 Design Project with Doe → 종료 Design Project with Doe Studio와 성공 토스트.
- 작업 개수와 활동 이력도 단계1→2에서 달라지므로 이름 편집의 효과로 해석하지 않는다.

- 상위 흐름: [Project detail](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Project detail/Editing project name`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **프로젝트 상세의 빈 개요**이다. 프로젝트 생성 활동1개와 빈 업무 영역. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **프로젝트 이름 변경 성공**이다. 변경 결과와 성공 안내. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Project detail](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.
