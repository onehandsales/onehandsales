## 2. 플로우 목적과 연결

프로젝트의 진행 단계를 선택하고 별도의 완료·보관·삭제 메뉴를 확인하는 흐름이다.

- 시작 New Lead 개요 → 상태 선택 → Proposal Sent 표시 → 추가 액션 메뉴.
- 마지막 캡처는 다시 New Lead이며 되돌린 동작이 수록되지 않았다. 상태 변경 실패로 단정하지 않는다.
- 프로젝트 진행 단계와 완료/아카이브 액션은 UI 위치와 의미가 다르다.

- 상위 흐름: [Project detail](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Project detail/Updating project status`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **프로젝트 상세의 빈 개요**이다. 프로젝트 생성 활동1개와 빈 업무 영역. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **프로젝트 추가 액션 메뉴**이다. 추가 액션을 열어 본 상태. 실행 결과는 없음. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Project detail](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

### 동일 재현을 위한 남은 분석 (R4)

- 프로젝트 상태 변경 저장 피드백과 완료/보관/삭제 결과는 미확인이다. 상태별 점·배경색과 메뉴 너비, 고객/협업자 미리보기의 차이를 추가 근거로 연결해야 한다.
- 공통 미완: 요소별 누락 검사, 정확한 배치·타이포그래피·색/장식·자산 대응·미노출 상태는 [12개 검토 항목](<../../../SOURCE_ANALYSIS_STANDARD.md>)으로 추가 명세한다. 원본에 없는 동작은 관찰 사실과 분리한다. 이 문서의 R4 표시를 동일 재현 명세나 FE 구현 완료로 읽지 않는다.
