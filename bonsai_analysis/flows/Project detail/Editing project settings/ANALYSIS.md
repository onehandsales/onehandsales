## 2. 플로우 목적과 연결

프로젝트 설정에서 종료일을 지정하고 명시적인 저장 후 개요로 돌아가는 흐름이다.

- 시작 설정 상단, 본문 아래로 이동하여 Save Changes까지 확인한다.
- 이름은 첫 캡처 Design Project with Doe에서 후속 Studio 포함 이름으로 달라져 있다. 별도 이름 변경 흐름과 교차한다.
- 종료 Overview의 성공 토스트. 종료일 값 자체는 종료 화면에 보이지 않으므로 재진입 검증이 남는다.

- 상위 흐름: [Project detail](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Project detail/Editing project settings`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **프로젝트 설정 상단**이다. 기한일 없는 설정, 설명 선택항목. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **프로젝트 설정 저장 결과**이다. 프로젝트 업데이트 성공. 저장한 종료일 자체는 현재 뷰에 없음. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Project detail](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

- 달력 열림·시작/종료일 순서 검증·날짜 삭제·리마인더 설정 효과는 미확인이다. 설정 카드/설명 입력/외부 리마인더 영역의 치수를 명세해야 한다.
- 공통 미완: 요소별 누락 검사, 정확한 배치·타이포그래피·색/장식·자산 대응·미노출 상태는 [12개 검토 항목](<../../../SOURCE_ANALYSIS_STANDARD.md>)으로 추가 명세한다. 원본에 없는 동작은 관찰 사실과 분리한다. 이 문서의 R4 표시를 동일 재현 명세나 FE 구현 완료로 읽지 않는다.
