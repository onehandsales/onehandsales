## 2. 플로우 목적과 연결

작업 문맥에서 이미 수행한 시간을 수동으로 입력하여 시간 기록을 추가하는 흐름이다.

- 작업 Initial Chat에서 프로젝트·작업·멤버가 채워진 Add Time Entry 모달로 진입한다.
- 타이머 없이 기록하는 체크가 선택되어 있고1시간·요율20을 입력한다.
- 성공 메시지 뒤 No hours added인 다른 캡처가 끼어 있으며, 마지막에는 작업 합계1시간이 보인다. 단일 연속 세션으로 추정하지 않는다.

- 상위 흐름: [Adding a task](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Project detail/Adding a task/Adding a time entry`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **작업 담당자 반영**이다. 드롭다운이 닫히고 담당자가 표시된다. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **작업에1시간 누적 표시**이다. 한 시간 기록이 있는 작업. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Adding a task](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

| 04 | 생성 성공 안내. — 작업·문서 개요는 빈 안내 유지. Time Tracking 카드는 아래 일부만 보임. | 생성 ID·목록갱신·토스트만 성공인 경우의 처리. |
| 05 | 설명은 채워져 있고 하위 작업은 없는 상태. — Initial Chat / In Progress / Feb6 2024 / Joe Doe. 설명 Call Jane to have initial chat. 하위 항목 없음. | 설명 저장 시점·하위 항목 없음의 정확한 조회 상태. |
| 06 | 한 시간 기록이 있는 작업. — 총01:00:00, 상태In Progress·담당Joe Doe·기한Feb6. 설명은 비어 있음. 뒤 보드에는동일제목2개. | 동일 제목 작업 구분·시간 상세·소유자. |

위 표는 화면에서 보이는 상태·값이다. 성공 토스트가 있어도 수신자 접근·영수증·서버 저장을 독립 검증한 것은 아니다.

### R2 재검토에서 보완한 해석

프로젝트·작업·멤버가 채워진 모달에서 회색 100.0 예시 대신 20과 1시간을 입력하고 생성 안내가 나타난다. 이후 설명이 있는 No hours added 작업과 설명이 없는 1시간 작업이 나타나며 배경에는 동일 제목 두 카드가 있다. 동일 작업의 저장 실패·성공으로 단정하지 않고 ID와 재조회 검증을 남긴다.

### 업무 규칙과 연결 시 주의점

- 관찰: 수동 시간은 HR/MIN/SEC 세 입력과 날짜로 표현된다.
- 관찰: Task 선택에 지우기X가 있지만 비워서 저장한 결과는 없다. 필수 여부를 단정하지 않는다.
- 관찰: Notes가 빈 예시 상태에서 생성 성공 화면으로 이어진다. 현행 문서의 Description 필수 안내와 버전/조건 차이를 기록한다.
- 관찰: Log these hours without starting a timer 체크가 켜져 있다. 체크 해제 분기는 이 흐름에 없다.

## 6. 공식 도움말과 API 대조

아래 URL과 5절의 문서 규칙은 **R2의 2026-11-20 대조 기록**이다. 공통 상세 대조 문서는 현재 체크아웃에 없다. R3에서 모든 URL을 다시 읽은 것은 아니며, 새로 확인한 자료와 적용 범위는 [이번 공식 자료 검토](<../../../../FE_REVIEW.md#official-sources>)에 구분했다. 과거 캡처에 현재 규칙을 소급 적용하지 않는다. 실제 계정이나 내부 API는 실행하지 않았다.

- [수동 시간 입력 도움말](https://help.hellobonsai.com/en/articles/3438791-manually-adding-time-tracking-entries): R2 본문 대조 기록(S074). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [Time Entries API](https://docs.hellobonsai.com/api/tag/time-entries): R2 본문 대조 기록(S075). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

## 7. 데이터 모델링 시사점

다음은 관찰에 기반한 OneHandSales 구현 후보다. 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- TimeEntry의 프로젝트·선택적 작업 후보·기록 멤버·기간 길이·업무일자·요율·메모 후보.
- 수동 기록과 타이머 실행의 생성 경로를 구분하되 같은 시간 합계에 포함하는 조회 모델 후보.
- 프로젝트 담당자와 실제 시간 기록자(Project Member)는 서로 다른 관계로 검토한다.
- FE 후보: 문맥으로 채워진 모달, 시/분/초 분할 입력, 수동모드 체크, 생성 성공 토스트.

### 단계별 모델링 근거

- 단계 01: 담당자 참조와 배경 조회 갱신 후보.
- 단계 02: 시간기록의 업무 대상과 기록자·시간·요율 후보.
- 단계 03: 기간을 정규화할 저장 단위와 요율 스냅샷 후보.
- 단계 04: 생성 결과와 후속 조회 분리 후보.
- 단계 05: 부모 작업 설명과 자식 목록 후보.
- 단계 06: 작업ID별 시간 합계와 표시명 분리.

## 8. 미확인 사항과 검토 질문

**원본에 없는 분기·남은 범위:** Task/Notes/Project Member의 실제 필수 조건은 무엇인가? 빈 값 제출과 공개 요청 스키마를 대조한다. 기록자가 다른 멤버의 시간을 입력할 수 있는가? 역할별 권한을 확인한다.

- Task/Notes/Project Member의 실제 필수 조건은 무엇인가? 빈 값 제출과 공개 요청 스키마를 대조한다.
- 기록자가 다른 멤버의 시간을 입력할 수 있는가? 역할별 권한을 확인한다.
- 0시간·음수·60분·24시간 이상 입력은 어떻게 정규화되는가? 경계값 검증이 필요하다.
- 성공 뒤 No hours added 캡처는 다른 작업인가? 동일 이름 두 작업의 실제 ID·시점을 확인한다.

### 단계별 미확인 사항

- 단계 01: 목록 반영·알림·권한·영속 저장.
- 단계 02: 프로젝트 필드 비활성 여부·멤버변경권한·필수값.
- 단계 03: 소수시간·자리수·음수·요율통화.
- 단계 04: 생성 ID·목록갱신·토스트만 성공인 경우의 처리.
- 단계 05: 설명 저장 시점·하위 항목 없음의 정확한 조회 상태.
- 단계 06: 동일 제목 작업 구분·시간 상세·소유자.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **부분**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: 시간 기록 생성과 작업 상세를 ID로 연결한다. 같은 제목 두 작업을 분리하고 성공 뒤 No hours added를 저장 실패로 단정하지 않는다.
- [이 흐름의 보완표](<../../../../FLOW_REVIEW_MATRIX.md#flow-38dcad7d-b2da-4d91-8eb3-2f3b39899b66>)와 [공통 웹 상태·연결 기준](<../../../../FE_REVIEW.md#fe-acceptance>)을 함께 적용한다. 캡처에 없는 동작은 Bonsai 관찰 사실로 쓰지 않고 목 가정 또는 추가 조사로 표시한다.


### 동일 재현을 위한 남은 분석 (R4)

- 시간 기록이 연결된 대상의 동일성·설명 변화·모달 기본값 출처를 추가 확인해야 한다. 요율 placeholder와 실제 값, 시분초 입력 폭/검증을 따로 명세해야 한다.
- 공통 미완: 요소별 누락 검사, 정확한 배치·타이포그래피·색/장식·자산 대응·미노출 상태는 [12개 검토 항목](<../../../../SOURCE_ANALYSIS_STANDARD.md>)으로 추가 명세한다. 원본에 없는 동작은 관찰 사실과 분리한다. 이 문서의 R4 표시를 동일 재현 명세나 FE 구현 완료로 읽지 않는다.
