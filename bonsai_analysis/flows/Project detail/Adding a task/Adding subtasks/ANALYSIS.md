## 2. 플로우 목적과 연결

실제 작업 Initial Chat에 두 하위 작업을 추가하고 첫 하위 작업의 담당자·완료 상태를 확인하는 흐름이다.

- 시작: In Progress 작업, Joe Doe 담당, Feb6 기한, 설명 Call Jane to have initial chat. 종료: Send invite 완료/JD, Prepare a deck 미완료.
- 하위 항목의 상세 편집은 Editing a subtask에 분리되어 있다.
- 단계2 이후 Files 위 붉은 가로선이 생기지만 오류 문구·권한 배지는 없다. 원본 주석 가능성을 남긴다.

- 상위 흐름: [Adding a task](../ANALYSIS.md)

- 폴더 위치: `bonsai_analysis/flows/Project detail/Adding a task/Adding subtasks`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **하위 작업 추가 전 작업 상세**이다. 설명은 채워져 있고 하위 작업은 없는 상태. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **하위 작업 완료·담당자 표시와 빈 댓글 입력**이다. Send invite는 완료 체크와 JD를 표시하고 Prepare a deck은 미완료다. 댓글은 비어 있으며 기존 자동 이벤트 두 항목이 보인다. 완료·할당 조작은 생략되어 있고 서버 저장은 독립 검증하지 않았다.
- 관련 흐름: [Adding a task](<../ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

- 관찰: 각 하위 항목에 Save가 있고 입력 상태와 일반 목록 상태가 다르다.

- 관찰: 첫 행 강조 상태에서 담당자 추가와 삭제 아이콘이 노출된다. hover인지 선택/포커스인지는 정적 캡처만으로 확정하지 않는다.
- 관찰: 첫 하위 작업에 JD가 표시되지만 부모 담당자가 자동 상속되는지 수동 할당인지 중간 단계가 없다.

## 6. 공식 도움말과 API 대조

아래 URL과 5절의 문서 규칙은 **R2의 2026-11-20 대조 기록**이다. 공통 상세 대조 문서는 현재 체크아웃에 없다. R3에서 모든 URL을 다시 읽은 것은 아니며, 새로 확인한 자료와 적용 범위는 [이번 공식 자료 검토](<../../../../FE_REVIEW.md#official-sources>)에 구분했다. 과거 캡처에 현재 규칙을 소급 적용하지 않는다. 실제 계정이나 내부 API는 실행하지 않았다.

- [Tasks API](https://docs.hellobonsai.com/api/tag/tasks): R2 본문 대조 기록(S046). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [작업 생성·추적 도움말](https://help.hellobonsai.com/en/articles/5182750-how-to-create-and-track-tasks-with-bonsai): R2 본문 대조 기록(S073). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

## 7. 데이터 모델링 시사점

다음은 관찰에 기반한 OneHandSales 구현 후보다. 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- Task의 부모 관계 또는 별도 하위 항목 엔티티 후보. 공식 문서의 중첩을 고려해야 하지만 실제 테이블 전략은 미정.
- 하위 항목별 제목·완료·담당자·순서·상위 연결 후보. 부모 상태와 자식 완료는 분리해서 검증한다.
- FE 후보: 인라인 항목 생성, 체크박스, 행별 보조 액션, 담당자 아바타, 패널 내부 스크롤.

### 단계별 모델링 근거

- 단계 01: 부모 작업 설명과 자식 목록 후보.
- 단계 02: 데이터 모델 변화 근거 없음; 시각적 미확인 항목으로 보존.
- 단계 03: 하위 항목 로컬 입력과 생성 요청 후보.
- 단계 04: 자식 제목 후보.
- 단계 05: 부모 아래 자식 목록과 개별 완료 상태 후보.
- 단계 06: 일대다 자식 관계 후보.
- 단계 07: 생성 순서 또는 별도 정렬값 후보.
- 단계 08: 독립 자식 완료 상태와 부모 관계 후보.
- 단계 09: 자식별 담당자·삭제 권한 및 행 액션 UI 후보.
- 단계 10: 활동 목록과 댓글 입력 상태 후보.

## 8. 미확인 사항과 검토 질문

**원본에 없는 분기·남은 범위:** 모든 하위 항목 완료 시 부모 상태는 변하는가? 부모가 여러 상태일 때 각각 재현한다. 하위 항목의 담당자·프로젝트·기한은 부모에서 상속되는가? 독립 변경과 부모 변경을 비교한다.

- 모든 하위 항목 완료 시 부모 상태는 변하는가? 부모가 여러 상태일 때 각각 재현한다.
- 하위 항목의 담당자·프로젝트·기한은 부모에서 상속되는가? 독립 변경과 부모 변경을 비교한다.
- 하위 삭제는 확인 모달·복구·손자/시간기록 처리 규칙이 있는가? 실제 계정의 테스트 데이터로 확인한다.
- 항목 순서 저장과 중첩 깊이 제한·순환 참조 방지는 어떤가? 공식 API 모델과 입력 검증을 대조한다.

### 단계별 미확인 사항

- 단계 01: 설명 저장 시점·하위 항목 없음의 정확한 조회 상태.
- 단계 02: 이미지 주석/캡처 도구 표시인지 실제 UI인지.
- 단계 03: 빈 제목 저장·Enter/ESC·취소.
- 단계 04: 제목 길이·중복·저장 요청 중 상태.
- 단계 05: 새로고침 유지·정렬·수정 진입.
- 단계 06: 복수 입력행 동시 열림·취소 시 기존 항목 영향.
- 단계 07: 중복 제출·입력 순서 저장.
- 단계 08: 부모 완료와 자식 상태 연동·다중선택.
- 단계 09: 담당자 선택 대상·삭제 확인·키보드 접근.
- 단계 10: 붉은 선 의미·댓글 표시 범위·빈 제출 가능성.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **결과**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: 하위 입력 저장·완료 체크·담당자 표시를 독립 상태로 둔다. 마지막 Send invite 완료/JD를 반영하고 부모 자동 완료는 가정하지 않는다.
- [이 흐름의 보완표](<../../../../FLOW_REVIEW_MATRIX.md#flow-b8bd1036-63f8-4e27-b2b7-a76abf4d8f10>)와 [공통 웹 상태·연결 기준](<../../../../FE_REVIEW.md#fe-acceptance>)을 함께 적용한다. 캡처에 없는 동작은 Bonsai 관찰 사실로 쓰지 않고 목 가정 또는 추가 조사로 표시한다.
