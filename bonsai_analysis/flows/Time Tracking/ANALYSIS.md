## 2. 플로우 목적과 연결

시간 기록을 일별 목록으로 조회하고 Insights에서 프로젝트별 시간·금액과 청구 상태 합계를 확인하는 흐름이다.

- 시작은 Dashboard, 종료는 프로젝트별 타임시트의 상세 행·합계다.
- Starting time tracking 완료 기록과 연결할 수 있는 설명·시간 값이 있지만 정적 캡처에는 레코드 ID가 없다.
- 수동 추가·행 편집·삭제·필터 내부는 이 루트의 캡처에 포함되지 않는다.
- FE는 날짜 그룹 목록, 두 탭, 집계 도구, 그래프, 지표, 프로젝트별 보고서로 분리한다.


- 폴더 위치: `bonsai_analysis/flows/Time Tracking`
- 부모·자식은 Gummble 탐색 분류이며, 모든 하위 플로우가 순차 실행된다는 뜻은 아니다.
- 상위 흐름: 없음. Gummble 최상위 분류.
- 하위 흐름: 없음.

### 진입 조건과 확인된 종료 범위

- 진입: 첫 캡처는 **대시보드 — 프로젝트 타임라인과 손익 요약**이다. Dashboard가 선택되어 있으며 모달·오류·성공 토스트는 없다. 여러 플로우가 공유하는 동일한 시작 이미지다. 이 화면 이전의 인증·권한·클릭 경로는 캡처에 보이는 범위만 인정한다.
- 종료: 마지막 캡처는 **프로젝트별 타임시트 상세**이다. By Project 보고서의 한 프로젝트 상세가 표시된다. 기록 종료를 전체 업무의 성공·서버 저장 완료로 확대하지 않는다.
- 관련 흐름: [Starting time tracking](<../Starting time tracking/ANALYSIS.md>), [Invoices](<../Invoices/ANALYSIS.md>)
- 관련 흐름은 기능 연결점이다. 서로 다른 캡처를 같은 계정·같은 시각의 연속 실행으로 합치지 않는다.

- 확정 전 확인: 내보내기 지원·권한별 멤버 정보·다중통화합산·고객/프로젝트 이동시 과거값. 소유 범위·필수값·연결 수·삭제 영향은 화면과 공식 계약을 추가 대조한다.

동일 Initial Chat 제목으로 7초·0.04달러와 1시간·20달러의 두 기록이 존재한다. 다음 화면의 2월 7일 기록은 1분 16초·0.42달러지만 Insights 기간은 1월 23일~2월 6일이어서 해당 기록이 집계 밖이다. 같은 합계에서 그래프 높이가 달라진 이유는 미확인이다. 시간 단가·표시 반올림·청구/수금은 별도로 검증해야 한다.

### 업무 규칙과 연결 시 주의점

- 관찰: 같은 작업에 여러 시간 기록이 존재하며 그룹 합계는 초 단위로 표시한다.
- 관찰: 미청구와 청구 합계가 나뉘며 시간과 금액을 각각 표시한다.
- 관찰: 목록의 Feb7 기록과 보고서의 Jan23–Feb6 기간을 구분해야 한다. 보고서에서 누락됐다는 버그로 판정하지 않는다.
- 미확인: 그래프 두 캡처의 높이 차이. 같은 지표 값이므로 원본 데이터 변화로확정하지않는다.

## 6. 공식 도움말과 API 대조

아래 URL과 5절의 문서 규칙은 **R2의 2026-11-20 대조 기록**이다. 공통 상세 대조 문서는 현재 체크아웃에 없다. R3에서 모든 URL을 다시 읽은 것은 아니며, 새로 확인한 자료와 적용 범위는 [이번 공식 자료 검토](<../../FE_REVIEW.md#official-sources>)에 구분했다. 과거 캡처에 현재 규칙을 소급 적용하지 않는다. 실제 계정이나 내부 API는 실행하지 않았다.

- [시간 청구 상태](https://help.hellobonsai.com/en/articles/1898575-invoicing-your-tracked-time): R2 본문 대조 기록(S043). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [Time Entries API](https://docs.hellobonsai.com/api/tag/time-entries): R2 본문 대조 기록(S075). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.
- [내부 시간 추적 도움말](https://help.hellobonsai.com/en/articles/2548737-tracking-time-internally-with-bonsai): R2 본문 대조 기록(S076). 공통 상세 원문은 현재 없으며, 이 문서에 남은 규칙·한계는 5·8절에서 확인한다.

화면과 대조할 때는 5절의 R2 해석 및 8절의 미확인 항목을 함께 적용한다. 현재 문서에만 있는 필수값·요금제·역할·새 UI를 과거 화면의 동작으로 확정하지 않는다.

- [API 검토 범위](<../../FE_REVIEW.md#api-boundary>): 이 흐름의 내부 endpoint·실제 요청/응답·DB 스키마는 확인하지 않았다. 공개 API 목록에 없는 기능의 미지원 여부도 확정하지 않는다.

## 7. 데이터 모델링 시사점

다음은 관찰에 기반한 OneHandSales 구현 후보다. 기능 채택·스키마·업무 정책으로 확정하지 않는다.

- 설계 가정: 시간기록 원본과 목록/보고서 집계를 구분한다. 날짜·프로젝트·멤버·청구 상태로 조회하는 요구가 관찰된다.
- 설계 가정: durationSeconds와 화폐 금액/통화를 정밀하게 보관하고 표시 반올림은 분리한다. 저장 단위는 API 스키마 확인 후 결정한다.
- 설계 가정: 청구와 결제는 다른 상태축이며 인보이스 연결이 필요할 수 있다.
- FE 후보: 고정 사이드바, 본문 스크롤, 날짜 그룹 접기, 조회상태·기간·집계 기준.

### 단계별 모델링 근거

- 단계 01: 프로젝트·문서 참조, 기간·통화별 재무 집계, 빠른 생성 진입점 및 공통 내비게이션 후보. 메뉴 노출은 서버 권한의 증거와 구분한다.
- 단계 02: TimeEntry 개별ID, 작업/설명, 프로젝트·멤버·금액·초 단위 시간; 날짜별 합계 투영 후보.
- 단계 03: 일별 내림차순 그룹·기록별 금액/합계·기간 경계 후보.
- 단계 04: 기간·그룹 기준·청구 상태별 시간과 금액 집계 후보; 시간기록 원본과 별도 조회 모델 가능.
- 단계 05: 그래프의 표시 상태와 집계 원본 값을 구분; 새 업무 상태로 모델링하지 않는다.
- 단계 06: 시간기록의 프로젝트 그룹별 상세와 총합. 멤버 아바타/이름은같은멤버참조 후보.

- By Project 외모드·빈보고서·오류·권한제한상태가 어떤가? 로컬추가이미지 또는 검증 계정으로 확인한다.

### 단계별 미확인 사항

- 단계 01: 날짜와 집계의 기준 시간대, 그래프 산식, 타임라인 아이콘의 정확한 날짜 의미, 역할별 접근 권한, 홍보 노출 조건은 이 이미지로 확인할 수 없다.

- 단계 03: $0.42 계산·반올림, 캡처간 날짜 경과 또는데이터변경.
- 단계 04: Y축 단위·기본 기간·By Project의 다른 집계 선택지·청구 전환 시합계반영.
- 단계 05: 두 이미지의 막대 차이 원인·축 자동스케일·애니메이션.
- 단계 06: 내보내기 지원·권한별 멤버 정보·다중통화합산·고객/프로젝트 이동시 과거값.

- 같은 계정·제품 빌드에서 시작 상태를 맞춘 뒤 해당 업무의 정상·취소·실패·재진입 결과를 검증해야 한다. 화면 목록과 이미지 검토 완료는 제품 전체 기능의 의미적 완전성이나 구현 검증 완료를 뜻하지 않는다.

### FE 구현 전 보완 (R3)

- 캡처 범위 분류: **조회**. 업무 전체의 완료 판정이 아니다.
- 목 구현·수용 기준 후보: 원시 초·표시 시간·단가·금액·청구 상태를 나눈다. 보고서 기간 밖 기록과 동일 제목 작업 ID를 구분하고 합계 예제를 검증한다.
- [이 흐름의 보완표](<../../FLOW_REVIEW_MATRIX.md#flow-525f8723-dca6-4932-ac6e-d159249090be>)와 [공통 웹 상태·연결 기준](<../../FE_REVIEW.md#fe-acceptance>)을 함께 적용한다. 캡처에 없는 동작은 Bonsai 관찰 사실로 쓰지 않고 목 가정 또는 추가 조사로 표시한다.
