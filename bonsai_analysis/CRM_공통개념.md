# Bonsai를 이해하기 위한 CRM·업무 공통 개념

Updated: 2026-11-17

Bonsai를 학습할 때 고객 정보만 보는 것이 아니라, 영업에서 합의·수행·청구로 이어지는 업무를 함께 이해한다. 아래 예시는 가상의 청소 회사 ‘맑은청소’와 고객 ‘한빛학원’의 일이다. 제품의 모든 단계가 자동 연결되거나 특정 업종을 지원한다는 검증 결과가 아니다.

| 개념 | 쉬운 뜻 | 예시 |
| --- | --- | --- |
| 계정·업무 공간 | 우리 회사와 팀이 일하는 데이터·권한 경계 | 맑은청소 내부 직원의 업무 공간 |
| 고객 회사·담당자 | 일을 맡기는 주체와 연락하는 사람 | 한빛학원과 김실장 |
| 거래·파이프라인 | 성사시키려는 건과 현재 영업 단계 | 다음 달 청소 계약을 협의 중 |
| 서비스·단가표 | 재사용할 작업 항목과 가격 기준 | 바닥·창문 청소 항목 |
| 견적(Estimate) | 범위·수량·단가·비용을 산정한 내용 | 이번 달에는 창문을 제외한 금액 |
| 합의 문서(Document) | 고객에게 보내고 확인·서명받는 문서 | 수행 범위와 금액을 담은 계약 |
| 프로젝트 | 실제 수행할 업무 묶음 | 한빛학원 12월 청소 |
| 작업·담당자 | 해야 할 일과 맡은 사람 | 창문 청소를 현장 팀장에게 배정 |
| 시간·비용 | 실제 투입한 노력과 지출 | 작업 시간과 소모품 비용 |
| 예산·배정 | 예상 투입량·금액과 사람의 일정 | 하루 두 명 배정, 예상 비용 관리 |
| 청구서(Invoice) | 고객에게 지급을 요청하는 문서 | 이번 작업의 청구 금액·기한 |
| 입금·결제(Payment) | 실제로 받은 금액과 기록 | 일부 입금과 남은 잔액 |
| 고객 포털 | 고객이 허용된 자기 자료를 확인하는 공간 | 계약·청구서·공유 작업 확인 |
| 사용자 필드·보기 | 추가 입력 항목과 표시·필터 방식 | 추가 정보, 담당자별 거래 보기 |
| 자동화·연동·보고서 | 사건에 따른 처리, 외부 연결, 업무 집계 | 조건에 따른 후속 작업·미청구 확인 |

제품별 정확한 동작은 [Bonsai 공식 출처](../AGENT/UXUI_AGENT/PLANNING/BONSAI_BENCHMARK_RESEARCH.md)의 B02~B24를 따른다.

## 정보를 섞지 않기

고객의 연락처는 여러 건에서 재사용할 수 있지만 이번 작업의 옵션·합의 금액·발송 문서·입금은 해당 업무의 정보다. 고객·거래·프로젝트·청구서를 모두 하나의 기록으로 취급하지 않는다. 정확한 필수 관계와 개수는 조사 후 정한다.

- 거래 수주는 프로젝트 완료가 아니다.
- 문서 서명은 입금 완료와 같지 않다.
- 기록한 모든 시간이 고객에게 청구되는 것은 아니다.
- 청구됨은 실제 돈을 받았다는 뜻이 아니다.
- 반복 청구서 발행과 카드 자동 결제 구독은 다르다.
- 내부 실무자 권한과 외부 고객 포털 권한은 다르다.

## 예시를 검증할 질문

1. 요청 범위와 가격을 어디에 적고 어느 내용으로 합의했는가?
2. 견적 수정 시 이미 발송한 문서·프로젝트·청구에 무엇이 반영되는가?
3. 영업 담당자의 약속을 실제 수행자가 어디에서 확인하는가?
4. 부분 입금·취소·추가 작업의 값과 상태가 어디에 남는가?
5. 고객과 내부 직원에게 각각 어떤 정보를 보여주는가?

지역·면적별 자동 가격, 국내 세무 연동 등은 별도 확인 항목이다. 청소·개발 예시를 제품의 확정 업종이나 구현된 기능으로 바꾸지 않는다.
