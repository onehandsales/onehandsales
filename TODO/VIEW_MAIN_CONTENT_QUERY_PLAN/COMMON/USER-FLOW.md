# View 선택부터 주 화면까지의 사용자 흐름

기준은 [원본 텍스트 UX](../../VIEW_TWO_AREA_TEXT_UX.md)다. 기존 헤더와 ‘보기 설정’ 패널의 위치·모양을 유지하고 본문만 타입별로 연결한다. 아래 텍스트는 **조회 설계**이며 화면 구현 결과가 아니다. 타입별 수치는 실제 목 데이터 조사 결과를 사용하되 전체 페이지/기간이 다른 경우를 명시한다.

현재 구현 대상은 [Backend 주 화면 GET만](SCOPE_AND_DEFERRED_WORK.md)이다. 이 문서의 FE 화면 연결은 후속 참고이며 필터·정렬 저장 동작은 나중에 구현한다.

## 1. 공통 흐름

```text
사이드바에서 Object / List 선택
  → 기존 초기 헤더 API: 현재 View의 viewDefinitionId / viewType 확보
  → 공통 View 본문: GET .../view-definitions/{viewDefinitionId}/data
  → 응답 viewType에 맞는 본문 컴포넌트 렌더링

현재 보기 ▼에서 다른 View 선택
  → 선택 ID 변경 → 이전 요청 취소 → 새 ID로 같은 API 호출
  → 해당 타입의 헤더 도구 노출 + 해당 타입의 본문

필터 / 정렬 / 보기 설정 열기
  → 기존 해당 메뉴 GET 사용
  → 메뉴 내용 조회와 본문 데이터 조회의 캐시는 별도
```

현재 헤더는 별도의 ID를 새로 생성하지 않는다. 선택된 ViewDefinition ID를 주 화면 요청에 넘긴다. View를 바꾸는 선택과 저장 View의 type 자체를 수정하는 행위를 구분한다.

## 2. 헤더와 본문의 경계

| 타입 | 유지할 오른쪽 도구 | 이번 본문 조회가 제공할 것 |
| --- | --- | --- |
| TABLE / KANBAN / LIST / GALLERY | 검색·필터·정렬·기록 추가·보기 설정 | 행/카드/단계와 표시값 |
| CALENDAR | 검색·필터·기록 추가·보기 설정 | 일정, 기간, 미설정 날짜 목록 |
| TIMELINE / GANTT | 검색·필터·정렬·기록 추가·보기 설정 | 기간 막대, Gantt 진행률·관계 |
| CHART / PIVOT | 필터·보기 설정, 원본 데이터는 후속 | 전체 조건 집계, 축·셀·합계 |
| MAP | 검색·필터·목록 정렬·기록 추가·보기 설정 | 좌표 핀과 연결 목록 |
| DASHBOARD | 보기 설정, 대시보드 편집은 후속 | 표시 위젯 배치와 각 원본 View |

‘기록 추가’는 기존 위치를 설명한다. 새로운 생성 API/타입별 생성 UX는 이번 계획에 포함하지 않는다. 기존 연결이 있는 기능의 회귀는 검증하되, 연결되지 않은 버튼을 완료 기능처럼 활성화하지 않는다. 원본 문서의 별표가 붙은 후속 도구를 주 화면의 선행 API로 추가하지 않는다.

**현재 GET은 DB에 저장된 설정을 실행한다.** 기존 메뉴의 로컬 임시 편집은 이번 GET에 전달하지 않는다. 사용자가 원하는 필터·정렬 변경 경험은 후속 저장 API 성공 → 본문 GET 재조회이며, 이번에는 저장 API와 해당 FE 연결을 구현하지 않는다. 기존 FE 임시 편집 UI도 이 BE 작업에서 변경하지 않는다. 후속 FE 연결 시 저장/적용 상태가 실제 결과와 일치하도록 표시한다.

## 3. TABLE — 표

```text
[회사] [전체 회사 ▼] ☆                 [검색] [필터] [정렬] [+ 기록] [보기 설정]
─────────────────────────────────────────────────────────────────────────
회사명             도메인           업종            담당자        ...
회사 A             a.example       SaaS            담당자 A      ...
회사 B             b.example       제조             담당자 A      ...
...
5개 기록                                  [더 보기: 다음 page가 있을 때]
```

실제 전체 회사 View는 8개 열·5개 Record다. 위 행의 이름/도메인은 설명용 가상 값이다. 열은 현재 View의 표시 순서와 너비를 사용하고 Object 속성 목록 전체로 대체하지 않는다. 값이 여러 개면 여러 칩/값을 보존한다.

## 4. KANBAN — 단계별 카드

```text
[영업 파이프라인] [영업 단계별 ▼] ☆      [검색] [필터①] [정렬①] [+ 기록] [보기 설정]
─────────────────────────────────────────────────────────────────────────
초기 미팅 · 1          제품 평가 · 1        PoC 준비 · 1        기술·보안 검토 · 1
┌────────────────┐    ┌──────────────┐    ┌──────────────┐    ┌────────────────┐
│ 기회 A         │    │ 기회 B       │    │ 기회 C       │    │ 기회 D         │
│ USD 250,000    │    │ USD 220,000  │    │ USD 180,000  │    │ USD 300,000    │
└────────────────┘    └──────────────┘    └──────────────┘    └────────────────┘
             나머지 빈 단계 포함, 총 10단계 · 조건에 맞는 4개 항목
```

카드 제목 A~D는 예시다. 단계별 독립 더 보기를 제공한다. 금액은 카드의 실제 표시 속성이며 단계 합계 설정은 현재 없으므로 헤더 합계를 자동 생성하지 않는다. 카드 드래그 저장은 후속이다.

## 5. LIST — 간결한 목록

```text
[핵심 관계자 관리] [핵심 관계자 ▼] ☆     [검색] [필터] [정렬] [+ 기록] [보기 설정]
─────────────────────────────────────────────────────────────────────────
담당자 A    [회사 A]    [의사결정자]       접촉 전략 요약 ...
담당자 B    [회사 B]    [실무 담당]        접촉 전략 요약 ...
...
15개 항목
```

이름·회사는 Record 값, 역할·전략은 Entry 값이다. 행 클릭의 상세 대상은 Record ID로 찾되 Entry 맥락도 함께 전달한다. 새 상세 API 구현은 이 계획의 본문 조회와 구분한다.

## 6. GALLERY — 카드 미리보기

```text
[제품] [제품 카드 ▼] ☆                  [검색] [필터] [정렬①] [+ 기록] [보기 설정]
─────────────────────────────────────────────────────────────────────────
┌─────────────────────┐ ┌─────────────────────┐ ┌─────────────────────┐
│ 이미지/텍스트 미리보기 │ │ 이미지/텍스트 미리보기 │ │ 이미지/텍스트 미리보기 │
│ 제품 A              │ │ 제품 B              │ │ 제품 C              │
│ 제품 설명 ...       │ │ 제품 설명 ...       │ │ 제품 설명 ...       │
│ 단가                │ │ 단가                │ │ 단가                │
└─────────────────────┘ └─────────────────────┘ └─────────────────────┘
```

실제 제품 3개, MEDIUM/CONTAIN. 이미지가 없거나 로드할 수 없으면 텍스트 카드를 유지한다. 허용할 이미지 형식은 P07 확정 대상이다.

## 7. CALENDAR — 일정

```text
[영업 실행 업무] [영업 일정 ▼] ☆        [검색] [필터] [+ 기록] [보기 설정]
─────────────────────────────────────────────────────────────────────────
[오늘] [‹] [2026년 11월] [›]                               [월 / 주]
월           화           수           목           금          토   일
────────────── 일정 A: 10/29~11/02 ──┘
             [일정 B: 11/03]
             ├──────── 일정 C: 11/03~11/20 ────────────────────┤
...
[날짜 미설정 0]    [날짜 확인 필요 0]
```

기간 이동 도구는 본문에 둔다. 11월과 겹치는 9개 일정이며 10월에 시작한 일정도 보여야 한다. 페이지가 남으면 ‘9개 중 표시한 개수’를 구분하고 나머지를 읽을 수 있게 한다. 사용자가 선택한 A안에 따라 시작일만 있는 Calendar 항목은 하루 일정으로 표시하고, 시작일도 없으면 날짜 미설정 목록으로 분리한다.

## 8. TIMELINE — 기간

```text
[데모·제품 평가·PoC] [제품 평가 일정 ▼] ☆   [검색] [필터①] [정렬①] [+ 기록] [보기 설정]
─────────────────────────────────────────────────────────────────────────
[오늘] [‹ 2026년 11월 ›]                                      [주 ▼]
항목                  11/02       11/09       11/16       11/23       11/30
제품 평가 A                        ├──────────────────────────┤
제품 평가 B                        ├──────────────────────────┤
[기간 미설정 0]    [날짜 확인 필요 0]
```

조회 조건에 맞는 2개 Entry의 기간은 11/09~11/27이다. 원본의 기간 값은 보존하고 화면에서만 잘라 그린다. 사용자 선택 A안에 따라 Timeline/Gantt에서 시작 또는 종료값이 부족하면 기간 미설정 목록에 둔다.

## 9. GANTT — 진행률과 의존관계

```text
[영업 실행 업무] [업무 진행 계획 ▼] ☆    [검색] [필터] [정렬①] [+ 기록] [보기 설정]
─────────────────────────────────────────────────────────────────────────
[오늘] [‹ 2026년 11월 ›]                                      [주 ▼]
업무                   진행률          11/02       11/09       11/16
업무 A                   50%           [████░░░░]
                                              └────→[업무 B]
...
[기간 미설정 0]    [날짜 확인 필요 0]
```

그림의 두 업무/연결은 설명용이다. 실제 10개 전체 관계 중 화면 대상인 관계만 그린다. 다음 page의 상대 업무가 아직 없으면 잘못된 행에 선을 붙이지 않는다. 날짜·진행률·연결선을 편집하는 기능은 후속이다.

## 10. CHART — 전체 집계

```text
[영업 파이프라인] [단계별 예상 금액 ▼] ☆                [필터①] [보기 설정]
─────────────────────────────────────────────────────────────────────────
조건에 맞는 4개 항목 · 총 USD 950,000
초기 미팅          █████████████       250,000
제품 평가          ███████████         220,000
PoC 준비           █████████            180,000
기술·보안 검토     ███████████████      300,000
```

막대 길이는 설명용이다. 실제 집계 숫자는 DB 값으로 재계산한 기대값이다. ‘원본 데이터’ 버튼 없이도 본 화면을 조회할 수 있다. 툴팁은 이미 받은 집계값을 보여주고 원본 기록 목록 드릴다운은 후속이다.

## 11. PIVOT — 교차 집계

```text
[영업 파이프라인] [회사·단계별 집계 ▼] ☆                [필터①] [보기 설정]
─────────────────────────────────────────────────────────────────────────
회사       초기 미팅     제품 평가     PoC 준비     기술·보안 검토      합계(USD)
회사 A      250,000           —            —              —             250,000
회사 B           —       220,000          —              —             220,000
회사 C           —            —       180,000            —             180,000
회사 D           —            —            —         300,000           300,000
합계        250,000       220,000      180,000         300,000           950,000
```

회사명 A~D는 가상 표기, 빈 열은 생략한 그림이다. ‘해당 조합 없음’, 측정값 누락, 숫자0을 별도 상태로 표현한다. 셀 클릭 원본 드릴다운 없이도 집계 화면은 완성할 수 있다.

## 12. MAP — 핀과 연결 목록

```text
[핵심 타깃 계정] [타깃 계정 지도 ▼] ☆   [검색] [필터] [목록 정렬] [+ 기록] [보기 설정]
─────────────────────────────────────────────────────────────────────────
조건에 맞는 위치 5개                  [전체 위치 보기]
┌──────────────────────────────┬─────────────────────┐
│          지도                │ 회사 A              │
│    ①         ②              │ 회사 B              │
│         ③         ④         │ 회사 C              │
│    ⑤                         │ 회사 D / 회사 E     │
└──────────────────────────────┴─────────────────────┘
[위치 미설정 0]
```

목록 정렬은 목록에 적용한다. 핀/목록 선택은 같은 itemKey로 연결한다. 페이지 밖 항목은 선택 조회로 보완한다. 모바일에서는 지도/목록 전환 또는 아래 패널로 같은 선택을 유지한다. 지오코딩·지도 Provider 선택은 본문 응답 설계와 별도다.

## 13. DASHBOARD — 원본 View 조합

```text
[영업 파이프라인] [영업 현황 ▼] ☆                             [보기 설정]
─────────────────────────────────────────────────────────────────────────
┌─ 단계별 예상 금액 ───────────┐ ┌─ 회사·단계별 집계 ──────────┐
│ CHART 결과                  │ │ PIVOT 결과                 │
│ 총 USD 950,000              │ │ 합계 USD 950,000           │
└─────────────────────────────┘ └────────────────────────────┘
┌─ 영업 단계별 ────────────────┐
│ KANBAN 결과                 │
│ 4개 항목                    │
└─────────────────────────────┘
```

구성 조회 후 3개 원본 View를 같은 API로 각각 읽는다. 위젯 하나가 실패하면 그 칸에서 재시도하고 정상 위젯은 유지한다. 각 위젯 안에 페이지 전체의 글로벌 헤더를 다시 넣지 않는다. 위젯 추가·편집·크기 저장은 후속이다.

## 14. 공통 상태 UX

| 상태 | 표시·동작 |
| --- | --- |
| 초기 로딩 | 선택 View 타입의 본문 skeleton. 이전 타입의 데이터를 새 제목 아래 보여주지 않음 |
| 원본 0개 | ‘아직 항목이 없습니다’ |
| 원본은 있으나 필터 결과 0 | ‘조건에 맞는 항목이 없습니다’ |
| NEEDS_CONFIGURATION | 필요한 역할/설정 안내. 기존 보기 설정 패널로 이동하되 저장 기능이 없으면 안내만 제공 |
| 값 일부 없음 | 빈 셀/미설정 날짜/미위치 목록. 숫자0으로 바꾸지 않음 |
| cursor 409 | 이전 page를 버리고 첫 page 새로 조회 |
| 한도 422 / 시간 초과 503 | 결과를 부분 성공으로 표시하지 않고 조건·기간 조정 또는 재시도 안내 |
| 접근 불가 | 안전한 접근 불가 화면. 다른 Workspace 이름/Record 제목 없음 |
| Dashboard 일부 오류 | 해당 위젯에만 안전한 상태·재시도 |

표시 문구는 후속 FE/UX 검토에서 조정한다. 현재 조회와 후속 저장→재조회 범위를 구분하고 기존 메뉴 패널을 새 전체 설정 화면으로 교체하지 않는다.
