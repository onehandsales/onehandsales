## 공개 웹의 웹 품질 기준

- 공개 route는 가상 세션이 없어도 직접 진입·새로고침·뒤로 가기가 가능해야 한다. 앱의 인증 bootstrap·workspace API를 자동 호출하지 않는다.
- 헤더·푸터·메가메뉴·검색·템플릿 카드·플랜 비교를 책임별 컴포넌트로 나눈다. 광고 이미지 속 앱 목업은 실제 입력 UI로 착각하지 않게 한다.
- 좁은 화면에서 메뉴 열기/닫기·키보드 포커스·Escape·스크롤 복귀, 긴 제목, 표/가격 카드의 재배치를 검증한다. 이미지로 보이지 않은 모바일 원본은 가정으로 남긴다.
- 검색 무결과·잘못된 상세 URL·이미지 실패·로딩·가입 인계 실패와 재시도를 구현한다. 정적 본문에 불필요한 가짜 로딩을 강제하지 않는다.
- 문서 제목·설명·canonical/index 여부·내부 링크·404·기존 정적 SEO 빌드 영향을 확인한다. 확정된 검색 노출 정책 없이 운영 배포하지 않는다.
- 쿠키/동의 UI가 원본 또는 실제 사용 기술상 필요한지는 R01에서 조사한다. 단지 랜딩이라는 이유로 새로운 정책·추적 기능을 추가하지 않는다.
- 비밀번호·개인정보를 return URL에 넣지 않는다. 초안 인계는 개발 목 저장소의 별도 데이터로 다루고 리셋/만료 시나리오를 정한다.

## 고객에게 공유하는 화면은 별도 영역

공개 폼(G48), 공개 예약(G53), 문서 검토·서명·결제(R09/R13/R14), 고객 포털(R17)은 외부 수신자가 쓰는 업무 화면이다. 일반 마케팅 랜딩과 동일한 로그인 정책을 적용하지 않는다. 링크 토큰·만료·수신자 확인·공유 해제·다른 고객의 접근은 해당 분석에서 확인한다.
