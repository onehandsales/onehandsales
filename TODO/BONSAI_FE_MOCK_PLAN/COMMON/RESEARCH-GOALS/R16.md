# R16 — 은행·CSV 가져오기·파일 내보내기

상태: **미착수** · 종류: 추가 분석 Goal · 실제 계정 재현: 미수행

## 1. 실행 시점과 소비 Goal

- [시작 체크리스트](<../START-CHECKLIST.md>)와 [UX/UI 재현 기준](<../UXUI-REPLICATION.md>)을 먼저 읽는다. FRONT_AGENT를 적용하며 Backend 문서·계약 확인은 현재 선행 조건에 포함하지 않는다.
- 기본 순서: 첫 소비 Goal 직전에 수행한다. 이미 확인한 자료의 재사용은 조회일·버전·적용 범위를 대조한 뒤 기록한다.
- 소비 Goal: [G68 비용 내보내기](<../GOAL-SPECS/G68.md>) · [G70 은행 연결 소개·취소·미연결 상태](<../GOAL-SPECS/G70.md>) · [G78 CSV 가져오기·매핑·오류](<../GOAL-SPECS/G78.md>)
- 선행 공통 기준: [G00 근거·버전·범위 대응표](<../GOAL-SPECS/G00.md>). 실제 FE 구현 완료가 분석 착수 조건은 아니다.
- 목적: 아래 질문을 해결하여 관찰된 화면 재현과 미수록 업무 구현의 경계를 정한다. 제품 전체 조사가 끝날 때까지 독립적인 다른 기능을 멈추는 조건으로 확대하지 않는다.

## 2. 이번 분석에서 확인할 질문

이번 R은 화면·상태·상호작용을 보완한다. 아래 질문 중 API·DB·서버 처리·실계정 검증은 후속 메모로 분류한다. 그 답을 기다리며 관찰된 UX/UI 구현을 멈추지 않으며 실제 API나 외부 서비스를 연결하지 않는다.

- [ ] 은행 선택·동의 취소·인증 결과·동기화·해제와 가져온 거래를 분리한다.
- [ ] CSV 수정 재시도·정상 완료·전체 실패/부분 저장·중복 처리·Currency 검증을 확인한다.
- [ ] 내보내기 열·정렬·범위·인코딩·파일 수신·실패를 실제 산출물과 대조한다.

## 3. 시작 근거와 확인 방법

- [Bookkeeping/Connect bank account](<../../../../bonsai_analysis/flows/Bookkeeping/Connect bank account/ANALYSIS.md>)
- [Bookkeeping/Downloading expenses](<../../../../bonsai_analysis/flows/Bookkeeping/Downloading expenses/ANALYSIS.md>)
- [Settings/Importing a CSV](<../../../../bonsai_analysis/flows/Settings/Importing a CSV/ANALYSIS.md>)
- [전체 FE 보완 분석](<../../../../bonsai_analysis/FE_REVIEW.md>) 및 [21개 기능군](<../../../../AGENT/PM_AGENT/PLANNING/BONSAI_FEATURE_PARITY_MATRIX.md>)에서 남은 범위를 확인한다.
- Gummble 화면/flow와 로컬 분석을 시안으로 사용하고, 필요한 화면 의미는 공식 도움말로 보완한다. 공식 REST API·실계정·서버 규칙 조사는 UX/UI 완성 후 단계로 남긴다. 현재 API 제공 여부로 화면을 제외하지 않는다.
- 자료를 새로 조회하면 직접 URL·조회일·적용 버전·확인한 화면/본문을 적는다. 이번에는 인증·발송·결제·삭제·외부 연결까지 모두 로컬 목 화면으로만 표현한다.
- 자료가 없으면 관찰 사실을 채워 넣지 않고 화면 대기·문서 근거·목 가정을 구분한다.

## 4. 완료 산출물과 필수 체크

- [ ] 시작 역할·입력·정상 종료·취소·실패·권한·재진입의 흐름 표를 작성했다.
- [ ] 확인한 자료와 미확인 항목, 구형/현행 충돌, 채택한 목 가정을 구분했다.
- [ ] 필드·관계 ID·상태·저장 경계·금액/시간·권한의 FE 요구를 작성했다. 실제 endpoint·DB 제약은 확정하지 않았다.
- [ ] 위 소비 Goal의 범위·입력·수용 기준·체크리스트를 분석 결과와 함께 갱신했다.
- [ ] 후속 구현 범위 **은행 동기화 상태 / 가져오기 성공·부분 오류 / 파일 내보내기 구현**를 기존 Goal에 명시적으로 배정하거나 별도의 실행 가능한 Goal 명세·순서·선행 조건으로 추가했다.
- [ ] [추가 기능 구현 대기표](<../EXPANSION-BACKLOG.md>)에서 후속 구현 위치와 상태를 갱신했다. 분석 완료만으로 구현 완료를 체크하지 않았다.
- [ ] 검토 결과와 남은 차이를 남기고 소비 Goal에서 이 결과로 역참조할 수 있게 했다.
