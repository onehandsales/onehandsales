# R09 — 문서 편집기 버전·수신자 수락·서명

상태: **미착수** · 종류: 추가 분석 Goal · 실제 계정 재현: 미수행

## 1. 실행 시점과 소비 Goal

- [시작 체크리스트](<../START-CHECKLIST.md>)와 [UX/UI 재현 기준](<../UXUI-REPLICATION.md>)을 먼저 읽는다. FRONT_AGENT를 적용하며 Backend 문서·계약 확인은 현재 선행 조건에 포함하지 않는다.
- 기본 순서: 첫 소비 Goal 직전에 수행한다. 이미 확인한 자료의 재사용은 조회일·버전·적용 범위를 대조한 뒤 기록한다.
- 소비 Goal: [G36 템플릿 선택·초안 생성](<../GOAL-SPECS/G36.md>) · [G37 테마·헤더 스타일](<../GOAL-SPECS/G37.md>) · [G38 만료 설정·발송](<../GOAL-SPECS/G38.md>) · [G39 내부 수락 처리·보관](<../GOAL-SPECS/G39.md>) · [G40 기본 정보·업무 범위](<../GOAL-SPECS/G40.md>) · [G41 지급 조건·청구 설정·초안](<../GOAL-SPECS/G41.md>) · [G42 초안 투어·편집 방식 전환](<../GOAL-SPECS/G42.md>) · [G43 작성자 서명](<../GOAL-SPECS/G43.md>)
- 선행 공통 기준: [G00 근거·버전·범위 대응표](<../GOAL-SPECS/G00.md>). 실제 FE 구현 완료가 분석 착수 조건은 아니다.
- 목적: 아래 질문을 해결하여 관찰된 화면 재현과 미수록 업무 구현의 경계를 정한다. 제품 전체 조사가 끝날 때까지 독립적인 다른 기능을 멈추는 조건으로 확대하지 않는다.

## 2. 이번 분석에서 확인할 질문

이번 R은 화면·상태·상호작용을 보완한다. 아래 질문 중 API·DB·서버 처리·실계정 검증은 후속 메모로 분류한다. 그 답을 기다리며 관찰된 UX/UI 구현을 멈추지 않으며 실제 API나 외부 서비스를 연결하지 않는다.

- [ ] 구형 Proposal/Contract와 새 Document Builder의 적용 대상을 먼저 정한다.
- [ ] 빈 문서·템플릿·PDF·블록·가격표·수신자별 필드/서명을 확보한다.
- [ ] 작성자 서명·내부 수락·고객 수락/서명·거절·철회·수정 후 재발송을 구분한다.
- [ ] 수락 가능 만료일과 공유 링크 수명, 서명 후 문서 snapshot을 대조한다.

- 자료가 없으면 관찰 사실을 채워 넣지 않고 화면 대기·문서 근거·목 가정을 구분한다.

## 4. 완료 산출물과 필수 체크

- [ ] 시작 역할·입력·정상 종료·취소·실패·권한·재진입의 흐름 표를 작성했다.
- [ ] 확인한 자료와 미확인 항목, 구형/현행 충돌, 채택한 목 가정을 구분했다.
- [ ] 필드·관계 ID·상태·저장 경계·금액/시간·권한의 FE 요구를 작성했다. 실제 endpoint·DB 제약은 확정하지 않았다.
- [ ] 위 소비 Goal의 범위·입력·수용 기준·체크리스트를 분석 결과와 함께 갱신했다.
- [ ] 후속 구현 범위 **새 편집기 / 고객 수락·서명 / 수신자 링크 lifecycle 구현**를 기존 Goal에 명시적으로 배정하거나 별도의 실행 가능한 Goal 명세·순서·선행 조건으로 추가했다.
- [ ] [추가 기능 구현 대기표](<../EXPANSION-BACKLOG.md>)에서 후속 구현 위치와 상태를 갱신했다. 분석 완료만으로 구현 완료를 체크하지 않았다.
- [ ] 검토 결과와 남은 차이를 남기고 소비 Goal에서 이 결과로 역참조할 수 있게 했다.

## 5. 결과 기록

| 항목 | 현재 상태 |
| --- | --- |
| 신규 자료 조회·계정 관찰 | 미수행 |
| 근거 URL·조회일·버전 | 이번 분석 실행 시 작성 |
| 확정한 FE 범위·목 가정 | 미작성 |
| 미해결 질문과 영향받는 행동 | 위 체크리스트 전체 대기 |
| 후속 구현 Goal 및 명세 링크 | 미배정; 위 소비 Goal과 확장 대기표가 추적 책임을 가짐 |
| 검토 판정·검토일 | 미검토 |

완료 판정: 질문별 처리 근거, 소비 명세 갱신, 후속 구현 배정, 검토 결과가 모두 있어야 한다. 화면 자료가 부족하면 해당 UI의 확인 범위를 기록한다. 서버/API/DB 정책은 후속 메모로 남기며 조사 미완료를 이유로 기존 시안의 FE 구현을 보류하지 않는다.
