# Goal 착수·종료 체크리스트

> 현재 상태 — 2026-11-23 KST G00: **R4 근거·색인·배정 재검토 완료 / 촬영 조건·요소 분석·시각 동일성 후속 대기**. [확인 범위·정합성·잔여 담당](../RESULTS/G00_RESULT.md#g00-recheck). 현재 [원본 동일 재현 기준](UXUI-REPLICATION.md#current-identity)을 적용하며 아래의 작은 시각 차이 허용은 과거 정책이다. G01의 동작 보완 이력과 시각/환경 대기를 유지한다. 이번 G00은 문서만 보완했으며 evidence·임시 산출물·새 결과 문서를 만들지 않았다. 다음 Goal은 자동 시작하지 않는다.

> 이전 G01 재검토 기록 — 2026-11-23 KST G01 재검토: **G01 공통 모달 2종 결함 보완·목 동작 검증 수행 / 엄격한 시각 동일성 대기**. 이번 G01·직접 연결 검증에서는 작은 폰트·크기·픽셀 차이를 허용하지 않는다. 과거 구현/체크는 당시 이력이며 다른 G/R의 전체 완료로 승격하지 않는다. [결과·체크·미완·직접 확인](../RESULTS/G01_RECHECK_RESULT.md). G32 이후 미착수, 실제 API/BE/DB 작업·push·배포 없음.

> 과거 계획 반영 기록 (이번 G01 수용 기준 아님) — 2026-11-23 KST: **R4 분석의 계획 반영**. [보완 대응표](SOURCE-ANALYSIS-IMPACT.md)를 먼저 읽는다. G01~G31의 기존 구현·검증 이력은 유지하며 R4 현재 구현 대조는 미실행이다. [현재 흐름 기준](FLOW-BEHAVIOR-REVIEW.md#policy)에 따라 행동·상태·저장·전환을 우선 대조한다. 폰트·크기·픽셀의 작은 차이는 허용한다. G32 이후 구현은 미착수이며 이 문서 변경만으로 재개하지 않는다. [이번 문서 검토](../RESULTS/SOURCE_ANALYSIS_PLAN_REVIEW.md).

각 Goal 실행 시 아래 항목을 해당 Goal 결과에 복사하고 실제 근거를 붙인다. 이 파일의 빈 체크는 전체 구현의 미완료 상태를 뜻한다.

## 착수 전에

이번 G00 적용 결과는 [기존 결과의 현재 재검토 절](../RESULTS/G00_RESULT.md#g00-recheck)에 항목별로 기록한다. 원본·코드의 읽기 전용 조사와 문서 무결성 검사는 수행하되, 코드 변경·앱/브라우저 실행·시각 비교는 N/A다. 아래 범용 체크를 이유로 evidence·캡처·임시 파일·새 결과 문서를 만들지 않는다. 누락된 과거 증거는 현재 검증으로 대체 계산하지 않는다.

- [ ] 사용자 요청의 Goal과 허용 범위, 제외 경로, 현재 Git 변경을 확인했다.
- [ ] [FRONT_AGENT](../../../AGENT/SOFTWARE_AGENT/FRONT_AGENT/README.md)와 [UX/UI 재현 기준](UXUI-REPLICATION.md)을 읽었다. Backend·API·DB 문서의 설계/확정을 현재 작업의 선행 조건으로 두지 않는다.
- [ ] [순서표](GOAL-WORK-ORDER.md)의 선행 G 결과·차이·검증 근거를 확인했다. 문서 존재만으로 구현 완료를 간주하지 않았다.
- [ ] 해당 G 명세 2절의 R 체크리스트를 전부 확인했다. 분석 전이면 R을 먼저 수행하고, 결과·출처·소비 명세 변경·검토 판정을 연결했다.
- [ ] R의 질문을 화면 보완과 후속 서버 메모로 나눴다. API·DB·실계정 정책 미확인이 관찰된 화면 제작을 막지 않게 했다.
- [ ] 원본 ANALYSIS의 2~8절과 이미지·단계 순서·버전, [추가 구현 대기표](EXPANSION-BACKLOG.md)를 읽었다. 본문 링크가 없거나 자료가 바뀌면 근거를 보완했다.
- [ ] 진입자·목표·입력·출력·route·권한·저장·취소·실패·재진입과 같은 객체를 사용하는 다른 화면을 정리했다.
- [ ] 현재 FE의 router/provider/bootstrap/query/HTTP 의존을 확인하고 목 경로에서 실제 API가 호출되지 않도록 경계를 정했다. 기존 실행·환경을 임의로 변경하지 않는다.
- [ ] 작업을 한 Goal로 검토할 수 없을 정도로 커졌으면 목적·결과가 분명한 하위 구현 명세로 분리하고 순서·색인을 갱신했다.

## 구현·검증 중

- [ ] 원본 해상도·표시 축척·구현 viewport/배율·스크롤·입력·상태를 기록하고 폰트·크기·색상·간격·배치·아이콘·플로우를 비교했다. 실제 원본 CSS viewport/DPR 미확인을 비교용 값으로 확정하지 않았다.

- [ ] 페이지는 조합, feature는 업무 UI, hook은 상태·요청, adapter는 데이터 접근을 담당한다. UI에 직접 HTTP나 중복 seed 배열을 두지 않는다.
- [ ] 컴포넌트·hook·함수별 한 줄 한글 `// 기능 : ...` 책임 주석과 복잡한 판단의 이유를 작성했다.
- [ ] 임시 입력·저장값·서버 결과를 구분하며 목 결과를 실제 발송·결제·서명 성공으로 표현하지 않았다.
- [ ] 로딩·빈 상태·검색 무결과·권한 제한·오류·pending·성공·실패 후 재시도 중 해당 상태를 검증했다.
- [ ] 키보드·포커스·직접 URL·뒤로/앞으로·새로고침·폭 변경·긴 한국어/영문·시간대·금액 표시를 확인했다.
- [ ] 해당 변경에 필요한 타입·lint·상태 전이·계산·브라우저 시나리오를 실행하고 명령·결과를 기록했다. 관련 없는 검증은 생략 이유를 남긴다.
- [ ] 네트워크에서 인증/업무/외부 서비스의 실제 요청이 없음을 확인하고 민감 정보가 로그·URL·저장소에 남지 않음을 점검했다.

## 종료 전에

- [ ] 수용 기준별 근거, 원본과의 차이, 미확인, 실제 실행하지 않은 검증을 기록했다.
- [ ] 표시 데이터·입력·전환에 필요한 로컬 목 상태만 정의했다. 서버 관련 질문은 후속 메모로 남겼으며 API 계약·DB 설계를 진행하지 않았다.
- [ ] R에서 발견된 기능은 기존 G 확장 또는 새 G 명세로 배정했으며 후속 구현 완료와 조사 완료를 구분했다.
- [ ] 관련 G/R·흐름 대응표·확장 대기표·순서표·색인·검토 상태를 갱신했다.

G83/G84는 G00~G82와 추가 구현 전부의 완료·연결 검증을 확인한다. 미배정 기능이나 필수 행동 보류가 남으면 전체 FE 완료를 선언할 수 없다. 이번 작업의 문서 체크 통과는 FE 구현 검증을 대신하지 않는다.
