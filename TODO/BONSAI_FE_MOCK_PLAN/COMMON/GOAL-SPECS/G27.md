# G27 — 댓글·활동

상태: **미착수** · 영역: **내부 업무** · 이전 대화 번호: `G19`

## 1. 목적·포함·제외

- 목표: 댓글 성공 후 목록 추가와 입력 초기화를 확인하고 시스템 활동과 사용자 댓글을 구분한다.
- 행위자: 가상 workspace의 소유자·허용된 멤버. 역할별 가시성은 근거 또는 명시한 목 시나리오로 구분한다.
- 포함: 제목의 동작과 아래 원본 단계, 연결된 R Goal에서 이번 범위로 확정한 성공·취소·실패·재진입.
- 제외: 실제 인증/업무 API 연결, 실제 발송·결제·서명·은행 동기화, DB 변경, 배포. 원본에 없는 기능은 분석 결과와 연결한 별도 구현 Goal로 등록한다.

## 3. 화면·입력·근거

- 주요 입력·표시: 댓글 본문, 작성자, 작업 ID, 활동 종류
- 페이지/feature UI는 표시·사용자 의도, hook은 상태·요청, adapter는 저장소 경계를 맡는다. 모든 신규 컴포넌트·hook·함수에 한 줄 한글 `// 기능 : ...` 책임 주석을 둔다.
- route·진입·복귀는 [전체 사용자 흐름](<../USER-FLOW.md>)을 기준으로 해당 Goal 착수 때 확정한다. 원본 URL과 우리 URL 후보를 구분한다.

- [Project detail/Adding a task/Adding a comment](<../../../../bonsai_analysis/flows/Project detail/Adding a task/Adding a comment/ANALYSIS.md>) · `1a0794d4-deb5-4eb3-b391-c7371c60e684` · 01~03단계. 4절의 화면/입력/버튼, 5절 규칙, 8절 질문을 함께 확인한다.

## 4. 목 데이터·저장·검증 경계

- 가상 ID·고정 시각·통화·역할의 시작 seed를 기록한다. 동명 객체를 같은 ID로 합치지 않는다.
- 입력 초안과 저장 결과를 구분한다. 하위 Save/전체 Save/자동 반영은 출처에 맞춰 선택하고 취소·실패 시 남는 값을 명시한다.
- 같은 객체의 목록·상세·선택지·검색·집계를 하나의 저장소에 연결한다. 이미 구현된 소비 화면은 재조회하고 아직 없는 소비 화면은 후속 Goal의 연결 검증에 남긴다.
- 조회는 초기 로딩·빈 데이터·필터 무결과·오류·권한 제한, 변경은 pending·성공·검증 오류·실패·재시도를 해당 행동에 맞게 준비한다.
- 로컬 목: [화면 상태 기준](<../MOCK-UI-STATE.md>)에 따라 표시·입력·변경을 프론트 내부에서 처리한다. API 명세·HTTP adapter·DB 스키마는 작성하지 않는다.

## 5. 기능별 완료 체크

- [ ] [UX/UI 재현 기준](<../UXUI-REPLICATION.md>)에 따라 원본과 같은 viewport에서 폰트·크기·색상·간격·배치·플로우를 비교하고 남은 차이를 기록했다.

- [ ] 댓글 성공 후 목록 추가와 입력 초기화를 확인하고 시스템 활동과 사용자 댓글을 구분한다.
- [ ] 댓글 등록 후 본문 표시와 입력 초기화를 검증한다. 자동 활동과 댓글을 구분하고 공개 범위·편집·삭제·실패를 따로 정한다.
- [ ] 정상·오류 수정 후 재시도·취소·재진입 결과와 관련 화면의 같은 ID를 확인했다.
- [ ] 직접 URL·뒤로/앞으로·키보드·모달 포커스·좁은 화면을 확인했다. 관련 없는 항목은 이유를 적었다.
- [ ] 실제 인증·업무·외부 서비스 호출 없이 목으로 동작함을 네트워크에서 확인했다.
- [ ] 변경에 맞는 typecheck/lint/상태·계산 검증/브라우저 시나리오를 실행하고 실제 결과를 기록했다.
- [ ] 원본과의 차이·남은 질문·새 데이터 요구·후속 Goal을 결과 기록에 연결했다.

## 6. 이번 기능에서 잊지 말아야 할 질문

원본 질문을 보존한 목록이다. 화면·사용자 동작은 이번 FE 범위에서 확인하고, API·DB·서버 정책·실계정 동작은 후속 메모로 남긴다. 후자의 답을 확정하는 것은 이 Goal의 착수·완료 조건이 아니다.

- [ ] 댓글이 프로젝트 고객·외부 협업자에게도 보이는가? Preview와 역할 계정으로 검증한다.
- [ ] 말줄임에는 수정/삭제가 있는가? 작성자와 다른 멤버의 메뉴를 비교한다.
- [ ] 멘션·첨부·Markdown·줄바꿈·중복 요청 처리를 추가 캡처와 API로 확인한다.
- [ ] 붉은 선이 원본 캡처 주석인지 실제 UI인지 사용자 다운로드 원본과 대조한다.
- [ ] 단계 01: 붉은 선 의미·댓글 표시 범위·빈 제출 가능성.
- [ ] 단계 02: 엔터 제출·글자 제한·자동 초안 저장.
- [ ] 단계 03: 재조회 영속성·행 메뉴·전달된 알림.

질문의 체크는 근거·선택·미해결 처리 위치를 남겼다는 뜻이다. 모든 Bonsai 동작을 검증했다는 뜻은 아니다. 관련 R Goal의 결과와 충돌하면 구현 전에 정리한다.
