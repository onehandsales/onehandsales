# G06 — 공개 템플릿·상세·파일 형식

상태: **미착수** · 영역: **공개 웹** · 이전 대화 번호: `G79`

## 1. 목적·포함·제외

- 목표: 공개 템플릿과 계정 복제본을 구분하고 Get template·파일 다운로드·가입 후 복귀를 명세화한다.
- 행위자: 익명 방문자와 가상 로그인 방문자. 역할별 가시성은 근거 또는 명시한 목 시나리오로 구분한다.
- 포함: 제목의 동작과 아래 원본 단계, 연결된 R Goal에서 이번 범위로 확정한 성공·취소·실패·재진입.
- 제외: 실제 인증/업무 API 연결, 실제 발송·결제·서명·은행 동기화, DB 변경, 배포. 원본에 없는 기능은 분석 결과와 연결한 별도 구현 Goal로 등록한다.

## 3. 화면·입력·근거

- 주요 입력·표시: 공개 템플릿 유형·업종·검색·페이지·상세·파일 형식
- 페이지/feature UI는 표시·사용자 의도, hook은 상태·요청, adapter는 저장소 경계를 맡는다. 모든 신규 컴포넌트·hook·함수에 한 줄 한글 `// 기능 : ...` 책임 주석을 둔다.
- route·진입·복귀는 [전체 사용자 흐름](<../USER-FLOW.md>)을 기준으로 해당 Goal 착수 때 확정한다. 원본 URL과 우리 URL 후보를 구분한다.

## 4. 목 데이터·저장·검증 경계

- 가상 ID·고정 시각·통화·역할의 시작 seed를 기록한다. 동명 객체를 같은 ID로 합치지 않는다.
- 입력 초안과 저장 결과를 구분한다. 하위 Save/전체 Save/자동 반영은 출처에 맞춰 선택하고 취소·실패 시 남는 값을 명시한다.
- 같은 객체의 목록·상세·선택지·검색·집계를 하나의 저장소에 연결한다. 이미 구현된 소비 화면은 재조회하고 아직 없는 소비 화면은 후속 Goal의 연결 검증에 남긴다.
- 조회는 초기 로딩·빈 데이터·필터 무결과·오류·권한 제한, 변경은 pending·성공·검증 오류·실패·재시도를 해당 행동에 맞게 준비한다.
- 로컬 목: [화면 상태 기준](<../MOCK-UI-STATE.md>)에 따라 표시·입력·변경을 프론트 내부에서 처리한다. API 명세·HTTP adapter·DB 스키마는 작성하지 않는다.

## 5. 기능별 완료 체크

- [ ] [UX/UI 재현 기준](<../UXUI-REPLICATION.md>)에 따라 원본과 같은 viewport에서 폰트·크기·색상·간격·배치·플로우를 비교하고 남은 차이를 기록했다.

- [ ] 공개 템플릿과 계정 복제본을 구분하고 Get template·파일 다운로드·가입 후 복귀를 명세화한다.
- [ ] 유형·업종·검색·페이지 필터를 분리하고 잘못된 카드 라벨을 도메인 타입으로 쓰지 않는다. 빈 썸네일과 무결과를 구분한다.
- [ ] 상세·목차·CTA를 연결한다. 이메일 Customize와 Get template의 가입 후 이동·입력 보존·앱 템플릿 대응은 추가 조사한다.
- [ ] 파일 다운로드·Google 문서·앱 가입 CTA를 각각 연결한다. 파일 수신·형식·앱 템플릿 연결은 버튼 존재와 구분한다.
- [ ] 정상·오류 수정 후 재시도·취소·재진입 결과와 관련 화면의 같은 ID를 확인했다.
- [ ] 직접 URL·뒤로/앞으로·키보드·모달 포커스·좁은 화면을 확인했다. 관련 없는 항목은 이유를 적었다.
- [ ] 실제 인증·업무·외부 서비스 호출 없이 목으로 동작함을 네트워크에서 확인했다.
- [ ] 변경에 맞는 typecheck/lint/상태·계산 검증/브라우저 시나리오를 실행하고 실제 결과를 기록했다.
- [ ] 원본과의 차이·남은 질문·새 데이터 요구·후속 Goal을 결과 기록에 연결했다.

## 6. 이번 기능에서 잊지 말아야 할 질문

원본 질문을 보존한 목록이다. 화면·사용자 동작은 이번 FE 범위에서 확인하고, API·DB·서버 정책·실계정 동작은 후속 메모로 남긴다. 후자의 답을 확정하는 것은 이 Goal의 착수·완료 조건이 아니다.

- [ ] 업종 필터·유형과의 교집합·검색/페이징·빈 결과·초기 잘못된 라벨을 확인한다.
- [ ] 썸네일 미표시가 결측 자산인지 로딩 지연인지 확인한다.
- [ ] 공개 카탈로그 ID와 앱 template API ID의 대응을 확인한다.
- [ ] 단계 01: 라벨 오류 원인·초기 선택·로딩 상태 미확인.
- [ ] 단계 02: 순서 규칙·총 개수·업종 다중 선택·누락 이미지 원인 미확인.
- [ ] 단계 03: 유형과 업종 결합·URL 상태·유형 경계 미확인.
- [ ] 단계 04: 선택 유지·업종 조건 미확인.
- [ ] 단계 05: 전체 개수·목록 끝·스크롤 로딩 방식 미확인.
- [ ] Get template와 이메일 Customize의 로그인 전후 결과·템플릿 ID 전달을 확인한다.
- [ ] 전체 미리보기·중간 설명·추가 목록의 빈 상태를 재확인한다.
- [ ] 견적과 청구서·제안서의 실제 앱 문서 유형 대응은 미정이다.
- [ ] 단계 01: 입력 방식·카드 전체 클릭 영역 미확인.
- [ ] 단계 02: 버튼의 가입/편집 이동·실제 read receipt 범위 미확인.
- [ ] 단계 03: 누적수 집계·본문 전체·템플릿 편집 동작 미확인.
- [ ] 단계 04: 작은 미리보기 세부값·실제 문서 타입·평점 출처 미확인.
- [ ] 단계 05: 추가 템플릿 빈 상태가 로딩/오류/실제0건인지 미확인.
- [ ] Get Template의 앵커 이동·파일 링크의 다운로드/새 탭/복사 동작을 확인한다.

- [ ] 공개 카탈로그·파일·API 템플릿의 ID 대응은 미확인이다.
- [ ] 단계 01: 기본 선택인지 이전 선택 유지인지 미확인.
- [ ] 단계 02: hover/click 동작·See all 대상 미확인.

- [ ] 단계 04: 버튼 후 동작은 Using invoice generator 흐름과 연결하되 같은 세션은 미확인.
- [ ] 단계 05: 다운로드 형식별 내용·동일 템플릿 대응 미확인.

- [ ] 단계 08: 형식별 다운로드와 같은 자산인지 미확인.

- [ ] 단계 10: 둘째 줄 상세 조건·앱 전용 표시의 캡처 범위 미확인.

질문의 체크는 근거·선택·미해결 처리 위치를 남겼다는 뜻이다. 모든 Bonsai 동작을 검증했다는 뜻은 아니다. 관련 R Goal의 결과와 충돌하면 구현 전에 정리한다.
