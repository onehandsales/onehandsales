# G30 — 작업 템플릿 작성

상태: **관찰 범위 목 구현·누락 보완·두 차례 검토·시각 비교·현재 회귀 검증; 자료·시각·환경 및 G31 연결 대기** · 영역: **내부 업무** · 이전 대화 번호: `G22`

## 1. 목적·포함·제외

- 목표: 하위 Save와 Save Task를 구분하고 작업이 없는 빈 템플릿도 표현한다.
- 행위자: 가상 workspace의 소유자·허용된 멤버. 역할별 가시성은 근거 또는 명시한 목 시나리오로 구분한다.
- 포함: 제목의 동작과 아래 원본 단계, 연결된 R Goal에서 이번 범위로 확정한 성공·취소·실패·재진입.
- 제외: 실제 인증/업무 API 연결, 실제 발송·결제·서명·은행 동기화, DB 변경, 배포. 원본에 없는 기능은 분석 결과와 연결한 별도 구현 Goal로 등록한다.

## 3. 화면·입력·근거

- 주요 입력·표시: 템플릿명, 구성 작업 제목·설명·파일·하위 항목
- 페이지/feature UI는 표시·사용자 의도, hook은 상태·요청, adapter는 저장소 경계를 맡는다. 모든 신규 컴포넌트·hook·함수에 한 줄 한글 `// 기능 : ...` 책임 주석을 둔다.
- route·진입·복귀는 [전체 사용자 흐름](<../USER-FLOW.md>)을 기준으로 해당 Goal 착수 때 확정한다. 원본 URL과 우리 URL 후보를 구분한다.

- [Tasks/Creating a task template](<../../../../bonsai_analysis/flows/Tasks/Creating a task template/ANALYSIS.md>) · `4c98a858-6ef7-4a6a-8e83-e626772a4df0` · 01~04단계. 4절의 화면/입력/버튼, 5절 규칙, 8절 질문을 함께 확인한다.
- [Tasks/Editing a template task](<../../../../bonsai_analysis/flows/Tasks/Editing a template task/ANALYSIS.md>) · `91a75fcf-9857-41ff-85c2-c2de0bae87d9` · 01~08단계. 4절의 화면/입력/버튼, 5절 규칙, 8절 질문을 함께 확인한다.

## 4. 목 데이터·저장·검증 경계

- 가상 ID·고정 시각·통화·역할의 시작 seed를 기록한다. 동명 객체를 같은 ID로 합치지 않는다.
- 입력 초안과 저장 결과를 구분한다. 하위 Save/전체 Save/자동 반영은 출처에 맞춰 선택하고 취소·실패 시 남는 값을 명시한다.
- 같은 객체의 목록·상세·선택지·검색·집계를 하나의 저장소에 연결한다. 이미 구현된 소비 화면은 재조회하고 아직 없는 소비 화면은 후속 Goal의 연결 검증에 남긴다.
- 조회는 초기 로딩·빈 데이터·필터 무결과·오류·권한 제한, 변경은 pending·성공·검증 오류·실패·재시도를 해당 행동에 맞게 준비한다.
- 로컬 목: [화면 상태 기준](<../MOCK-UI-STATE.md>)에 따라 표시·입력·변경을 프론트 내부에서 처리한다. API 명세·HTTP adapter·DB 스키마는 작성하지 않는다.

## 6. 이번 기능에서 잊지 말아야 할 질문

원본 질문을 보존한 목록이다. 화면·사용자 동작은 이번 FE 범위에서 확인하고, API·DB·서버 정책·실계정 동작은 후속 메모로 남긴다. 후자의 답을 확정하는 것은 이 Goal의 착수·완료 조건이 아니다.

- [ ] 중복 이름을 허용하는가? 같은 이름으로 두 번 생성해 확인한다.
- [ ] 템플릿 소유 범위와 편집권한은 개인/팀 중 무엇인가? 역할별 조회를 대조한다.
- [ ] 이름 입력 길이·공백 정규화·서버 오류 문구를 확인해야 한다.
- [ ] 단계 01: 템플릿 보유 여부·사용 권한·빈 목록의 정확한 조건.
- [ ] 단계 02: 이름필수·중복·최대길이·닫기취소 의미.
- [ ] 단계 03: 엔터제출·중복요청 방지·생성권한.
- [ ] 단계 04: 연필 편집 결과·여러 템플릿 간 선택 방식.
- [ ] 빈 템플릿에서 Edit 모달이 뜨는 정확한 진입은 무엇인가? New Task 클릭부터 재현해 누락 단계를 보완한다.
- [ ] 하위 Save 후 모달을 닫으면 항목이 남는가? 저장 범위·취소 의미를 검증한다.
- [ ] 템플릿에서 첨부 삭제·작업 삭제 시 이미 생성한 실제 작업은 어떻게 되는가? 복제/공유 정책을 확인한다.
- [ ] 첨부 파일 형식·크기·실패·여러 개 업로드 상태를 추가 이미지로 확인한다.
- [ ] 단계 01: 연필 편집 결과·여러 템플릿 간 선택 방식.
- [ ] 단계 02: 신규/기존 항목 여부와 입력 기본값.
- [ ] 단계 03: 제목 필수 여부·중복 제한·입력 길이.
- [ ] 단계 04: 파일 카드 상태별 아이콘·첨부 권한·스토리지 참조.
- [ ] 단계 05: 미리보기 렌더링과 실제 업로드 완료의 관계·하위 Save의 저장 범위.
- [ ] 단계 06: 체크박스가 템플릿의 기본 완료값인지 실제 실행 상태인지.
- [ ] 단계 07: 드래그 정렬·하위 항목 삭제·다중 깊이 지원 여부.
- [ ] 단계 08: 펼친 상세 내용·새로고침 후 첨부와 하위 항목 보존.

질문의 체크는 근거·선택·미해결 처리 위치를 남겼다는 뜻이다. 모든 Bonsai 동작을 검증했다는 뜻은 아니다. 관련 R Goal의 결과와 충돌하면 구현 전에 정리한다.
