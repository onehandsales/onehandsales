## 1. 목적·포함·제외

- 목표: 계약 01~12단계의 조건부 필드와 초안을 유지하고 지급 조건 단계로 넘긴다.
- 행위자: 가상 workspace의 소유자·허용된 멤버. 역할별 가시성은 근거 또는 명시한 목 시나리오로 구분한다.
- 포함: 제목의 동작과 아래 원본 단계, 연결된 R Goal에서 이번 범위로 확정한 성공·취소·실패·재진입.
- 제외: 실제 인증/업무 API 연결, 실제 발송·결제·서명·은행 동기화, DB 변경, 배포. 원본에 없는 기능은 분석 결과와 연결한 별도 구현 Goal로 등록한다.

## 4. 목 데이터·저장·검증 경계

- 가상 ID·고정 시각·통화·역할의 시작 seed를 기록한다. 동명 객체를 같은 ID로 합치지 않는다.
- 입력 초안과 저장 결과를 구분한다. 하위 Save/전체 Save/자동 반영은 출처에 맞춰 선택하고 취소·실패 시 남는 값을 명시한다.
- 같은 객체의 목록·상세·선택지·검색·집계를 하나의 저장소에 연결한다. 이미 구현된 소비 화면은 재조회하고 아직 없는 소비 화면은 후속 Goal의 연결 검증에 남긴다.
- 조회는 초기 로딩·빈 데이터·필터 무결과·오류·권한 제한, 변경은 pending·성공·검증 오류·실패·재시도를 해당 행동에 맞게 준비한다.
- 로컬 목: [화면 상태 기준](<../MOCK-UI-STATE.md>)에 따라 표시·입력·변경을 프론트 내부에서 처리한다. API 명세·HTTP adapter·DB 스키마는 작성하지 않는다.

## 6. 이번 기능에서 잊지 말아야 할 질문

원본 질문을 보존한 목록이다. 화면·사용자 동작은 이번 FE 범위에서 확인하고, API·DB·서버 정책·실계정 동작은 후속 메모로 남긴다. 후자의 답을 확정하는 것은 이 Goal의 착수·완료 조건이 아니다.

- [ ] 국가·사업체 형태별 입력 필수 여부와 지원 범위를 실제 폼 검증으로 확인한다.
- [ ] deposit=0 허용 안내와 오류가 동시에 보이는 단계의 해소 시점 및 서버 저장값을 확인한다.
- [ ] 시급 $20 표시와 생성 예정 Invoice $20의 계산 관계, 실 작업시간 반영 시점을 확인한다.
- [ ] 별도 Dashboard 활동에는 생성·서명·발송 사건이 구분되어 있다. 본 플로우 마지막 목록의 Sent에 이르기까지 생략된 서명·발송 조작과 계약 ID를 대조한다.
- [ ] 표준 조건 변경이 본문과 생성된 청구서에 어떤 범위로 전파되는지 확인한다.
- [ ] 단계 01: 날짜와 집계의 기준 시간대, 그래프 산식, 타임라인 아이콘의 정확한 날짜 의미, 역할별 접근 권한, 홍보 노출 조건은 이 이미지로 확인할 수 없다.
- [ ] 단계 02: See Sample 결과와 빈 상태 판단 조건은 미확인.
- [ ] 단계 03: 선택 항목의 초기값 출처, 미선택 검증은 미확인.
- [ ] 단계 04: 템플릿 목록의 전체 항목·선택 방식은 미수록.
- [ ] 단계 05: 추천 기준·사용자별 개인화는 미확인.
- [ ] 단계 06: 고객 변경 시 프로젝트 자동 초기화 규칙은 중간 화면이 없어 미확인.
- [ ] 단계 07: Owner의 실제 기본값 여부, 각 빈 값의 검증은 미확인.
- [ ] 단계 08: 국가 변경 시 주 초기화·지원 지역은 미확인.

- [ ] 단계 11: 첨부 크기/형식·텍스트 길이 제한·빈 값 검증은 미확인.
- [ ] 단계 12: 자동 저장 여부와 이전 단계 복귀 시 보존은 미확인.
