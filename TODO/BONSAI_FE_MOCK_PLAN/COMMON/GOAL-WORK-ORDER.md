G는 기반·FE 구현·검증, R은 추가 분석이다. 번호는 이번 계획의 고정 식별자이며 실제 실행은 아래 순번과 선행 조건을 따른다. 로그인 전 공개 웹을 앞쪽에 배치해 이전 대화의 번호를 재정렬했다. 이전 번호로 요청받으면 해당 행의 현재 번호·제목을 함께 확인한다.

## 실행 규칙

모든 G는 프론트 UX/UI와 로컬 목 작업이며 모든 R은 화면·상호작용 보완이다. Backend/API/DB 작업은 없고 서버 정책 확정을 기다리지 않는다. [UX/UI 재현 기준](UXUI-REPLICATION.md)을 우선한다.

1. [시작 체크리스트](START-CHECKLIST.md) → 해당 명세 → 원본 분석을 읽고 한 번에 한 Goal을 실행한다.
2. R을 처음 소비하는 G 앞에 분석을 배치했다. 이후 같은 R을 쓰는 G도 결과·유효 범위·남은 질문을 다시 체크한다.
3. 첫 R 배치는 최소 선행 시점이다. 공식 자료를 먼저 조사할 수 있으나, 선행 목 UI 없이 모든 제품을 한 번에 확정하려 하지 않는다.
4. 원본 단계 소유가 없는 공통 Goal과 한 플로우를 나눈 Goal이 있으므로 문서 수를 Goal 수와 동일시하지 않는다.
5. R 결과에 새 기능이 있으면 기존 G를 확장하거나 새 G 명세를 추가하고 표·의존성·색인을 갱신한다. R04/R19/R22처럼 현재 직접 구현 Goal이 없는 기능은 아래 최종 검증 전에 반드시 구현 자리를 만든다.
6. G83은 G00~G82 및 추가 배정 구현 전체의 검증 결과가 필요하다. R 조사만 마친 상태에서 통합 완료로 넘어가지 않는다.
7. 85 G + 22 R은 현재 작업 단위다. 전체 기능을 85개 안으로 제한하지 않는다. 상태 변경은 실제 결과를 남긴 후 명세·표·색인에 함께 반영한다.

## R4 반영 이후의 현재 실행 전제

기존 107개 G/R 실행 순서는 식별자·선행 관계와 수행 이력으로 보존한다. 현재 먼저 할 작업은 [흐름·상태·저장 대응→명세 보완→기존 구현 영향 검토](SOURCE-ANALYSIS-IMPACT.md#workflow)다. 이 절은 위 역사적 실행 규칙의 즉시 재개보다 우선한다.

G01~G31은 전부 다시 구현하는 목록이 아니다. 대조 결과가 있는 항목만 공통 요소→관련 기능 순서로 보완 작업을 구성하고 기존 G와 결과에 연결한다. 새 기능이 발견된 경우에만 기존 확장 규칙으로 실행 명세를 배정한다. G32/R07의 순번 자체는 바꾸지 않지만 현재 분석·검토 전제 충족과 사용자의 실행 요청 없이 시작하지 않는다.
