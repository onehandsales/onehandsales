# 현재 작업 범위와 Bonsai UX/UI 재현 기준

> 현재 작업 — 2026-11-23 KST G01 재검토: **G01 공통 모달 2종 결함 보완·목 동작 검증 수행 / 엄격한 시각 동일성 대기**. 이번 G01·직접 연결 검증에서는 작은 폰트·크기·픽셀 차이를 허용하지 않는다. 과거 구현/체크는 당시 이력이며 다른 G/R의 전체 완료로 승격하지 않는다. [결과·체크·미완·직접 확인](../RESULTS/G01_RECHECK_RESULT.md). G32 이후 미착수, 실제 API/BE/DB 작업·push·배포 없음.

> 과거 계획 반영 기록 (이번 G01 수용 기준 아님) — 2026-11-23 KST: **R4 분석의 계획 반영**. [보완 대응표](SOURCE-ANALYSIS-IMPACT.md)를 먼저 읽는다. G01~G31의 기존 구현·검증 이력은 유지하며 R4 현재 구현 대조는 미실행이다. [현재 흐름 기준](FLOW-BEHAVIOR-REVIEW.md#policy)에 따라 행동·상태·저장·전환을 우선 대조한다. 폰트·크기·픽셀의 작은 차이는 허용한다. G32 이후 구현은 미착수이며 이 문서 변경만으로 재개하지 않는다. [이번 문서 검토](../RESULTS/SOURCE_ANALYSIS_PLAN_REVIEW.md).

현재 작업은 **프론트 UX/UI만**이다. Gummble MCP로 확보한 Bonsai 화면·플로우를 PM·UXUI 결과물로 보고, 프론트 개발자가 실제 화면을 만들어 연결한다. [FRONT_AGENT](../../../AGENT/SOFTWARE_AGENT/FRONT_AGENT/README.md)와 [결정 006](../../../AGENT/SOFTWARE_AGENT/FRONT_AGENT/DECISIONS/006_bonsai_uxui_only_phase.md)을 모든 G/R에 적용한다.

## 구현 범위

- 로그인 전 공개 페이지, 가입·로그인·온보딩, 내부 업무, 고객 공유 화면의 시각 요소와 상호작용을 전부 로컬 목으로 구현한다.
- 실제 인증·세션·workspace·업무 데이터·파일 업로드·메일·결제·외부 서비스 API는 연결하지 않는다. HTTP adapter·API 계약·DB 스키마·Backend 작업도 현재 범위에 없다.
- Gummble MCP 조회는 시안 확인이다. 제품 FE의 API 연결과 구분한다.
- 추가 분석 R은 부족한 화면·상호작용을 보완한다. 서버 정책·DB 제약·실계정 검증의 미확인은 나중에 확인할 메모이며, 관찰된 화면 제작을 막는 조건이 아니다.

## 화면마다 확인할 값

| 영역 | 원본과 비교할 항목 |
| --- | --- |
| 타이포그래피 | font family, weight, size, line-height, letter-spacing, 줄바꿈·정렬 |
| 색상 | 페이지/패널 배경, 본문·보조 텍스트, 테두리, 강조, 상태별 버튼·입력 |
| 치수·배치 | 헤더/사이드바·본문 폭, 열·행 높이, 버튼·입력·모달 크기, padding·gap·margin |
| 세부 표현 | radius, border, shadow, 아이콘 크기·선 굵기·정렬, 이미지 비율 |
| 화면 상태 | 기본·선택·hover·focus·disabled·오류·빈 결과·로딩·열림/닫힘 |
| 플로우 | 진입·클릭·입력·저장 표현·취소·다음 화면·뒤로·재진입·스크롤 |

각 Goal에서 Flow ID·Screen ID·시안 버전·비교 viewport를 먼저 기록한다. 이미지 픽셀 크기를 CSS px로 단정하지 않는다. 정확한 폰트명·색상·수치를 확인할 근거가 없으면 시각 추정값과 미확인을 명시하고, 대조 후 보정한다. 원본 확인 없이 특정 폰트나 token을 정답으로 확정하지 않는다.

공통 token과 컴포넌트로 일관되게 재현한다. 기존 FE의 디자인이 다르면 Bonsai 원본에 맞춘다. 임의 리디자인·문구 교체·다른 버전 혼합은 하지 않는다. 좁은 화면과 키보드 접근은 FRONT_AGENT 규칙으로 확인하며 원본에서 보이지 않은 동작은 목 가정으로 기록한다.

## 화면 완료 체크

- [ ] 원본을 직접 보고 폰트·크기·색상·간격·배치·문구·아이콘을 대조했다.
- [ ] 원본 이미지 해상도·비교 표시 크기/축척·구현 viewport/배율·스크롤·입력·상태를 기록하고 비교했다. 원본 CSS viewport/DPR가 미확인이면 비교 조건의 추정 여부를 남겼다.
- [ ] 클릭·입력·팝업·전환·취소·재진입이 로컬 목으로 연결된다.
- [ ] 컴포넌트·hook·함수별 책임과 한글 주석, 상태 소유권을 FRONT_AGENT에 맞췄다.
- [ ] 실제 API 요청이 0건임을 네트워크에서 확인했다. 요청 실패를 미연결 증거로 사용하지 않았다.
- [ ] 남은 시각·동작 차이를 해당 Goal 결과에 기록했다. 목 완료와 실제 서비스 성공을 구분했다.

## 나중에 할 일

프론트 UX/UI 전체가 완성된 뒤, 완성한 결과물과 Bonsai 공식 도움말·공식 API 문서를 근거로 DB 스키마와 Backend를 별도 설계한다. 현재 계획에 Backend 구현 Goal을 추가하거나 기능별로 API 연결을 끼워 넣지 않는다.

## G01에서 남긴 원본 확인 항목

[G01 비교](../RESULTS/G01_RESULT.md)는 공통 요소 범위다. 정확한 폰트 family/파일·아이콘 SVG는 미확인이고 Outfit/Lucide는 근사값이다. R01에서 공개 웹과 내부 앱의 버전을 분리해 출처를 확인하고 R02/G11·R03/G19에서 소비 화면의 줄바꿈·크기를 재비교한다. 현재 공개 웹 CSS의 폰트를 과거 내부 캡처에 소급 적용하지 않는다. 원본 동일성 대기를 전체 화면 완료로 바꾸지 않는다.

## R4 분석과 요소별 수용 기준

[원본 기준의 12개 영역](../../../bonsai_analysis/SOURCE_ANALYSIS_STANDARD.md)과 [공통 명세 대기표](SOURCE-ANALYSIS-IMPACT.md#common)를 적용한다. 비교 시트의 전체 단계 확인, 요소별 정밀 대조, 재현 명세 완결, FE 실행 검증을 각각 판정한다.

기능마다 Flow ID→단계/Screen ID→영역/요소 ID→문구·스타일·상태·자산→분석 위치→담당 G→수용 기준→검증 근거를 추적한다. 배경과 작은 글자·아이콘을 포함하고 불명확한 부분은 원본 해상도로 다시 확인한다. OCR 후보·원본 픽셀·추정 폰트를 실제 CSS·정확한 font family로 확정하지 않는다. 자료 밖 hover/focus/모바일/취소/실패는 명시적 목 가정과 분리한다.

공통 요소를 고치면 소비 화면과 변형별 상태를 검토한다. 이전에 충족한 업무 로직과 테스트 결과를 지우지 않으며 새 결함 근거 없이 전체 기능을 다시 만들지 않는다. 문서 반영은 시각 동일성이나 새 실행 통과가 아니다.

각 G의 기존 체크에 있는 “원본과 같은 viewport”는 위 비교 조건 기록 기준으로 적용한다. 2880×1800 PNG를 1440×900으로 표시했다고 실제 CSS viewport=1440 또는 DPR=2가 확인된 것은 아니다. 과거 체크와 수치는 수행 이력으로 보존하며 원본 캡처 환경 확인의 증거로 사용하지 않는다.

[요소 대응표 필드](SOURCE-ANALYSIS-IMPACT.md#element-trace)와 [완료 판정](SOURCE-ANALYSIS-IMPACT.md#completion)을 적용한다. 메모 연결, 요소별 분석, 명세 완결, 구현 검증을 분리하고, 원본의 재현 필수 미확정을 기록만 한 상태에서 명세 완결로 판정하지 않는다. 공통 수정 전에는 [공유 화면 영향](SOURCE-ANALYSIS-IMPACT.md#shared-screens)과 실제 컴포넌트 소비 범위를 함께 확인한다.

## 과거 계획 반영 당시 수용 기준 — 2026-11-23 KST (이번 G01에는 적용하지 않음)

[흐름 검토와 현재 판정](FLOW-BEHAVIOR-REVIEW.md#policy)을 위 시각 동일성 관련 안내보다 우선한다. 폰트·크기·픽셀의 작은 차이는 허용하고 기록한다. 정확한 폰트 파일·배경 계수·세부 치수의 미확인만으로 흐름 작업을 보류하지 않는다. 입력·선택·필수/오류 표시·행동·저장·취소·분기·종료와 관련 화면 영향은 일치해야 한다. 제어가 가려지거나 경고 의미가 달라지면 시각 차이 허용 대상이 아니다.

기존 G 체크의 “같은 viewport에서 폰트·크기·색상·간격·배치·플로우 비교”는 비교 조건과 차이를 남기는 절차다. 픽셀 동일성을 현재 완료의 필수 조건으로 해석하지 않는다. R4의 요소 전수성·정밀 재현 인증과 기존 결과는 보존하며 이번에는 실제 구현을 재판정하지 않았다.

## G01 재검토의 엄격한 동일성 기준 — 2026-11-23 KST

이번 G01과 직접 연결 검증은 폰트·글자 크기·색·치수·배치·아이콘·입력/상태/흐름을 원본과 동일하게 재현해야 한다. 작은 차이도 완료로 허용하지 않는다. 미확인 폰트·자산·촬영 조건은 추정 또는 대기로 남기고, 독립적인 동작 수정·검증은 계속한다. 원본 PNG를 바꾸지 않고 원본 해상도·비교 축척·구현 viewport/DPR·배율·스크롤·입력·상태를 기록한 픽셀 비교가 필요하다. 위 과거 정책과 체크 이력은 보존하며 이번 시각 동일성 완료의 증거로 쓰지 않는다.

이번 적용 체크 6항목과 엄격 동일성 대기는 [G01 결과 5·8절](../RESULTS/G01_RECHECK_RESULT.md)에 구분했다.
