# User Web 구현 기준과 검증

상태: 계획. 코드·브라우저 실행 검증은 후속 Goal에서 수행한다.

## 기반과 책임

[UX/UI 재현 기준](../COMMON/UXUI-REPLICATION.md)에 따라 Gummble의 Bonsai 시안을 구현한다. 폰트·크기·색상·간격·배치·플로우의 원본 비교를 각 Goal의 완료 조건으로 둔다. 실제 API는 인증을 포함해 전부 연결하지 않는다.

- G00/G01에서 현재 router·provider·세션 초기화·query cache·HTTP client·SEO 생성기의 의존을 추적한다. 실제 BE 없이 공개/가상 인증/업무/외부 수신자 경로가 실행되는 구조를 마련한다.
- 페이지는 route parameter와 화면 조합, feature UI는 업무 표시·사용자 의도, hook은 조회/변경·상태 전이, data-source adapter는 데이터 접근을 맡는다.
- 같은 객체의 원본은 한 목 저장소에 두며 여러 페이지에 독립 배열을 복제하지 않는다. 가상 ID·관계·시각·역할 seed는 재현 가능해야 한다.
- 여러 페이지가 쓰는 버튼·입력·모달·메뉴·표는 공통화하고, 업무 규칙이 다른 컴포넌트를 props 분기만 늘린 하나의 거대 컴포넌트로 합치지 않는다.
- 기존 파일 구조는 [FRONT_AGENT](../../../AGENT/SOFTWARE_AGENT/FRONT_AGENT/README.md)와 [컴포넌트 설계](../../../AGENT/SOFTWARE_AGENT/FRONT_AGENT/CONVENTION/COMPONENT_DESIGN.md)를 따른다. 대규모 파일 이동은 실제 필요 범위로 제한한다.

## 한글 주석

컴포넌트·hook·함수 선언의 책임을 한 줄 한글 `// 기능 : ...`로 설명한다. 복잡한 계산·타이머·상태 전이·저장 경계는 왜 그 처리가 필요한지 별도 한 줄씩 설명한다. JSX 안에서는 문법에 맞는 주석을 사용한다. 줄마다 문법을 반복 해설하거나 구현과 다른 주석을 남기지 않는다. [주석 정본](../../../AGENT/SOFTWARE_AGENT/FRONT_AGENT/CONVENTION/COMMENT_AND_LOGGING.md)을 적용한다.

## 상태와 웹 동작

조회·저장·취소·재시도, 빈 목록·검색 무결과, draft·saved, modal/popup·선택 상태를 구분한다. 목록·상세·검색·집계는 같은 저장 결과를 반영한다. 타이머의 닫기/정지, 시간의 Draft/Billed/Paid, 내부 수락/고객 동의 등은 원본의 의미를 유지한다.

검색·필터·정렬·페이지·선택 상태의 URL/메모리 보존 기준을 기능별로 정한다. 직접 URL·새로고침·뒤로/앞으로·없는 객체·권한 제한을 검증한다. 좁은 화면·긴 콘텐츠·키보드·포커스·Escape·스크롤·입력 label·오류 연결은 [웹 접근성 기준](../../../AGENT/SOFTWARE_AGENT/FRONT_AGENT/CONVENTION/WEB_ACCESSIBILITY_AND_LAYOUT.md)을 따른다.

실제 인증 토큰이나 사용자 비밀번호를 목 데이터로 복사하지 않는다. 목 모드의 시나리오 선택·리셋은 개발 도구 위치에 두고 일반 제품 화면에 내부 데이터 저장 구조를 설명하는 UI를 넣지 않는다.

## 단계별 검증

| 시점 | 확인할 내용 |
| --- | --- |
| G01 | BE를 중단/호출 차단한 조건의 독립 실행, 가상 세션, seed/reset, 실패 시나리오 |
| G02~G09 | 공개 페이지 직접 진입, 메뉴 목적지, 콘텐츠·입력·CTA 전달, 반응형/키보드 |
| G10~G14 | 공개 탐색→가입/로그인→온보딩/목적지→로그아웃, 보호 route·만료·복귀 |
| 각 업무 Goal | 실제 입력·저장·취소·실패·재조회·관련 화면 ID·계산·권한 시나리오 |
| 외부 수신자 Goal | 다른 역할·공유 링크·만료/취소·수신 결과의 내부 반영 |
| G83/G84 | 전 영역 연결, 추가 구현 누락, 역할·웹 품질·회귀·남은 차이 |

실행 명령은 `FE/user-web`에서 현재 `package.json`을 확인한 뒤 선택한다. 현재 확인한 기본 명령은 `pnpm.cmd typecheck`, `pnpm.cmd lint`, `pnpm.cmd test`, `pnpm.cmd build`, `pnpm.cmd test:e2e`다. 변경에 맞는 계산/상태 테스트와 브라우저 시나리오를 실행하고 결과를 기록한다. 가벼운 문서 변경에 앱 테스트를 강제하거나 구현을 그대로 복사한 테스트를 만들지 않는다.

목 검증에서는 네트워크에 실제 인증·업무·결제·메일·은행 호출이 없는지 확인한다. 실서버 저장·계정 재현·외부 서비스 성공은 별도 후속 검증이다. 완료 기록에는 수행한 명령/시나리오·결과·미실행·차이를 남긴다.
