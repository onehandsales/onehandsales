# 사이드바 UX 통일 기획 검토

- 일자: 2026-10-24
- 판정: 통과 — 구현 착수 가능
- 대상: 사용자 확정 요청, 현재 SidebarNav/AppShell, 기존 업무 목록 E2E, API 표시 기준

Frontend 규칙에 따라 feature/API/Query 경계를 유지하면서 화면 표시만 단순화한다. 기존 관리 항목을 실제 UI 기준으로 사용하고, 로딩·데이터 존재·빈 배열·최초 조회 실패·캐시 데이터가 있는 실패의 동작을 명시했다.

새 도메인 정책이나 route/API 변경은 없다. 기존 E2E를 변경된 UX에 맞춰 갱신하고 관련 검증을 수행한다. 최초 구현 문서는 완료 이력으로 유지하고 이번 사용자 요청을 새 작업으로 기록한다.

## 구현 완료 검토

- 판정: 통과
- AppShell의 업무 목록 오류/재시도 전달과 SidebarNav의 전용 안내·상태 wrapper를 제거했다.
- 로딩 분기·Skeleton·추가 버튼 표시가 관리 항목과 같은 구조다. 빈 배열은 null을 반환한다.
- 행 크기·간격과 hover 배경·글자·아이콘 색상을 관리 항목과 비교했다.
- 기존 업무 목록 E2E를 새 요청에 맞춰 갱신했다. 성공·hover·로딩·빈 배열·최초 조회 실패·접힘·Workspace 전환과 기존 헤더의 관련 5건이 통과했다.
- typecheck/lint/단위 테스트 33개/build가 통과했다. 기존 build chunk 크기 경고 외 신규 실패·경고는 없다.
- Backend/API/DB schema, Query/인증 client, 관리 항목 기능·route 변경과 커밋은 없다.
- 알려진 기존 생성 모달 테스트 2건은 이번에 재실행하거나 변경하지 않았다. 실제 Backend 별도 smoke는 실행하지 않았다.
