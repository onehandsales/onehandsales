- 상태: 후속 구현 설계. 신규 API는 관련 계약이 confirmed 된 이후 연결한다.

## 1. 현재 구현과 보존할 UX

- 현재 shared header 모델의 선택 `viewDefinitionId`와 `viewType`을 사용한다.
- 초기 헤더 응답 `viewId`의 기존 변환을 유지한다. 전체 API 필드를 일괄 이름 변경하지 않는다.
- `crm-view`의 API client/query key/hooks를 재사용하고 외부에서는 공개 barrel로 접근한다.
- 한 줄 헤더, 기존 보기 설정의 264px 팝업·레이아웃 행·평평한 체크박스·구분선·로컬 미리보기 안내를 유지한다.
- 필터·정렬의 기존 편집 UI를 읽기 전용 기술 목록으로 바꾸지 않는다.
- 현재 저장되지 않는 미리보기와 실제 조회/저장의 상태를 구분한다. 한국어·영어 문구와 접근성을 함께 반영한다.
- MAP `목록 정렬`의 기존 메뉴 연결은 존재한다. 원본 데이터·대시보드 편집 버튼과 주 화면 실행 완료를 주장하지 않는다.
- Admin Web은 이 계획의 소비자가 아니다.

## 2. 타입별 동작

| 타입 | 버튼 | 데이터 동작 |
| --- | --- | --- |
| CHART/PIVOT | 원본 데이터 | A03 호출. 구간 클릭은 같은 원본 흐름에 선택 문맥 전달 |
| MAP | 목록 정렬 | 기존 A01로 저장 설정 표시. 실제 정렬은 주 화면 조회 계약에 연결 |
| DASHBOARD | 대시보드 편집 | 기존 A02 응답/캐시를 편집 초안으로 사용 |
| DASHBOARD 편집 중 | 위젯 추가 | D10에 따라 기존 View 목록 또는 A04 |
| DASHBOARD 편집 중 | 취소 / 저장 | 취소는 로컬 초안 폐기. 저장은 후속 A05 |

버튼 표시를 위해 신규 API를 매번 선호출하지 않는다. 표시 타입과 실제 API 지원·권한은 별도이며, FE에서 버튼을 숨기는 것이 서버 검증을 대체하지 않는다.

## 3. 원본 목록

1. 현재 View와 유효 설정이 저장 상태인지 초안인지 확인한다.
2. D08이 저장 상태 조회만 허용하면 미저장 조건이 적용된 것처럼 표시하지 않는다. 실행 초안을 지원하면 확정된 preview 계약을 사용한다.
3. 헤더 버튼은 전체 구간, 차트/피벗 클릭은 D06에서 확정한 선택 문맥으로 조회한다.
4. 응답의 View·행 기준·열 key로 표시한다. List는 ListEntry ID로 행을 구분한다.
5. 로딩·정상 빈 목록·실패를 분리한다. 반환된 행이 없다고 모든 집계 숫자를 0으로 바꾸지 않는다.
6. 기록 클릭은 원본 Record와 List 업무 맥락을 보존하는 상세 흐름에 연결한다. 집계값을 직접 수정하지 않는다.

패널 위치·원본 표시 열·타입별 값/참조명은 D09와 주 화면 UX에서 확정한다. sample 응답의 amount 같은 key를 실제 고정 CRM 필드로 만들지 않는다.

## 4. MAP 목록 정렬

- A01의 정렬 규칙 순서·방향을 기존 팝업에서 표시한다.
- 규칙 변경 후 적용은 D08의 초안 실행 또는 별도 저장 계약에 맞춘다.
- 서버에서 한 페이지만 조회한 뒤 FE가 정렬해 전체 순서처럼 보여주지 않는다.
- 필터/정렬 변경 시 기존 커서·페이지를 초기화한다.
- 핀 좌표는 정렬로 변경하지 않는다. 좌표 미확인 기록도 목록에서 확인할 수 있게 한다.
- 전체 정렬 속성 후보는 A01의 참조 메타데이터와 다르다. Object의 기존 속성 조회와 List/참조 경로 후보의 부족한 계약을 구분한다.

## 5. 대시보드 편집 상태

```text
조회
→ 편집 진입: 저장 구성의 별도 초안 생성
→ 이동/크기/제목/숨김 변경: 초안만 수정
→ 위젯 추가: 후보 조회 및 선택
→ 취소: 초안 폐기, 저장 구성으로 복귀
→ 저장: 중복 제출 제어
   ├─ 성공: 응답의 저장 구성 반영, 편집 종료
   ├─ 충돌: 초안 보존, 최신 상태와 재조정
   └─ 실패: 초안 보존, 실패 종류에 맞춰 재시도
```

- query cache를 초안 편집으로 직접 변형하지 않는다. refetch가 수정 중 초안을 덮어쓰지 않게 한다.
- 숨긴 위젯과 같은 원본의 여러 위젯을 보존한다. 렌더 key와 변경 대상은 위젯 ID다.
- 아직 저장하지 않은 위젯의 임시 ID와 서버 ID 대응, 재요청 식별은 D13을 따른다.
- View/Workspace 변경 중 초안의 처리 UX는 D08/D12와 함께 정한다. 다른 View에 초안을 적용하지 않는다.
- 원본 위젯 결과의 실패와 대시보드 설정 조회 실패를 구분한다. 설정이 깨졌는데 임의 빈 대시보드를 만들어 저장하지 않는다.
- 대시보드의 소속 List/필터를 모든 원본 View에 자동 전달하지 않는다.
- 원본 View의 설정 변경 기능을 위젯 배치 편집에 섞지 않는다.

## 6. 캐시·요청·검증

- 메뉴 조회는 기존 사용자/Workspace/View/menu key, 활성 메뉴 시점 조회, 취소·지연 응답 처리 방식을 유지한다.
- 본문/원본 key는 사용자·Workspace·View·유효 설정·선택 구간·페이지를 구분한다. 데이터/설정 revision이 도입되면 의미에 맞게 반영한다.
- 원본 닫기·View 전환 시 요청 취소와 오래된 응답 무시를 처리한다.
- 저장 완료 후 해당 settings·구성과 관련 결과 캐시를 갱신한다. 후속 refetch 실패를 이미 성공한 저장 실패로 알리지 않는다.
- 사용자별 권한과 401/403/404를 구분하고 이전 View 데이터를 새 View의 정상 결과처럼 보여주지 않는다.

확인할 사용자 시나리오:

- 11개 타입에서 세 버튼 노출 규칙, 기존 필터·설정·즐겨찾기 회귀.
- CHART/PIVOT 전체/셀/합계/빈 값 그룹 선택과 View 빠른 전환.
- 동일 Record의 여러 ListEntry 행 선택과 상세 맥락.
- MAP 여러 페이지의 정렬, 동률, 좌표 없는 기록.
- 대시보드 숨긴 위젯·중복 원본·저장 취소·충돌·응답 유실 재시도.
- 좁은 화면의 헤더/팝업, Escape·외부 클릭·focus 복귀, 한국어/영어.

Frontend 함수·component·hook·handler에는 `// 기능 : ...`, API/상태 전환에는 번호 주석을 둔다. 실제 client/typecheck/lint/unit/build와 관련 Playwright를 변경 범위에 맞게 검증한다. mock E2E와 실제 Backend/DB 검증 결과를 구분한다.
