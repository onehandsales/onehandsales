# 보기 설정 사용자 흐름

기준: [TODO Software Agent Reference](../../../AGENT/PM_AGENT/CONVENTION/TODO_SOFTWARE_AGENT_REFERENCE.md), [API 계약](API-SPEC/VIEW_CONFIGURATION_API.md). 이 문서는 구현 후 재검토에서 기존 승인 행동을 구체화한 기록이다.

1. 로그인한 Workspace 멤버가 관리항목·업무목록 또는 즐겨찾기 View에 들어간다. TABLE/KANBAN/LIST는 설정 GET으로 한 번의 저장 기준을 읽는다.
2. 필터·정렬·보기 설정 팝오버와 TABLE 컬럼에서 변경한다. 메뉴를 닫거나 화면 폭이 바뀌어도 같은 임시 입력을 유지한다. 250ms 뒤 POST 미리보기로 본문에 적용한다.
3. `보기 설정 저장`을 누르면 변경한 section 전체를 PATCH한다. 같은 보기에서 중복 저장과 추가 편집을 막는다. 다른 보기의 편집은 가능하다.
4. 성공하면 서버 버전으로 기준을 교체하고 같은 사용자/Workspace/View의 본문·페이지 token·메뉴를 갱신한다. 재방문·새로고침에도 저장값을 사용한다.
5. `변경 되돌리기`는 DB 쓰기 없이 저장 기준을 복원한다. 실패하면 입력을 유지한다. 409이면 `내 변경을 버리고 최신 설정 사용`을 명시적으로 선택한다. 최신 조회 도중 새로 입력한 값은 늦은 응답으로 지우지 않는다.
6. 보기 이동은 이전 초안을 해제한다. 진행 중인 저장은 요청 당시 View에만 반영하고 새 화면의 초안·성공 메시지·본문 캐시를 바꾸지 않는다. 브라우저를 닫을 때 미저장 경고를 등록한다.

빈 결과는 조건 변경 안내, 조회 실패는 재시도, 미지원 8개 타입은 준비 중 안내를 표시한다. 같은 View 사용자에게 공유됨을 저장 영역에서 알린다. 기존 승인된 TABLE/칸반 화면을 재사용하며 모바일 기본 레이아웃 전환은 이 변경의 범위가 아니다. 새 전역 Company/Deal 모델이나 역할 등급을 도입하지 않는다.
