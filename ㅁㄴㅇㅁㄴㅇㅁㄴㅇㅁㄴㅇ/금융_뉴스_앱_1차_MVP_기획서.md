# 금융 뉴스 앱 1차 MVP 기획서

작성일: 2026년 11월 16일  
상태: 제품 방향과 1차 기능 범위 및 모바일 개발 기술 확정, 세부 정책과 나머지 기술 선택은 일부 미정  
서비스 이름: 미정

해외 경제·금융 뉴스를 RSS로 수집하고, 사실 요약과 앙드레 코스톨라니의 투자 관점을 적용한 해설을 제공하는 모바일 앱을 만든다. 같은 내용을 초등학생·중학생·고등학생·성인 수준으로 바꾸어 읽을 수 있으며, 각 수준에 맞는 예시를 함께 제공한다.

첫 목표는 개발자 본인이 매일 읽고 싶은 콘텐츠 앱을 실제로 사용하는 것이다. Kotlin과 Spring Boot를 활용한 개발·운영 경험을 쌓고 금융 관련 기업으로의 이직 포트폴리오로도 활용한다. 우선 1차 MVP를 완성하고, 다음 기능은 직접 사용하고 운영한 뒤 결정한다.

## 두 프로젝트의 구분

| 프로젝트 | 목적과 형태 | UX 참고 기준 |
| --- | --- | --- |
| OneHandCRM | 기존 CRM 프로젝트. 현재는 웹으로 개발 | folk. 화면 조사 도구는 Nicelydone 사용 |
| 금융 뉴스 앱 | 별도 사이드 프로젝트. React Native로 개발하는 iOS·Android 모바일 콘텐츠 앱 | 실제 Medium 모바일 앱 |

이 문서는 금융 뉴스 앱의 기획서다. 저장 위치가 OneHandSales 저장소 안에 있더라도 CRM의 기능·기술·UX 기준을 변경하는 결정은 아니다. 기존 CRM을 Kotlin으로 마이그레이션하는 작업도 포함하지 않는다.

## 확정한 제품 방향

- 사용자가 글을 읽는 것만으로도 가치를 얻는 정보 전달형 앱으로 만든다.
- 영어 학습 기능을 결합하지 않고, 경제·금융 콘텐츠에 집중한다.
- Articler를 콘텐츠 공급 기반으로 사용하지 않고 RSS 기사 수집을 출발점으로 삼는다.
- 사용자용 서비스는 모바일 앱으로 제공한다. iOS와 Android를 대상으로 한다.
- 모바일 클라이언트는 React Native로 개발한다. 두 플랫폼에서 공통 코드를 활용하고, 플랫폼별 설정·빌드·동작은 각각 확인한다.
- 백엔드는 Kotlin과 Spring Boot를 사용한다.
- 콘텐츠 표현과 생성 프롬프트는 초기 버전을 만든 뒤 계속 개선한다.
- 1차 MVP의 중심은 콘텐츠다. 모의투자 도입 여부는 1차 이후에 결정한다.

사용자는 1차 MVP의 개발 목표를 약 1주일로 보고 있다. 이는 목표 기간이며, 앱 스토어 심사·공개 배포까지 포함한 확정 일정은 아니다.

## 콘텐츠가 만들어지고 읽히는 흐름

콘텐츠 처리의 기본 순서는 다음과 같다. 수집 주기, 발행 방식, 생성 시점의 세부 정책은 구현 전에 정한다.

1. RSS에서 기사와 출처 정보를 가져온다.
2. 이미 수집한 기사와의 중복을 정리한다.
3. 확보한 기사 내용에서 확인 가능한 사실과 근거를 정리한다.
4. 코스톨라니의 투자 관점을 적용한 해설을 작성한다.
5. 동일한 핵심 내용을 4가지 난이도와 각각의 예시로 구성한다.
6. 발행된 콘텐츠를 앱의 피드와 상세 화면에서 제공한다.

사용자는 홈에서 글을 고르고, 원하는 난이도로 읽은 뒤 좋아요를 누르거나 북마크할 수 있다. 저장한 글은 나중에 다시 읽는다. 비로그인 상태에서 허용할 범위와 로그인 요청 시점은 별도 정책으로 정한다.

## 콘텐츠 한 편의 구성안

| 순서 | 내용 | 작성 기준 |
| --- | --- | --- |
| 1 | 무슨 일이 있었나 | 기사에서 확인한 사건과 핵심 사실을 요약 |
| 2 | 왜 중요한가 | 사건의 배경, 원인, 관련 근거 설명 |
| 3 | 코스톨라니 관점으로 해석하면 | 정리된 투자 원칙을 현재 사건에 적용한 해석 |
| 4 | 어떤 영향을 생각해 볼 수 있나 | 현금·예금·주식·부동산 등과 연결되는 일반적인 영향과 조건 |
| 5 | 생활 속 예시 | 선택한 난이도에 맞는 구체적인 상황으로 설명 |
| 6 | 생각해 볼 점 | 독자가 살펴볼 변수, 다른 가능성, 판단할 때 참고할 질문 |
| 7 | 출처 | 기사 제목, 매체, 원문 링크, 기사 날짜 등 확보한 근거 |

1차에서는 사용자의 실제 보유 자산이나 재무 상황을 입력받아 분석하지 않는다. 자산에 대한 설명은 콘텐츠 안에서 다루는 일반적인 사례와 영향이다.

기사로 확인한 사실과 AI가 적용한 해석을 구분한다. 전망에는 성립 조건과 불확실성을 표현하며, AI가 작성한 문장을 코스톨라니의 실제 발언이나 현재의 의견으로 표시하지 않는다.

### 코스톨라니 관점의 기준

기준 자료는 사용자가 지정한 『돈, 뜨겁게 사랑하고 차갑게 다루어라』 관련 1~3권 전체다. 실제 자료 준비 시 권별 제목과 판본을 확인하고, 사용할 원칙과 해당 근거를 정리한다. 현재 대화에서 책 본문이나 발췌 자료를 전달받아 분석한 상태는 아니다.

책에서 정리한 원칙과 그 원칙을 기사에 적용한 AI 해설을 구분한다. 특정 인물의 말투를 흉내 내는 것보다, 어떤 원칙을 어떤 근거에 적용했는지 설명하는 데 초점을 둔다.

## 4가지 읽기 난이도

난이도는 설명의 수준을 뜻한다. 실제 사용자 연령을 수집하거나 나이에 따라 이용을 제한하는 정책으로 확정한 것은 아니다. 네 버전 모두 같은 기사와 핵심 사실을 다루고, 어휘·설명의 깊이·예시를 다르게 구성한다.

| 난이도 | 설명 방식 | 예시의 소재 |
| --- | --- | --- |
| 초등학생 | 어려운 용어를 풀고 짧은 문장으로 설명 | 용돈, 저금통, 물건 사고팔기 |
| 중학생 | 기본 경제 용어를 소개하고 원인과 결과를 연결 | 저축, 소비 계획, 원하는 물건 구매 |
| 고등학생 | 금리·물가·기업 활동의 관계를 단계적으로 설명 | 아르바이트 수입, 학비 계획, 작은 사업 |
| 성인 | 경제 변수와 자산·소비·대출에 미칠 영향을 조건별로 설명 | 예금, 대출, 주식, 주거비, 가계 지출 |

다음은 설명 수준을 구분하기 위한 가상 예시다. 실제 발행 기사나 코스톨라니의 발췌문이 아니다.

**가정한 주제: 기준금리 인상 소식과 돈을 빌리는 비용의 변화**

| 난이도 | 설명 예시 |
| --- | --- |
| 초등학생 | 돈을 빌릴 때 더해서 갚는 돈을 이자라고 해. 이 부담이 커지면 사람들은 물건을 살 돈을 빌리기 전에 한 번 더 생각할 수 있어. |
| 중학생 | 대출 이자가 오르면 같은 금액을 빌려도 갚아야 할 돈이 늘 수 있어. 사고 싶은 물건을 당장 사기보다 저축해서 나중에 사려는 사람이 늘어날 수 있지. |
| 고등학생 | 금리 변화는 가계 소비뿐 아니라 기업의 투자 비용에도 영향을 줄 수 있어. 작은 가게가 돈을 빌려 새 기계를 사려 할 때 이자 부담이 커지면 구매를 미룰 수 있는 것과 비슷해. |
| 성인 | 변동금리 대출의 이자 부담, 예금 조건, 기업의 자금 조달 비용에 영향을 줄 수 있다. 다만 실제 반영 시점과 크기는 계약 조건과 시장 상황에 따라 다르다. |

실제 콘텐츠에는 이러한 수준별 예시와 함께 해당 기사의 사실, 해석, 근거가 들어간다. 단순히 어려운 단어를 바꾸는 것만으로 네 버전을 완성한 것으로 보지 않는다.

## 모바일 UX 기준과 초기 화면 구성

금융 뉴스 앱의 UX 참고 기준은 실제 Medium 모바일 앱이다. 기사 탐색과 본문 읽기에 집중하고, 난이도 전환과 금융 해설을 서비스의 차별점으로 추가한다.

Medium 모바일 화면 자료는 사용자가 직접 찾기로 했다. 자료를 전달받은 뒤 실제 화면을 기준으로 배치와 상호작용을 구체화한다. Nicelydone에 Medium 모바일 화면이 확보되어 있다고 전제하지 않는다.

| 화면 | 역할 | 포함할 요소 |
| --- | --- | --- |
| 홈 | 읽을 콘텐츠 탐색 | 기사 목록, 최신순·인기순·추천순 선택 |
| 기사 상세 | 콘텐츠 읽기 | 난이도 전환, 본문, 예시, 출처, 좋아요·북마크 |
| 저장한 글 | 다시 읽을 콘텐츠 관리 | 북마크 목록, 기사 상세 이동 |
| 내 정보 | 계정 이용 | 로그인 상태와 계정 관련 설정 |

이는 초기 화면 구성안이다. 하단 탭 수, 로그인 화면 배치, 글꼴, 색상, 카드 크기와 같은 세부 UI는 모바일 참고 화면을 보고 정한다. 계정 설정의 구체적인 항목도 미정이다.

## 콘텐츠 운영에서 정할 사항

RSS를 사용한다는 방향은 확정했지만 구체적인 매체·피드 목록과 초기 수집 범위는 아직 정하지 않았다. 일부 RSS가 제목이나 짧은 요약만 제공할 수 있으므로, 확보한 내용만으로 어느 수준까지 분석하고 발행할지 정해야 한다.

프롬프트는 초기 버전부터 개선한다. 기사에 없는 사실을 추가하지 않고, 확인된 사실과 해석을 구분하며, 네 난이도 사이의 핵심 내용이 일치하는지를 콘텐츠 확인 기준으로 삼는다. 원문과 이미지의 이용 가능 범위도 출처를 선정할 때 확인한다.

수집·생성·발행을 모두 자동으로 할지, 발행 전에 사람이 확인할지는 아직 확정하지 않았다. 같은 원칙으로 기사 수정·삭제와 생성 실패 시 처리 방식도 정한다.

## 1차 MVP 완료 확인 항목

아래 항목은 구현 결과를 확인할 때 사용할 기준이다. 현재 구현 완료를 뜻하지 않는다.

- 선정한 실제 RSS 기사로 콘텐츠 수집부터 발행·열람까지 이어진다.
- 동일한 콘텐츠를 네 난이도로 읽을 수 있고 각각에 맞는 예시가 제공된다.
- 기사 사실, AI 해석, 원문 출처를 독자가 구분할 수 있다.
- 구글 로그인과 좋아요·북마크가 동작하고, 저장한 글을 다시 열 수 있다.
- 최신순·인기순·추천순과 조회수가 정한 정책에 맞게 동작한다.
- React Native 앱을 iOS와 Android 각각에서 빌드하고, 로그인·기사 탐색·본문 읽기 흐름을 확인한다.
- 개발자가 실제 콘텐츠를 지속적으로 읽으며 개선할 수 있는 상태가 된다.

## 1차 이후의 결정

2차 MVP의 기능은 확정하지 않았다. 모의투자는 여러 확장 후보 중 하나다. 이전에 이야기한 실제 종목·차트, 국내·미국 시장, 가상 1,000만 원은 모의투자를 선택할 경우 다시 검토할 아이디어로 남긴다.

따라서 가상 계좌·주문·보유 종목·시세 연동을 1차의 선행 작업으로 만들지 않는다. 먼저 직접 읽고 운영하면서 콘텐츠의 유용성, 북마크, 재방문과 사용자 반응을 살펴본 뒤 콘텐츠 개선에 집중할지 다른 기능으로 확장할지 결정한다.
