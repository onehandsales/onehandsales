# CRM 관련 제품 비교 이력

조사 기준일: 2026-11-16

> Historical — 현재 기준은 Bonsai 전체 재현 후 차별화이며 UX 조사 도구는 Gummble이다. 아래 타사 비교는 과거 조사 기록으로 보존하며 이번 작업에서 최신 기능을 재검증하지 않았다. 현재 기획·구현 기준으로 추가하지 않는다.

**서비스별 차이만 같은 기준으로 비교한 표다.** 공통 기능과 용어는 [CRM 공통 개념](CRM_공통개념.md)에 모았다. 제품명을 누르면 근거 자료를 볼 수 있고, 전체 출처는 [공식 문서와 확인 범위](CRM_공식문서_출처.md)에 있다.

업무 예시는 공식 자료의 기능을 적용한 **가상 상황**이다. 실제 계정에서 실행한 화면 안내는 아니다. ‘청소 사업에 대입하면’은 현재 들은 사례에 대한 해석이며, 현재의 Bonsai 재현 범위를 정의하는 기능 명세는 아니다.

## 비슷해 보여도 구분할 부분

| 헷갈리기 쉬운 비교 | 차이를 이해하는 기준 |
| --- | --- |
| **Apollo · Wiza · Surfe** | Apollo는 **대상 발굴에서 순차 연락까지**, Wiza는 **연락 가능한 정보 확보**, Surfe는 **웹에서 찾은 정보를 CRM으로 옮기기**에 초점을 두고 비교하면 쉽다. 기능이 서로 겹칠 수 있다. |
| **Rox · Mutinyhq · Lightfield** | Rox는 **기업을 조사하고 영업 근거 준비**, Mutinyhq는 **미팅 이후 고객용 자료 준비**, Lightfield는 **연결된 대화에서 고객 맥락과 약속 찾기**라는 상황으로 구분한다. |
| **Bonsai · Assembly · Capsule · Arrows** | Bonsai는 **무엇을 얼마에 합의할지**, Assembly는 **고객과 어디서 자료를 주고받을지**, Capsule은 **성사된 거래를 어떻게 수행할지**, Arrows의 도입 계획은 **고객과 무엇을 함께 준비할지**라는 질문에 연결한다. |

위 구분은 이해를 돕기 위해 강조점을 비교한 것이다. 각 제품의 기능 범위가 이 한 가지에만 한정된다는 뜻은 아니다.

| [Clay → Mesh](https://me.sh/for/creators) | 이 문서의 Clay는 관계 관리 제품이며 현재 공식 도착지는 me.sh다. 영업 데이터 서비스 Clay.com과 구분한다. |
| [Bonsai](https://help.hellobonsai.com/en/articles/15879228-document-builder-overview) | 현재 문서 작성 도구와 과거 제안서의 청구 자동화 동작을 구분한다. 가격표·서명 기능 확인만으로 옵션 자동 계산이나 변경 승인까지 확인한 것은 아니다. |
| [Distrobird](https://appsumo.com/products/distrobird/) | 최신 공식 사이트는 접근 제한으로 조회하지 못했다. **2023-09-11 AppSumo에 게시된 창업자 설명**을 사용했다. 최신 공식 도움말로 검증한 제품과 근거 수준이 다르다. |
| [Arrows](https://arrows.to/) | 비교표의 근거는 공개된 고객 도입 계획 도움말이다. 현재 홈페이지는 거래별 계획·자료·후속 업무를 수행하는 영업 AI도 강조한다. 두 범위를 한 버전의 동일한 UX로 섞지 않는다. |

기능 사용 조건도 별개다. 예를 들어 Apollo의 이메일 시퀀스는 메일함 연결·활성화가 필요하고, Capsule의 프로젝트 자동 생성은 규칙 설정이 필요하다. Surfe의 정보 보강은 CRM에 추가하기 전에도 가능하다. 표의 예시를 모든 계정에서 설정 없이 실행되는 흐름으로 해석하지 않는다.

## 누나의 사업에서는 무엇을 먼저 비교할까?

같은 청소 사업이라도 **가장 어려운 업무**에 따라 참고할 제품이 달라진다. 아래는 비교 관점이며 최종 추천 순위가 아니다.

| 실제로 가장 어려운 일 | 먼저 관찰할 업무 | 관련 제품 예 |
| --- | --- | --- |
| 새로운 법인 고객을 찾기 | 대상 검색, 담당자 정보 확보, 후속 접촉 | Apollo, Wiza, Surfe |
| 문의 전화를 놓치거나 다시 정리하기 | 전화 응대와 요청 내용 기록 | Beside |
| 고객과의 대화·약속을 기억하기 | 관계 이력, 그룹, 미팅 맥락, 다음 연락 | Clay, Lightfield |
| **서비스 범위와 항목별 가격을 문서로 합의하기** | **견적, 가격표, 계약 문서, 고객 검토** | **Bonsai** |
| 거래처와 사진·자료·계약을 한곳에서 주고받기 | 고객용 공간과 내부 업무 연결 | Assembly |
| 계약 이후 준비와 수행을 이어가기 | 영업 기회와 프로젝트, 공동 준비 계획 | Capsule, Arrows |
| 청소 누락이나 재작업 요청 처리하기 | 고객 문의와 내부 담당 업무 연결 | Intercom |
| 회사마다 다른 관리 구조를 직접 구성하기 | 데이터 종류·관계·사용자 정의 업무 | Attio, Twenty |

지금 들은 문제는 **고객별로 달라지는 작업 범위와 가격 조건 관리**다. 따라서 같은 가상 거래로 **요청 정리 → 항목과 금액 표현 → 변경 → 고객과 합의**를 비교하면 된다. 이 비교는 당시의 선택 과정 기록이다. 현재는 Bonsai를 기준으로 각 단계가 기본 기능인지, 설정 또는 외부 연동이 필요한지 확인한다.
