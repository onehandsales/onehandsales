# 상태 소유권과 데이터 흐름

User Web은 아래 기준으로 상태를 배치한다. Admin Web도 소유권 원칙을 공유하지만 설치되지 않은 라이브러리를 자동으로 도입하지 않는다.

## 1. 상태를 어디에 둘 것인가

| 상태 | 기본 소유자 | 판단 기준 |
| --- | --- | --- |
| 현재 상세 ID·공유할 탭·필터·정렬·페이지 | route / search params | 링크 복사·새로고침·뒤로가기로 복원해야 하는가 |
| 열림·hover·임시 선택·표시 토글 | 가장 가까운 컴포넌트 또는 공통 부모 | 다른 화면까지 유지할 이유가 있는가 |
| 편집 중 입력·오류·dirty | 폼 hook / React Hook Form | 저장된 결과와 독립적인 초안인가 |
| 조회 결과·저장 결과·갱신 상태 | TanStack Query | 비동기 데이터 원본에서 읽거나 변경하는가 |
| session·workspace·locale·데이터 공급자 | 범위가 명확한 provider | 여러 기능이 공유하는 실행 문맥인가 |
| mock의 원본 데이터 | mock adapter의 저장소 | 화면이 재마운트되어도 같은 데이터를 읽어야 하는가 |
| 필터링 결과·합계·선택 객체 | 기존 값에서 계산 | 별도 state 없이 도출 가능한가 |

계산할 수 있는 값을 중복 state로 유지하지 않고, 편집 초안처럼 의도적으로 복사한 상태는 초기화 시점을 명시한다. [React 상태 구조](https://react.dev/learn/choosing-the-state-structure)

Context에 모든 업무 목록과 입력값을 넣지 않는다. 새 전역 상태 라이브러리는 기존 소유권으로 해결되지 않는 구체적 문제와 함께 제안한다.

## 2. URL과 폼

- URL 값을 읽을 때 허용값·기본값·범위를 검증한다. 잘못된 ID·필터는 정상적인 오류 또는 정규화 경로로 처리한다.
- 검색 입력 중 초안과 확정 검색어를 구분한다. 입력마다 history를 쌓지 않도록 replace/push 기준을 정한다.
- 필터 변경 시 페이지·선택 항목 처리 기준을 명시한다. URL의 상태를 별도 state와 effect로 양방향 복제하지 않는다.
- search params는 새 값을 만들어 라우터 setter로 반영한다. setter 없이 객체만 변경하지 않는다. 변경은 내비게이션을 발생시킨다. [React Router 7](https://reactrouter.com/7.18.6/api/hooks/useSearchParams)
- 상세 ID가 바뀌면 폼 초안을 이전 ID에 저장하지 않는다. 서버/fixture 갱신으로 사용자의 dirty 입력을 조용히 덮어쓰지 않는다.
- 취소·닫기·route 이탈 시 초안 유지 또는 폐기 동작을 기능별로 정한다. 모든 폼에 일괄 확인창을 강제하지 않는다.

## 3. Query key와 캐시

- key는 해당 기능의 한 파일에서 생성한다. 결과를 바꾸는 ID·필터·정렬·페이지·실행 범위를 포함한다.
- 사용자나 workspace에 종속된 결과는 해당 식별자를 포함하고, 토큰·이메일·입력 본문 같은 비밀·개인정보는 key에 넣지 않는다.
- mock/live 캐시가 섞이지 않도록 데이터 모드를 key에 포함하거나 모드별 QueryClient를 분리한다. 모드 전환은 캐시·진행 요청을 정리한 새 실행 문맥으로 처리한다.
- 같은 기능의 목록과 상세를 구분한다. 저장 후 영향받는 상세·목록·요약만 갱신하며 무조건 전체 캐시를 비우지 않는다.
- `staleTime`, 재시도, focus refetch는 데이터 특성에 맞춘다. 인증·유효성 오류를 반복 재시도하지 않는다.
- mock 원본은 fixture store, 화면 조회 캐시는 Query다. 컴포넌트별 복사 배열을 또 만들지 않는다.

Query 함수가 사용하는 변경 가능한 조회 조건을 key에도 포함한다는 원칙은 [TanStack Query keys](https://tanstack.com/query/v5/docs/framework/react/guides/query-keys)를 따른다.

## 4. 비동기와 경쟁 조건

- query가 제공한 `AbortSignal`을 adapter와 실제 fetch까지 전달한다. mock 지연도 취소에 응답하도록 한다. [TanStack 취소](https://tanstack.com/query/v5/docs/framework/react/guides/query-cancellation)
- 로그아웃·workspace 변경 시 진행 조회를 취소하고 관련 캐시를 제거한다. 오래된 응답이 새 화면의 선택·폼·토스트를 변경하지 않게 실행 문맥을 확인한다.
- mutation 시작 시 대상 ID·workspace·입력 snapshot을 고정한다. 완료 callback에서 “현재 선택 항목”을 저장 대상으로 다시 읽지 않는다.
- 중복 제출을 막고, 실패하면 초안을 유지하여 재시도할 수 있게 한다. mutation 자동 재시도는 중복 실행 가능성을 검토한 경우에만 사용한다.
- 낙관적 갱신은 UX상 필요한 경우에만 사용한다. 이전 snapshot, 실패 복구, 동시 수정 충돌, 후속 재조회 범위를 함께 구현한다.
- 클라이언트에서 요청을 중단해도 서버 작업이 취소되었다고 단정하지 않는다. 결제·발송·서명 같은 효과는 실제 계약으로 결과 확인 방법을 정한다.
- 초기 로딩과 기존 데이터의 재조회 표시를 구분한다. 재조회 실패 시 기존 데이터와 오류 안내를 함께 보여줄 수 있어야 한다.

## 5. 표시 데이터와 전송 데이터

- API DTO, 기능 모델, 표시용 문자열을 구분한다. 모든 DTO마다 별도 클래스를 만들 필요는 없으며 실제 차이가 있을 때 변환한다.
- `null`, 누락, 빈 문자열, 숫자 0의 의미를 보존한다. `value || '-'`로 유효한 0을 지우지 않는다.
- 돈은 금액과 통화를 함께 다루고 반올림·소수 자릿수·합계 범위를 명시한다. mock 화면의 정밀도만으로 DB 타입이나 과금 정책을 결정하지 않는다.
- 날짜만 나타내는 값과 시각을 구분한다. 시각은 기존 [시간 정책](../../DB_SCHEMA/TIME_AND_TIMEZONE_POLICY.md)에 맞춰 표시 timezone으로 변환하고, 날짜 전용 값은 UTC 변환으로 하루가 바뀌지 않게 한다.
- 목록이 부분 조회라면 현재 페이지 합계를 전체 합계로 표시하지 않는다. 서버 정렬과 클라이언트 정렬을 혼합할 경우 적용 범위를 명시한다.
- 정렬 tie-breaker·검색 비교·페이지 경계는 합의한 계약을 따른다. FE에서 임의 규칙을 추가하지 않는다.

## 6. 리뷰에서 확인할 시나리오

빠르게 A → B 상세로 이동하기, 저장 중 workspace 전환, 실패 후 재시도, 필터 변경 후 뒤로가기, 다른 화면에서 변경한 항목 재진입을 확인한다. 같은 데이터와 상태 경계는 [mock 개발](MOCK_FIRST_DEVELOPMENT.md)에서도 동일하게 적용한다.
