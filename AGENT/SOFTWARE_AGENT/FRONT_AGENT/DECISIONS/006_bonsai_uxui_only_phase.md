# 006. Bonsai UX/UI 전용 구현 단계

결정일: 2026-11-20 KST · 상태: 사용자 지시 반영

## 현재 작업

Gummble MCP의 Bonsai 화면·플로우와 로컬 분석을 PM·UXUI 시안으로 삼아 프론트엔드 화면을 먼저 전체 구현한다. FRONT_AGENT의 웹 구조·컴포넌트·상태·접근성·한글 주석 규칙을 적용한다.

- Bonsai의 폰트·글자 크기·굵기·행간·색상·치수·간격·배치·아이콘·화면 전환·입력·팝업을 원본에 맞춰 재현한다. 기존 UI나 임의 디자인으로 대체하지 않는다.
- 데이터와 동작은 전부 로컬 목으로 처리한다. 로그인·가입·세션·workspace·업무 조회/저장·파일 업로드·메일·결제·외부 연동을 포함해 실제 API를 연결하지 않는다.
- Gummble MCP는 디자인 참고 자료를 확인하는 도구다. 제품 FE가 호출하는 데이터 공급자로 연결하지 않는다.
- Backend 코드·API 계약·endpoint·DB 스키마·migration은 현재 작업에 포함하지 않는다. HTTP adapter나 서버 준비를 FE 구현의 선행 조건으로 두지 않는다.
- 추가 분석은 미수록 화면·시각 값·버전 차이·화면 전환·입력/오류/취소 상태를 확인하는 FE 보완 작업이다. 서버 처리 규칙·DB 정책·실계정 재현을 끝내야 화면을 만들 수 있는 것은 아니다.
- 화면에 없는 서버 동작은 나중에 확인할 메모로 남긴다. 지금은 관찰 범위와 임시 목 시나리오를 구분해 화면을 구현한다.

## 우선순위와 검증

이번 단계에는 결정 005와 mock 개발 문서의 선택지 중 **완전 독립 목 실행**만 적용한다. 실제 로그인 유지 선택지와 기능별 API 연결 단계는 적용하지 않는다. 기존 스타일 token이 Bonsai 원본과 다르면 재현 근거에 맞춰 FE token을 조정한다.

같은 viewport에서 원본과 구현 화면을 비교하고 남은 시각 차이를 기록한다. 목 데이터로 클릭·입력·전환·취소·재진입을 검증하며, 네트워크에서 실제 API 요청이 발생하지 않는지 확인한다. 화면·상호작용 완료만 이번 단계의 완료로 판정한다.

## 후속 단계

프론트 UX/UI가 완성된 뒤 사용자가 후속 작업을 요청하면, 완성한 화면과 Bonsai 공식 도움말·공식 API 문서를 바탕으로 DB 스키마와 Backend를 별도로 설계한다. 현재 FE Goal 완료가 Backend 작업의 자동 착수 신호는 아니다.

이 결정은 작업 기준을 명시한 문서다. 기존 실행 코드·환경·API 연결을 이번 문서 수정으로 변경한 것은 아니다.
