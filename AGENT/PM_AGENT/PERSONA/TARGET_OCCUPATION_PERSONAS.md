# Target Occupation Personas

Status: Current PM Baseline
Date: 2026-09-12

## 1. 목적

이 문서는 OneHand CRM의 초기 직군 후보를 PM 관점에서 정리한다.

OneHand CRM은 모든 사용자에게 같은 영업 CRM을 제공하지 않는다. 직군별 업무 구조를 Kit으로 준비하는 것이 핵심이므로, PM은 먼저 어떤 직군의 Kit을 만들지 판단해야 한다.

## 2. 직군 우선순위

| 우선순위 | 직군 | Kit 가치 | 주의점 |
| --- | --- | --- | --- |
| 매우 높음 | 부동산 중개사 | 고객, 매물, 소유자, 방문, 계약 관계가 명확하다. | 매물 상세와 지역 데이터 범위를 과도하게 키우지 않는다. |
| 매우 높음 | 헤드헌터/채용 컨설턴트 | 후보자, 회사, 채용공고, 인터뷰, 추천 관계가 강하다. | ATS 전체 기능으로 커지지 않게 한다. |
| 높음 | 보험/재무 상담사 | 고객, 상담, 상품, 계약, 갱신과 후속 연락 니즈가 강하다. | 민감정보와 규제 표현을 조심한다. |
| 높음 | 프리랜서/컨설턴트 | 리드, 고객사, 제안, 프로젝트, 미팅 관리가 필요하다. | 일반적인 프로젝트 관리 도구처럼 보이지 않게 한다. |
| 중간 | B2B 기술영업 | 회사, 담당자, 기회, 제품, Sample, Technical Issue, Quote 관계가 뚜렷하다. | 제품이 다시 영업 전용 CRM처럼 보이지 않게 한다. |
| 중간 | 교육/코칭/상담 업무자 | 수강생, 상담, 세션, 진도, 결제 흐름이 있다. | 결제/수업 운영 범위를 MVP에 과도하게 넣지 않는다. |
| 중간 | CRM이 무거운 소규모 팀 | 기존 CRM보다 쉬운 시작 경험을 원한다. | Team/권한 요구가 커질 수 있으므로 MVP 후순위로 본다. |

## 3. 첫 Kit 후보 평가

PM 기준 첫 Kit 후보는 `부동산 중개`와 `헤드헌팅/채용 컨설팅`을 우선 검토한다.

이유:

- 단순 연락처보다 관계형 CRM 구조가 잘 드러난다.
- Kit 미리보기에서 OneHand CRM의 차별점을 보여주기 쉽다.
- 기본 Object와 Relationship을 정의하기 좋다.
- 첫 Record 생성 흐름을 명확하게 만들 수 있다.

## 4. 공통 니즈

직군은 다르지만 공통 니즈는 같다.

- 빠른 첫 기록
- 직군별 상태 관리
- 다음 행동 정리
- 여러 기록 사이의 관계 파악
- 모바일에서 핵심 정보 확인
- 처음 구조에 갇히지 않는 확장성

## 5. 제외 기준

초기 Kit에서 아래 직군은 우선순위를 낮춘다.

- 법적/의료적 민감정보가 MVP를 지배하는 직군
- 외부 시스템 연동 없이는 가치가 약한 직군
- 결제/정산/재고가 핵심이라 CRM Core보다 ERP 기능이 먼저 필요한 직군
- 첫 사용자가 10분 안에 첫 기록을 만들기 어려운 직군
