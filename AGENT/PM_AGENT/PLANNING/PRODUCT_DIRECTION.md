# Product Direction

Status: Current Product Direction
Date: 2026-09-12

## 1. 목적

이 문서는 루트 `README.md`의 제품 방향을 PM 관점에서 풀어쓴 기준 문서다.

새 PRD, MVP 범위, UX/UI 계획, Software 설계, TODO 계획을 만들 때는 이 문서를 먼저 확인한다. 이 문서는 세부 DB schema나 화면 명세가 아니라, 제품이 어떤 문제를 풀어야 하는지와 어떤 방향으로 판단해야 하는지를 정의한다.

## 2. 핵심 제품 문장

OneHand CRM의 핵심 문장은 다음이다.

> CRM을 배우거나 설계할 필요 없이, 내 일에 맞는 CRM이 바로 준비된다.

이 문장은 제품의 판매 포인트이자 PM 판단 기준이다. 기능이 이 문장을 강화하지 못하거나, 사용자가 다시 CRM 구조를 직접 공부하게 만든다면 우선순위를 낮춘다.

## 3. 제품 철학

제품 철학은 다음 문장으로 고정한다.

> Ready-made, but never locked.

의미:

- 처음 시작은 준비된 CRM처럼 쉬워야 한다.
- 사용자가 빈 화면에서 Object, Field, Relation, View를 직접 만들게 하지 않는다.
- 시간이 지나며 업무가 달라지면 구조를 확장할 수 있어야 한다.
- 확장도 설정 화면에서 데이터 모델링을 강요하는 방식이 아니라 업무 언어로 제안되어야 한다.

## 4. 하지 않는 것

OneHand CRM은 아래 제품이 아니다.

- 모든 사용자에게 같은 Company/Product/Deal 구조를 주는 고정형 영업 CRM
- 사용자가 처음부터 직접 데이터베이스를 설계해야 하는 CRM builder
- 템플릿 파일을 많이 제공하는 단순 템플릿 마켓
- 결제/구독을 먼저 붙인 뒤 제품 가설을 나중에 검증하는 판매 중심 제품

## 5. 해야 하는 것

OneHand CRM은 사용자의 직업과 업무를 이해한 뒤, 그 일에 맞는 CRM 구조를 먼저 제공해야 한다.

예:

| 직군 | 준비되어야 하는 관리 대상 |
| --- | --- |
| 부동산 중개 | 고객, 매물, 소유자, 방문, 상담, 계약 |
| 헤드헌팅 | 후보자, 회사, 채용공고, 인터뷰, 추천, Offer |
| B2B 기술영업 | 회사, 담당자, 기회, 제품, Sample, Technical Issue, Quote |
| 보험/재무 상담 | 고객, 가족/관계자, 상담, 보험상품, 계약, 갱신 |
| 프리랜서/컨설팅 | 리드, 고객사, 제안, 프로젝트, 미팅, 청구 |
| 교육/코칭 | 수강생, 상담, 과정, 세션, 진도, 결제 |

`회사`, `제품`, `딜` 같은 단어는 특정 Kit 안에서는 사용할 수 있다. 다만 OneHand CRM 전체의 고정 기본 도메인처럼 쓰면 안 된다.

## 6. 세 가지 제품 약속

### 6.1 Zero Setup

사용자는 CRM 구조를 직접 만들지 않는다.

가입 후 사용자가 해야 할 첫 결정은 "어떤 일을 하는가"에 가까워야 한다. 제품은 그 답을 바탕으로 기본 관리 대상, 상태, 관계, 보기, 첫 행동을 준비한다.

### 6.2 Work-aware

직군별 Kit은 이름만 다른 템플릿이 아니다.

좋은 Kit은 실제 업무에서 다루는 대상, 상태, 관계, 기본 화면, 다음 행동이 다르다. PM 문서는 각 Kit이 어떤 업무 문제를 해결하는지 설명해야 하며, 단순히 필드 목록만 나열하면 부족하다.

### 6.3 Infinite Expansion

사용자는 처음 제공된 구조에 갇히면 안 된다.

다만 확장은 내부 용어가 아니라 업무 언어로 제공한다.

예:

- 나쁜 표현: `Object를 생성하고 Relationship을 설정하세요.`
- 좋은 표현: `제품별로 고객을 관리하고 있는 것 같아요. 제품 관리를 추가할까요?`

## 7. PM 판단 기준

새 기능을 검토할 때 PM은 아래 질문을 먼저 확인한다.

- 이 기능은 사용자가 CRM을 배우지 않아도 되게 만드는가?
- 이 기능은 특정 직군의 실제 업무 흐름을 더 잘 반영하는가?
- 이 기능은 첫 사용자가 더 빨리 기록을 시작하게 만드는가?
- 이 기능은 고정형 영업 CRM으로 되돌아가게 만들지 않는가?
- 이 기능은 현재 MVP에서 필요한가, 아니면 후속 확장인가?
- 이 기능을 구현하기 전에 첫 Kit 또는 CRM Core 개념 결정이 필요한가?
