## 공통 상태와 완료 기준

현재 모든 기능군의 Gummble 화면 확인·실계정 검증·Bonsai 동등 구현 판정은 **대기**다. 기존 기반이 있다는 설명은 해당 기능군의 완료를 뜻하지 않는다.

하위 기능마다 다음 상태를 별도로 관리한다.

- 조사: 미수집 / 공식 문서 확인 / 화면 확인 / 계정 재현 / 자료 충돌.
- 계약: 초안 / 확정, API·DB·권한·오류·금액·날짜·삭제·중복 처리.
- 구현: 미착수 / 진행 / 코드 반영.
- 검증: 미실행 / 로컬 검증 / 외부 서비스 동작 확인 / 원본 비교 완료.
- 차이: 원본과의 차이·이유·영향·미확인 항목.

기능 완료는 화면뿐 아니라 저장·재조회·상태 전이·권한·오류까지 계약대로 검증한 경우다. mock이나 문서 확인만으로 완료 처리하지 않는다.

## 중심 검증 시나리오

같은 고객을 기준으로 거래 → 견적 → 합의 문서 → 프로젝트·작업 → 시간·비용 → 청구·부분 입금 → 고객 포털 확인을 연결한다. 이는 검증용 예시이며 모든 경로가 필수이거나 자동이라는 뜻은 아니다. 실패 거래, 견적 수정, 문서 거절/만료, 추가 작업, 일정 지연, 청구 취소, 권한 제한도 조사한다.

## 범위 운영

학습·구현 순서는 [ROADMAP](ROADMAP.md)을 따른다. 후순위 기능, API에 없는 기능, 국가·요금제 제한 기능을 목록에서 지우지 않는다. 원본의 제공 조건과 우리 구현의 결정 대기를 구분한다. 전체 목록과 차이가 검수되기 전에는 전체 복제를 완료했다고 표현하지 않는다.
