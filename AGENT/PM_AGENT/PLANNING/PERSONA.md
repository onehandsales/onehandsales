# Persona

Status: Current PM Persona Baseline
Date: 2026-09-12

## 1. 목적

이 문서는 OneHand CRM의 초기 타겟 사용자와 Jobs-to-be-Done을 정의한다.

초기 PM 판단에서는 회사 규모보다 업무 형태를 우선한다. 핵심 사용자는 CRM을 전문적으로 설계하고 운영하는 관리자가 아니라, 자기 업무를 바로 정리해야 하는 개인 또는 작은 팀이다.

## 2. 1차 핵심 페르소나

### 관계 기반 업무를 혼자 관리하는 실무자

이 사용자는 고객, 후보자, 매물, 상담, 제안, 계약, 후속 연락을 혼자 관리한다. CRM을 잘 만들고 싶은 것이 아니라, 업무 기록을 놓치지 않고 다음 행동을 이어가고 싶다.

대표 직군:

- 1인 사업자
- 개인 영업자
- 부동산 중개사
- 보험/재무 상담사
- 헤드헌터와 채용 컨설턴트
- 프리랜서와 컨설턴트
- 교육, 코칭, 상담 업무자

## 3. Jobs-to-be-Done

| 상황 | 사용자가 원하는 결과 |
| --- | --- |
| 새 고객 또는 리드가 생겼을 때 | 빠르게 기록하고 다음 연락을 놓치지 않는다. |
| 상담이나 미팅을 마쳤을 때 | 맥락과 상태를 남기고 후속 행동을 정한다. |
| 여러 대상이 연결될 때 | 고객, 매물, 후보자, 회사, 계약 같은 관계를 헷갈리지 않는다. |
| 이동 중 확인해야 할 때 | 모바일에서도 핵심 기록과 다음 행동을 빠르게 본다. |
| 업무가 바뀌거나 커질 때 | 처음 구조에 갇히지 않고 필요한 관리 대상을 추가한다. |

## 4. 행동 특성

- 고객 정보를 메신저, 노트, 스프레드시트, 연락처에 나눠 적는다.
- 기록은 하지만 다시 찾기 어렵다.
- 후속 연락을 기억이나 캘린더에 의존한다.
- CRM 설정 화면에서 멈추는 경우가 많다.
- 직업별 업무 흐름과 맞지 않는 빈 CRM에서는 시작이 늦어진다.
- 복잡한 팀 권한보다 개인의 빠른 기록과 상태 관리가 먼저 필요하다.

## 5. 제품이 해결해야 할 감정

- "어디부터 세팅해야 하지?"를 없애야 한다.
- "내 일에는 안 맞는데?"를 줄여야 한다.
- "일단 적어두긴 했는데 다시 못 찾겠다"를 해결해야 한다.
- "다음에 누구에게 연락해야 하지?"를 보여줘야 한다.

## 6. PM 요구사항

- 첫 화면은 빈 builder처럼 보이면 안 된다.
- 사용자는 자기 직업의 언어로 관리 대상을 이해해야 한다.
- 첫 기록 생성은 10분 안에 가능해야 한다.
- 모바일 확인 흐름을 후순위로 밀면 안 된다.
- Team/결제/자동화보다 Kit fit과 첫 기록 생성이 먼저다.
