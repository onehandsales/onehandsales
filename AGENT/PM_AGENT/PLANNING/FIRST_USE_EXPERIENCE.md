# 첫 사용 경험

Status: Current PM Baseline
Date: 2026-09-12

## 1. 목적

이 문서는 신규 사용자가 가입 후 처음 10분 안에 경험해야 하는 흐름을 정의한다.

OneHand CRM의 첫 사용 경험은 빈 CRM builder가 아니라, 사용자가 자기 일을 선택하면 바로 쓸 수 있는 CRM이 준비되는 경험이어야 한다.

## 2. 첫 사용 성공의 정의

첫 사용 성공은 사용자가 아래 행동을 완료한 상태다.

1. 로그인 또는 가입을 완료한다.
2. 자신의 업무 유형을 선택한다.
3. Kit이 적용된 Workspace를 확인한다.
4. 첫 Record를 생성한다.
5. 생성한 Record를 기본 List/View에서 다시 확인한다.
6. 다음에 해야 할 행동을 이해한다.

## 3. 첫 10분 원칙

첫 10분 안에는 사용자가 CRM 구조를 공부하게 만들지 않는다.

하지 않는 것:

- Object 생성부터 시키기
- Attribute/Relationship 설정부터 시키기
- 빈 dashboard를 보여주기
- "원하는 CRM을 만들어보세요"라고 말하기
- Team, billing, automation 같은 후속 기능을 먼저 노출하기

해야 하는 것:

- "무슨 일을 하시나요?"를 묻기
- 직군 또는 업무 유형을 선택하게 하기
- 선택된 Kit의 관리 대상과 기본 보기를 준비하기
- 첫 기록을 쉽게 만들게 하기
- 다음 행동을 보여주기

## 4. 권장 흐름

```text
가입/로그인
-> 업무 유형 선택
-> Kit 미리보기
-> Workspace 준비
-> 첫 기록 생성
-> 기본 보기 확인
-> 다음 행동 안내
```

## 5. 화면별 PM 요구사항

### 5.1 업무 유형 선택

목적:

- 사용자가 CRM을 직접 설계하지 않게 한다.
- 제품이 사용자의 업무 맥락을 파악한다.

PM 요구사항:

- 후보 Kit을 너무 많이 보여주지 않는다.
- 사용자가 모르는 내부 용어를 사용하지 않는다.
- `기타/직접 설명`은 둘 수 있지만 MVP에서는 정교한 AI 생성까지 포함하지 않는다.

### 5.2 Kit 미리보기

목적:

- 사용자가 "내 일에 맞는 구조가 준비된다"고 느끼게 한다.

PM 요구사항:

- 관리 대상과 관계를 간단히 보여준다.
- 너무 많은 설정 값을 노출하지 않는다.
- 사용자가 시작 전에 모든 것을 커스터마이즈하게 만들지 않는다.

### 5.3 첫 기록 생성

목적:

- activation을 만든다.

PM 요구사항:

- 첫 입력 필드는 최소화한다.
- 필수 입력은 해당 직군에서 정말 필요한 것만 둔다.
- 저장 후 사용자가 다음 화면에서 방금 만든 기록을 확인할 수 있어야 한다.

### 5.4 기본 보기

목적:

- 사용자가 기록이 어디에 쌓이고 어떻게 다시 찾는지 이해한다.

PM 요구사항:

- 목록, 상태, 최근 기록, 다음 행동 중 하나 이상을 보여준다.
- 빈 상태는 설정 안내가 아니라 첫 행동 안내여야 한다.

## 6. 직군별 첫 기록 예시

| Kit | 첫 기록 후보 | 첫 다음 행동 |
| --- | --- | --- |
| 부동산 중개 | 고객 또는 매물 | 방문 일정 잡기 |
| 헤드헌팅 | 후보자 또는 채용공고 | 인터뷰 단계 기록 |
| 보험/재무 상담 | 고객 또는 상담 | 후속 연락일 지정 |
| 프리랜서/컨설팅 | 리드 또는 프로젝트 | 제안 상태 기록 |
| 교육/코칭 | 수강생 또는 상담 | 다음 세션 일정 기록 |

## 7. 제외 범위

첫 MVP의 첫 사용 경험에서 제외한다.

- 결제/구독 유도
- 팀 초대 강제
- 고급 설정
- 자동화 builder
- 대량 import
- 모든 Kit 동시 제공
- 사용자가 내부 CRM Core 용어를 직접 조작하는 흐름

## 8. 성공 지표

- 가입 후 Kit 선택 완료율
- Kit 선택 후 Workspace 준비 완료율
- 첫 Record 생성률
- 가입 후 첫 Record 생성까지 걸린 시간
- 첫 Record 생성 후 같은 세션에서 두 번째 행동을 하는 비율
- 첫 사용 중 지원 문의 또는 이탈이 발생한 지점
