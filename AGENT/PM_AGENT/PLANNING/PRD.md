# PRD

Status: Current Product Requirements Draft
Date: 2026-09-12

## 1. 제품 정의

OneHand CRM은 사용자가 CRM을 배우거나 직접 설계하지 않아도, 자기 일에 맞는 CRM 구조를 바로 시작할 수 있게 만드는 No Setup CRM이다.

제품은 직군별 Kit을 통해 관리 대상, 관계, 필드, 상태, 기본 보기, 다음 행동을 준비한다. 사용자는 준비된 구조로 바로 기록을 시작하고, 필요해지는 순간 업무 언어로 확장할 수 있어야 한다.

## 2. 문제 정의

초기 대상 사용자는 고객, 상담, 제안, 계약, 후속 연락 같은 관계 기반 업무를 혼자 또는 작은 팀으로 처리한다. 그러나 기존 선택지는 모두 비용이 있다.

| 선택지 | 문제 |
| --- | --- |
| 스프레드시트 | 시작은 쉽지만 관계, 상태, 후속 행동, 기록 맥락이 약하다. |
| 고정형 CRM | 바로 시작은 가능하지만 특정 영업 구조에 갇힌다. |
| 자유로운 CRM/DB 도구 | 원하는 구조를 만들 수 있지만 사용자가 먼저 설계해야 한다. |

OneHand CRM이 풀어야 하는 문제는 "더 많은 기능"이 아니라 "사용자가 CRM 구조를 몰라도 자기 업무 관리가 바로 시작되는가"다.

## 3. 타겟 사용자

1차 타겟:

- 1인 사업자와 개인 영업자
- 부동산 중개사
- 보험/재무 상담사
- 헤드헌터와 채용 컨설턴트
- 프리랜서와 컨설턴트
- 교육, 코칭, 상담 업무자

2차 타겟:

- CRM이 무겁게 느껴지는 소규모 팀
- 스프레드시트로 고객/상담/계약을 관리하다가 한계를 느끼는 사용자

초기 PM 판단에서는 "팀 협업 규모"보다 "직군별 업무 구조가 뚜렷한가"를 우선한다.

## 4. 핵심 제품 요구사항

### 4.1 직군 선택 또는 업무 설명

사용자는 가입 후 자신의 업무 유형을 선택하거나 설명할 수 있어야 한다.

MVP에서는 자유 입력 AI 생성보다, 검증 가능한 후보 Kit 선택 흐름을 우선한다.

### 4.2 Kit 기반 CRM 준비

제품은 선택된 Kit에 따라 기본 CRM 구조를 준비해야 한다.

Kit은 단순 템플릿 이름이 아니라 아래를 포함한다.

- 관리 대상
- 대상 간 관계
- 필수/권장 정보
- 상태
- 기본 목록/상세 보기
- 첫 기록 예시 또는 입력 흐름
- 다음 행동 제안

### 4.3 첫 기록 생성

사용자는 Kit이 준비된 뒤 첫 기록을 바로 만들 수 있어야 한다.

예:

- 부동산 중개: 첫 고객 또는 첫 매물
- 헤드헌팅: 첫 후보자 또는 첫 채용공고
- 보험/재무 상담: 첫 고객 또는 첫 상담
- 프리랜서/컨설팅: 첫 리드 또는 첫 프로젝트

### 4.4 기본 보기와 다음 행동

제품은 기록을 만든 뒤 사용자가 다음에 무엇을 해야 하는지 보여줘야 한다.

예:

- 연락 예정
- 상담 대기
- 계약 검토
- 인터뷰 예정
- 방문 예정
- 갱신 예정

### 4.5 업무 언어 기반 확장

사용자가 추가 관리 대상이나 관계가 필요해질 때, 제품은 내부 데이터 모델 용어가 아니라 업무 언어로 확장을 제안해야 한다.

예:

- `Object 생성`이 아니라 `매물 관리를 추가할까요?`
- `Relationship 설정`이 아니라 `고객과 매물을 연결할까요?`
- `View 생성`이 아니라 `방문 예정 고객만 모아볼까요?`

## 5. 현재 구현 범위

현재 활성 구현은 제품 foundation이다.

- OAuth 로그인과 앱 세션
- 내 프로필, 연결 계정, 로그인 기기, 세션 관리
- 오류 신고, 지원 문의, 공개 문의
- 관리자 권한 확인 API
- `/app` 빈 홈과 `/app/more` 더보기 화면
- locale 기반 공개 사이트

이 범위는 제품 운영에 필요한 기반이지만, OneHand CRM의 핵심 제품 가치를 완성한 상태는 아니다.

## 6. 다음 MVP 포함 범위

다음 제품 MVP는 최소한 아래를 포함해야 한다.

- 기본 Workspace
- 첫 출시 Kit 1개 이상
- Kit 선택 또는 적용 흐름
- Kit에 포함된 Object/Attribute/Relationship 정의
- Record 생성과 조회
- 기본 List/View
- 첫 기록 생성 경험
- 빈 상태와 다음 행동

## 7. 다음 MVP 제외 범위

아래는 MVP 이후로 둔다.

- 복잡한 Team/조직 권한
- 결제/구독/Paddle checkout
- 외부 도구 양방향 연동
- 자동화 builder
- 고급 권한 matrix
- 모든 직군 Kit 동시 출시
- 사용자가 처음부터 자유롭게 모든 Object/Relation을 설계하는 builder UX

## 8. 성공 기준

MVP 성공은 기능 개수보다 activation으로 판단한다.

- 신규 사용자가 Kit 선택 후 첫 기록을 만들 수 있다.
- 사용자가 CRM 용어를 배우지 않고도 핵심 흐름을 이해한다.
- 첫 Kit이 해당 직군의 실제 업무 대상과 상태를 반영한다.
- 현재 foundation 기능이 새 CRM Core 흐름과 충돌하지 않는다.
- Company/Product/Deal 같은 단어가 전역 기본 도메인으로 되살아나지 않는다.
