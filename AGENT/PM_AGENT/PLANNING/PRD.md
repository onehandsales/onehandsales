# Product Requirements

Status: Bonsai transition PRD
Updated: 2026-11-17

## 목표와 범위

Bonsai의 기능·정보 구조·상호작용을 재현하고 전체 대응 검수 이후 차별화한다. 대표·회사 영업사원·운영·프로젝트 담당자·실무자·고객의 사용을 조사한다. 최종 업종·팀 규모는 임의로 제한하지 않는다.

| 영역 | 요구와 확인할 경계 |
| --- | --- |
| 고객·영업 | 고객 회사·담당자, 거래 단계·금액·담당자, 메모·연락 이력 |
| 견적·합의 | 서비스·단가·견적 항목, 문서 작성·템플릿·서명, 수정·버전·전송 상태 |
| 수행 | 프로젝트·작업·하위 작업·반복·기한, 시간·비용·예산, 인력 배정 |
| 청구·수금 | 청구서·항목·부분 입금·반복 청구·구독, 취소·실패·잔액 |
| 협업·포털 | 내부 멤버 권한과 고객 공유 범위, 파일·댓글·알림 |
| 조회·운영 | 사용자 필드·보기·검색·가져오기/내보내기·보고서·자동화·연동·설정 |

세부 기능과 미확인 항목은 [BONSAI_FEATURE_PARITY_MATRIX](BONSAI_FEATURE_PARITY_MATRIX.md)를 따른다. 목록은 계속 확장하며 모든 하위 기능을 이미 수집했다고 주장하지 않는다.

## 데이터·상태 요구

고객 정보, 개별 거래, 견적 원본, 발송 문서, 수행 기록, 청구와 입금의 소유·수정 범위를 구분한다. 거래 수주, 문서 서명, 프로젝트 완료, 청구서 발행, 입금 완료를 하나의 상태로 합치지 않는다. 금액·통화·반올림·날짜·시간대·재시도·중복 처리·동시 수정은 기능별 계약에 명시한다.

## 수용 기준

1. 각 화면·흐름에 공식 출처와 관찰 조건(버전·계정·권한·국가·요금제)이 연결된다.
2. 정상·빈·로딩·실패·권한 제한 및 되돌리기/취소 가능 여부를 정의한다.
3. 저장 후 재조회·새로고침·연결 화면에서 일관된 데이터를 확인한다.
4. 고객 간, Workspace 간, 내부 재무 정보와 고객 포털 사이에 정보가 누출되지 않는다.
5. 원본과의 차이·미확인·외부 실행 미검증을 별도로 남긴다.
6. 화면 mock, 로컬 구현, 외부 발송·서명·결제 검증을 구분한다.

[ROADMAP](ROADMAP.md)의 단계는 구현 순서다. 이번 변경은 문서이며 schema/API/화면을 구현한 결과가 아니다.
