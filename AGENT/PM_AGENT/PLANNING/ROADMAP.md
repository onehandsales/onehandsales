# Roadmap

Status: Proposed execution order
Updated: 2026-11-17

최종 목표는 [Bonsai 기능 대응표](BONSAI_FEATURE_PARITY_MATRIX.md)의 전체 대응 후 차별화다. 특정 Kit·업종 선정이나 고정된 전체 완료 일정을 선행 조건으로 두지 않는다.

| 단계 | 산출물 | 완료 판단 |
| --- | --- | --- |
| 0. 문서 전환 | 방향·출처·현재/목표 경계·의존 | 허용 범위 안의 상충 지침·링크 정리 |
| 1. 화면·업무 조사 | 공식 자료 + Gummble + 실계정 기록 | 기능군별 화면·버전·미확인 사항 등록 |
| 2. 중심 흐름 설계 | 고객→거래→견적→문서→수행→청구의 화면·계약 초안; 실제 프런트엔드의 임시 데이터 화면으로 검토 가능 | 역할별 행동·입력·상태·연결 검토; Figma는 필수 아님 |
| 3. 첫 수직 구현 | 고객·거래의 DB/API/FE | 저장·권한·오류·재조회 검증 |
| 4. 연결 흐름 구현 | 견적·문서·프로젝트·작업·시간·청구·입금 | 전환 전후 값·상태·중복 처리 검증 |
| 5. 전체 기능 확장 | 포털·인력·예산·보고서·자동화·연동·설정 등 | 기능별 수용 기준 및 원본 차이 검수 |
| 6. 전체 대응 검수 | 세부 기능 목록·버전별 차이·검증 증거 | 미확인·미구현·미검증 항목을 완료로 계산하지 않음 |
| 7. 차별화 | 사용자 요구에 따른 별도 개선 계획 | 재현 기준과 변경 이유를 분리해 기록 |

3~5단계는 기능별로 반복하고 데이터 이전·기존 참조 제거를 함께 수행한다. 기존 테이블을 먼저 삭제하지 않는다. Gummble 자료가 없는 기능은 공식 문서와 실계정 조사로 보완하며 조사 공백을 기록한다. 연결 대기 중에도 공식 문서 분석과 계약 초안 작성은 진행할 수 있다.

2단계도 기능별로 3~5단계와 반복한다. 전체 Figma 또는 전체 mock 완성을 개발 착수 조건으로 두지 않는다. 원본이 확보된 기능은 기존 프런트엔드에서 화면을 만들면서 계약을 구체화하고 실제 저장·조회로 연결한다. 역할별 책임과 착수 기준은 [UX 025의 Figma와 구현 착수](../../UXUI_AGENT/DECISIONS/025_uxui_bonsai_reference.md#figma와-구현-착수)를 따른다.

현재 요청은 0단계의 두 경로 문서 변경이다. 실행 코드나 외부 서비스 설정 변경을 포함하지 않는다.
