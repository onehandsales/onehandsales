# Roadmap

Status: Proposed execution order
Date: 2026-11-15

최종 범위는 [folk 기능 대응표](FOLK_FEATURE_PARITY_MATRIX.md)다. 특정 Kit 선정이나 1개월 전체 완성을 일정 전제로 두지 않는다.

| 단계 | 산출물 | 완료 판단 |
| --- | --- | --- |
| 0. 문서 정비 | 방향·현재 구현·근거·전환 영향 | 기존 활성 문서 충돌 해소 |
| 1. 화면 조사 | Nicelydone/실계정의 flow·상태·버전 | 미확인 상태와 공식 문서 차이 명시 |
| 2. 첫 흐름 설계 | mock 화면 + API/DB/권한 계약 | 등록·그룹·Table/Pipeline·상세 연결 |
| 3. 수직 구현 | 같은 흐름의 BE/FE/DB | 실제 저장·조회·권한·오류 검증 |
| 4. 기능 확대 | 메모·작업·객체·협업·연동 등 | 대응표의 기능별 완료 기준 통과 |
| 5. 기존 구조 정리 | 데이터 이전·참조 제거·migration | 삭제 영향·복구 경로 검증 |
| 6. 전체 비교 | 원본 대비 기능·UX 차이 목록 | 범위 누락 및 임의 차이 해소 |

3~5단계는 기능 단위로 반복할 수 있다. 모든 화면을 완성한 뒤 DB 의미를 처음 설계하지 않는다. 날짜·배치 크기는 조사 결과와 구현 인력에 따라 산정한다.
