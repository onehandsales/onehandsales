# 첫 사용 Flow

Status: UX Baseline
Date: 2026-09-12

## 1. 목적

이 문서는 신규 사용자가 가입 후 첫 10분 안에 OneHand CRM의 핵심 가치를 경험하게 만드는 화면 흐름을 정의한다.

핵심 목표는 사용자가 CRM을 직접 설계하지 않고, 자신의 업무에 맞는 Kit이 적용된 Workspace에서 첫 Record를 만드는 것이다.

## 2. 성공 상태

첫 사용 경험은 아래 상태에 도달하면 성공으로 본다.

1. 로그인 또는 가입을 완료한다.
2. 업무 유형을 선택한다.
3. 선택한 Kit의 구조를 간단히 확인한다.
4. Kit이 적용된 Workspace에 들어간다.
5. 첫 Record를 만든다.
6. 생성한 Record를 기본 List/View에서 다시 확인한다.
7. 다음에 할 행동을 이해한다.

## 3. 권장 화면 흐름

```text
로그인/가입
-> 업무 유형 선택
-> Kit 미리보기
-> Workspace 준비
-> 첫 Record 생성
-> 기본 보기 확인
-> 다음 행동 안내
```

이 흐름에서 사용자는 `Object`, `Attribute`, `Relationship`, `View`를 직접 설정하지 않는다.

## 4. 화면별 UX 기준

### 4.1 업무 유형 선택

목표:

- 사용자가 "CRM을 만들기"가 아니라 "내 일을 고르기"로 느끼게 한다.

화면 기준:

- 후보 Kit은 한 화면에서 비교 가능한 수로 제한한다.
- 카드 제목은 직업/업무 언어로 쓴다.
- 설명은 "무엇을 관리할 수 있는지" 중심으로 쓴다.
- `기타/직접 설명`은 둘 수 있지만 MVP에서는 완전한 자유 생성처럼 보이지 않게 한다.

### 4.2 Kit 미리보기

목표:

- 사용자가 선택한 Kit이 자기 업무를 알고 있다고 느끼게 한다.

화면 기준:

- 관리 대상, 관계, 기본 보기, 첫 행동을 짧게 보여준다.
- 설정 가능한 필드 목록을 길게 노출하지 않는다.
- "시작 전 커스터마이즈"를 강요하지 않는다.
- 미리보기는 템플릿 설명이 아니라 업무 구조 확인이어야 한다.

### 4.3 Workspace 준비

목표:

- 사용자가 빈 화면이 아니라 준비된 CRM에 들어온다고 느끼게 한다.

화면 기준:

- 준비 중 상태는 짧게 보여준다.
- 완료 후 바로 Workspace home으로 이동한다.
- "설정 완료"보다 "바로 기록할 수 있음"이 느껴져야 한다.

### 4.4 첫 Record 생성

목표:

- 가입 직후 activation을 만든다.

화면 기준:

- 첫 입력 필드는 해당 Kit에서 꼭 필요한 값만 둔다.
- 상세한 정보는 생성 이후 채우게 한다.
- 저장 후 방금 만든 Record를 바로 볼 수 있어야 한다.
- 다음 행동이 있다면 생성 결과 옆에 함께 보여준다.

### 4.5 기본 보기 확인

목표:

- 사용자가 기록이 어디에 쌓이고 어떻게 다시 찾는지 이해한다.

화면 기준:

- 기본 List/View에 새 Record가 표시되어야 한다.
- 빈 상태는 설정 안내가 아니라 첫 행동 안내여야 한다.
- 첫 Record 이후의 다음 행동을 지나치게 강요하지 않는다.

## 5. 모바일 기준

모바일 첫 사용은 데스크톱보다 더 짧고 선형이어야 한다.

- 업무 유형 선택 카드는 1열 목록을 우선한다.
- Kit 미리보기는 관리 대상과 첫 행동 중심으로 접어 보여준다.
- 첫 Record 생성은 긴 form보다 단계가 짧은 입력 흐름을 우선한다.
- 저장 후 목록과 상세 사이 이동이 분명해야 한다.

## 6. 제외 범위

첫 사용 UX에서 제외한다.

- Object/Field/Relation builder
- Team 초대 강제
- 결제/구독 유도
- 자동화 builder
- 대량 import
- 모든 Kit 동시 제공
- 고급 권한 설정
