# Kit 선택 UX

Status: UX Baseline
Date: 2026-09-12

## 1. 목적

이 문서는 사용자가 자기 업무에 맞는 Kit을 선택하고, 선택한 Kit이 어떤 CRM 구조를 준비하는지 이해하게 만드는 UX 기준을 정의한다.

Kit 선택은 OneHand CRM의 첫 제품 경험이다. 사용자는 CRM 구조를 직접 만드는 대신 자신이 하는 일을 고른다.

## 2. 기본 원칙

- Kit은 템플릿 목록처럼 보이면 안 된다.
- 사용자는 `Object`, `Attribute`, `Relationship`을 선택하지 않는다.
- Kit 설명은 기능보다 업무 상황을 먼저 말한다.
- "자유롭게 만들기"보다 "내 일에 맞게 준비됨"을 강조한다.
- 선택 전 모든 설정을 끝내게 하지 않는다.

## 3. Kit 카드

Kit 카드에는 최소한 아래 정보를 담는다.

- Kit 이름
- 누구에게 맞는지
- 관리할 주요 대상
- 대표 다음 행동

예:

```text
부동산 중개
고객, 매물, 방문, 계약을 함께 관리해요.
첫 기록: 고객 또는 매물 추가
```

```text
헤드헌팅
후보자, 회사, 공고, 인터뷰 단계를 연결해요.
첫 기록: 후보자 또는 채용공고 추가
```

## 4. Kit 미리보기

Kit 미리보기는 시작 전에 사용자가 확인해야 할 최소 구조를 보여준다.

포함:

- 관리 대상
- 핵심 관계
- 기본 보기
- 첫 Record 후보
- 대표 다음 행동

제외:

- 전체 필드 목록
- 내부 schema 표현
- 설정 화면처럼 보이는 편집 UI
- 고급 자동화와 권한 옵션

## 5. 기타/직접 설명

`기타/직접 설명`은 사용자의 업무가 후보 Kit에 없을 때 필요하다.

다만 MVP에서는 아래처럼 제한한다.

- 완전한 AI CRM 생성처럼 과장하지 않는다.
- 사용자가 적은 설명을 바탕으로 즉시 완성된 schema를 보장하지 않는다.
- PM이 확정한 Kit 외 구조는 후속 상담/대기/요청 흐름으로 처리할 수 있다.

사용자-facing 예:

```text
찾는 업무가 없나요?
하는 일을 알려주면 맞는 Kit을 준비할 때 참고할게요.
```

## 6. 선택 후 확인

Kit 선택 후에는 사용자가 아래를 확인해야 한다.

- 선택한 Kit 이름
- 준비될 관리 대상
- 첫 기록으로 무엇을 만들 수 있는지
- 시작하면 Workspace가 준비된다는 점

권장 CTA:

- `이 Kit으로 시작`
- `다른 Kit 보기`

## 7. 검수 질문

- 사용자가 CRM을 설정하는 느낌보다 업무를 고르는 느낌을 받는가?
- 카드만 보고도 어떤 일이 관리되는지 알 수 있는가?
- Kit 미리보기가 템플릿 설명이 아니라 업무 구조 확인으로 보이는가?
- 기타 흐름이 blank builder로 이어지는 것처럼 보이지 않는가?
