# UX Writing Guide

Status: UX Writing Baseline
Date: 2026-09-12

## 1. 목적

OneHand CRM의 사용자 노출 문구는 쉽고 짧고 행동이 분명해야 한다.

사용자는 CRM 용어를 배우러 온 것이 아니라 자기 일을 관리하러 온다. 문구는 내부 구조를 설명하기보다 사용자가 지금 무엇을 하면 되는지 알려야 한다.

## 2. 적용 범위

- User Web 화면 텍스트
- 버튼, 탭, 메뉴, 필터, placeholder
- toast, dialog, modal
- loading, empty, error state
- form validation message
- 사용자에게 노출되는 API error message
- Admin Web의 로그인/권한 확인 문구

## 3. 기본 톤

해요체를 기본으로 쓴다.

피해야 할 표현:

- `~입니다`
- `~습니다`
- `~합니다`
- `~없습니다`
- `~하지 않습니다`
- `~수 없습니다`
- `~못했습니다`
- `~필요합니다`
- `~되었습니다`

권장 표현:

- `~이에요`
- `~해요`
- `~했어요`
- `~하고 있어요`
- `~할 수 있어요`
- `~해 보세요`

예:

| 피하기 | 권장 |
| --- | --- |
| 저장되었습니다. | 저장했어요. |
| 불러오는 중입니다. | 불러오고 있어요. |
| 로그인이 필요합니다. | 로그인하면 이용할 수 있어요. |
| 요청을 처리할 수 없습니다. | 잠시 후 다시 시도해 주세요. |

## 4. OneHand CRM 용어 기준

내부 용어를 사용자에게 그대로 노출하지 않는다.

| 내부 용어 | 사용자-facing 표현 |
| --- | --- |
| Workspace | 내 CRM, 업무 공간 |
| Kit | 부동산 중개 CRM, 헤드헌팅 CRM |
| Object | 관리할 항목, 또는 실제 업무명 |
| Attribute | 필요한 정보 |
| Relationship | 연결 |
| Record | 기록 |
| View | 보기 |
| Workflow | 반복 작업 자동화 |

가능하면 일반 표현보다 Kit의 실제 업무 언어를 쓴다.

예:

- `Object 추가` 대신 `관리할 항목 추가`
- `Relationship 생성` 대신 `고객과 매물 연결`
- `View 생성` 대신 `보기 방식 추가`

## 5. First Use 문구

첫 사용 흐름에서는 "설정"보다 "시작"과 "준비"를 우선한다.

권장:

- `무슨 일을 하고 있나요?`
- `내 일에 맞는 CRM을 준비할게요.`
- `부동산 중개 CRM이 준비됐어요.`
- `첫 고객을 추가해 볼까요?`

피하기:

- `CRM을 설정하세요.`
- `Object를 생성하세요.`
- `필드를 구성하세요.`
- `원하는 데이터베이스를 만드세요.`

## 6. Empty state

빈 상태는 `없습니다`로 끝내지 않는다. 사용자가 할 수 있는 행동을 함께 보여준다.

예:

| 피하기 | 권장 |
| --- | --- |
| 등록된 기록이 없습니다. | 첫 기록을 추가하면 여기에서 다시 볼 수 있어요. |
| 검색 결과가 없습니다. | 검색어를 바꾸면 더 많은 기록을 찾을 수 있어요. |
| 연결된 데이터가 없습니다. | 관련 기록을 연결하면 함께 확인할 수 있어요. |

## 7. Loading state

`~중입니다` 대신 `~하고 있어요`를 쓴다.

예:

- `CRM을 준비하고 있어요.`
- `기록을 불러오고 있어요.`
- `세션을 확인하고 있어요.`

## 8. Success state

결과 문구는 수동형보다 능동형을 쓴다.

예:

| 피하기 | 권장 |
| --- | --- |
| 저장되었습니다. | 저장했어요. |
| 추가되었습니다. | 추가했어요. |
| 문의가 접수되었습니다. | 문의가 접수됐어요. |

## 9. Error state

문제가 생겼다는 사실은 짧게 말하고, 다음 행동을 붙인다.

예:

| 피하기 | 권장 |
| --- | --- |
| 요청을 처리하지 못했습니다. | 문제가 생겼어요. 잠시 후 다시 시도해 주세요. |
| 목록을 불러오지 못했습니다. | 목록을 불러오지 못했어요. 다시 시도해 주세요. |
| 삭제할 수 없습니다. | 연결된 기록을 정리하면 삭제할 수 있어요. |

## 10. Validation

입력 검증 문구는 짧고 구체적으로 쓴다.

예:

| 피하기 | 권장 |
| --- | --- |
| 이름을 입력해주세요. | 이름을 입력해 주세요. |
| 날짜 형식은 YYYY-MM-DD입니다. | 날짜는 YYYY-MM-DD 형식으로 입력해 주세요. |
| 10MB 이하여야 합니다. | 10MB 이하 파일만 올릴 수 있어요. |

`해주세요`는 `해 주세요`로 띄어 쓴다.

## 11. Dialog와 Button

버튼은 짧은 행동형으로 쓴다.

권장:

- `저장`
- `추가`
- `삭제`
- `복구`
- `다운로드`
- `닫기`

원칙:

- 다이얼로그 왼쪽 버튼은 `닫기`로 통일한다.
- `취소`는 사용자가 진행 중인 작업 자체가 취소된다고 오해할 수 있을 때 피한다.
- 버튼에 긴 설명을 넣지 않는다.
